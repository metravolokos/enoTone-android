## Ограниченный LRU (ADR-0026)
- Новые MockWebServer тесты: четыре 64-КиБ блока, повторные чтения блоков 0 и 2 без сети, вытеснение старейшего после пятого блока, точные байты; 40 чередований двух блоков должны дать только 2 GET.
- Существующие тесты HTTP 206, Content-Range, ETag/If-Range, short/oversized body, 8 МиБ/128 GET, запрет redirect, Room schema v1 и GMS остаются обязательными.
- После зелёного CI: отдельный Preview с собственной базой; импортировать /AllMusic; проверить **только один** файл, прислать только title/artist/album 0/1, GET, байты, `RAM-повторения` и `вытеснения`. Никакой массовой обработки.
- Более низкое число GET нельзя считать доказанным ускорением, пока не обеспечено сравнение **одного и того же файла** и условий. Если RAM-повторений нет, LRU на этом файле не даёт выигрыша.

## Быстрый разбор ID3/FLAC — эксперимент
- JVM: ID3v2.3 с UTF-16 кириллицей, ID3v2.4 с UTF-8/synchsafe размером, ID3v1 из хвоста; APIC ~280 КиБ пропускается по фрейму без скачивания тела.
- JVM FLAC: STREAMINFO, PICTURE ~300 КиБ пропускается, Vorbis Comment в другом диапазоне читается; испорченные комментарии и большие блоки отклоняются.
- MockWebServer: на синтетическом FLAC с большой PICTURE **два Range GET**, проверяются HTTP 206/Content-Range/ETag и точные байты через существующий WebDavRangeReader.
- Нестандартные/неподдерживаемые структуры: фиксированные статусы `UNSUPPORTED_LAYOUT`, `NO_EMBEDDED_TAGS`, `FAST_BUDGET_EXCEEDED`; никаких автоматических 39–50 GET по резервному пути.
- После зелёного CI: новый изолированный Preview, импорт списка /AllMusic, один MP3 (по умолчанию), затем при желании один **явно выбранный** FLAC; передать только код, флаги embedded title/artist/album, GET, байты, saved 0/1. Путь/имена/пароль не публиковать.
- Тот же файл можно проверить старой кнопкой с MediaMetadataRetriever отдельно, чтобы сравнение было валидно; не делать это массово.

## Проверка пилотного индексатора — ADR-0028
- JVM: выбрать не более 10/20 файлов; пропустить завершённые и имеющие теги, чужой sourceKey и вложенные пути, поставить RETRY после новых; для повторного listing сбросить checkpoint только при изменении remote version.
- MockWebServer: ограничение per-reader 1 GET/64 КиБ, отказ до второго запроса; невозможно поднять лимиты исходного 8 МиБ/128 GET.
- CI: проверить Room v1 JSON, экспорт схемы v2 с новым nullable tagScanCode и успешную AutoMigration; Android/JUnit/Lint/GMS/подпись APK.
- На Huawei **не запускать сразу 20**: сначала 10 файлов. В новой Preview импортировать /AllMusic, нажать «Пилот до 10 треков», зафиксировать только числовые счётчики. Повторить: первый набор должен пропускаться. Проверить «Остановить пилот» и продолжение в **той же** Preview после перезапуска.
- Если общие GET/байты достигли лимита, следующий файл не запускается; если был HTTP 401/403, исправить доступ, не повторять в цикле. Не делиться именами, путями, самими тегами или паролями.
- Заполнение тегов для всей медиатеки не включено. Не принимать M1 полностью до инструментального теста миграции и измерений на разных форматах.
