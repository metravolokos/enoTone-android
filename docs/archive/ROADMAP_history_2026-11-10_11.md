# ROADMAP — исторические разделы (2026-11-10 … 11)

> **Архив.** Перенесено из `docs/ROADMAP.md` 2026-11-13 (ревью «что удалить», [REDUCTION_REVIEWS](../REDUCTION_REVIEWS.md)). Описывает состояние до M6-0; текущее — в [ROADMAP](../ROADMAP.md) и [STATUS](../STATUS.md).

## M1: завершение тегов и индексации (2026-11-11)

Новая [ADR-0066](../DECISIONS/ADR-0066-indexing-finalization.md) фиксирует согласованную модель: **одна обычная команда импорта/обновления** (только новые/изменённые/незавершённые), все поддерживаемые текстовые поля за тот же MP3/FLAC проход, и **отдельная подтверждаемая команда полной переиндексации** в Настройках, без очистки старых тегов и с автоматическим запуском фоновой обработки. Проверяем разные причины обновления версии: ETag, размер и last-modified. Готова внутренняя атомарная подготовка переиндексации по ключу альбома, обычного исполнителя или исполнителя альбома; **контекстные меню пользователь ещё не утверждал**, они будут добавлены на этапе дизайна. Обложки при этом не загружаются массово.

## M2: постоянные обложки — действующее решение 2026-11-11

[ADR-0067](../DECISIONS/ADR-0067-permanent-album-artwork.md) заменяет исторический [ADR-0064](../DECISIONS/ADR-0064-single-master-artwork-cache.md). **Один сжатый мастер до 1200 px по большей стороне** без увеличения маленьких источников; приватное **постоянное `filesDir/enotone-artwork-v2`**, без дискового LRU 64 МиБ или автоматического удаления. Дедупликация идентичных WebP, локальное уменьшение экранных размеров, ленивая миграция прежнего временного кэша. **Одна выбранная обложка реального альбома** во всех разделах (плитка, детали, треки, мини-плеер, Now Playing), но у «Неизвестного альбома» нет искусственно общей картинки. В Настройках — **автоматический режим после импорта/окончания тегов** либо **по мере обращения**, прогресс, Pause/Stop, занимаемый объём и подтверждаемая ручная очистка. По явной переиндексации инвалидируются source/album refs даже с прежним ETag. **Обложка альбома как будущая обложка плейлиста** — архитектурный принцип без дубляжа мастера, пока **не** готовый UI плейлистов.

**Приёмка:** [PR #71](https://github.com/metravolokos/enoTone-android/pull/71) объединён, exact-HEAD CI #300 (19 шагов) и подписанная сборка [#301](https://github.com/metravolokos/enoTone-android/actions/runs/42971807110) (23 шага) прошли. Владелец установил Preview #301 на Huawei и сообщил **«Работает»** — базовая функциональность принята. Проверку offline-повтора после перезапуска, реальных GET, автоматической фоновой очереди и принудительной очистки нужно фиксировать отдельно. Ни одна из них не подразумевается ответом «Работает».

## Новое согласованное решение: единый импорт, жанры и затем обложки

По просьбе владельца больше не разрабатываем две обязательные пользовательские команды «получить список» и «индексировать теги». **Импорт / обновление медиатеки — одно действие**, внутри которого остаются две безопасные фазы: быстрый PROPFIND Depth:1 с атомарным сохранением снимка, затем возобновляемый фоновый MP3/FLAC парсер с четырьмя параллельными читателями. Все текущие текстовые поля, включая **GENRE** (ID3 TCON/ID3v1/FLAC Vorbis), извлекаются за этот же проход. Room v4 добавляет nullable genre без уничтожения сохранённых 3590 треков. Подробности и правила приёмки — [ADR-0062](../DECISIONS/ADR-0062-unified-import-genre-artwork.md).

**Три окончательных пользовательских сценария:** «Импортировать медиатеку» / «Обновить медиатеку» / «Переиндексировать»; последние два не путать: обновление проверяет новые/изменённые файлы, а переиндексация принудительно перечитывает теги выбранных файлов и **сбрасывает ссылки на обложки** для их последующего получения по мере надобности. Области альбома/исполнителя пока поддержаны backend, но контекстные меню отложены. Пункты переиндексации на экранах появятся позже вместе с согласованием контекстных меню (три точки / долгое нажатие). Текущие диагностические кнопки по 10 треков временно оставлены до замены.

**Обложки (актуально):** PR #67–#69 дали миниатюры и полноценный Now Playing, PR #71 перевёл мастер на **1200 px в постоянное `filesDir`** с общим альбомным выбором и двумя режимами получения. Текстовая индексация не загружает все картинки; автоматический режим подготовки обложек выполняется отдельно и только при включении. Портреты исполнителей, UI плейлистов и окончательный дизайн не реализованы.

## Историческая контрольная точка #235 и уточнение приоритета M2-UI (2026-11-10; ниже — тогдашние незавершённые работы)

Владелец **принял подписанную Stable Preview #235 как техническое превью**: имеющаяся библиотека и воспроизведение работают. Это не утверждение окончательного дизайна. Полноценные страницы альбомов/исполнителей, изображения, Now Playing и мини-плеер в смысле исходного ТЗ остаются незавершёнными: сейчас есть рабочие виртуальные группировки, текстовые списки и технический плеер в диалоге.

**Новый UX-критерий владельца:** минималистичный, интуитивный интерфейс современного музыкального плеера, минимум текстовых кнопок и пояснений, минимальная высота навигации. Не переносить несогласованные фирменные цвета/изображения на Android до отдельной приёмки.

План небольших последовательных изменений:

1. **M2-UI-A — компактный каркас:** иконки разделов в низкой нижней панели (целевой размер 52 dp), выделение активного раздела, TalkBack-описания, сохранение четырёх независимых разделов и индивидуальной видимости страниц. Не перекрывать мини-плеер. Данный PR реализует первую часть; полная перестройка настройки/диагностики — отдельный срез.
2. **M2-ART-A — обложки:** встроенные APIC/FLAC PICTURE через ленивые, ограниченные HTTP Range-запросы, без повторного полного сканирования библиотеки и без регрессии быстрого парсинга текстовых тегов. 192/512/1320 px и локальный LRU, безопасное масштабирование, placeholders. Обложка альбома не объявляется автоматически фотографией исполнителя.
3. **M2-UI-B — экраны:** треки с миниатюрами; сетка альбомов 2–3 колонки, детальная страница альбома; страницы исполнителей и исполнителей альбомов с альбомами и треками. Сохранить «Неизвестный альбом».
4. **M3-UI-A — полноценный Now Playing и мини-плеер:** вместо большого диагностического диалога отдельный пользовательский экран с обложкой/seek/иконками управления; мини-плеер компактный и доступный над нижней навигацией. Сохранить единый Media3 сервис и playback при переключении разделов.
5. **M2-SEARCH/M6 — FTS/сортировка, доступность, локализация и проверка компоновки на Huawei**, затем отдельно согласовать фирменные ресурсы enoTone.

Никаких изменений Room v2, списка 3590 файлов, секретов, WebDAV, сетевого бюджета или подписи APK ради навигационного PR. Любое изменение пользовательской логики проходит exact-HEAD CI и проверку подписанной Stable Preview поверх существующей установки.

## Уточнение интерфейса от владельца: Home и пять иконок (2026-11-10)

После принятия рабочего технического превью и промежуточной компоновки принято решение: **Home → Треки → Альбомы → Исполнители → Исполнители альбомов** в компактной нижней панели (52 dp, иконки без постоянных текстовых подписей). Home всегда доступен; независимая видимость остальных четырёх разделов настраивается через **Настройки**. Прежний стартовый экран подключения/обслуживания/диагностики и прежняя настройка видимости переносятся в отдельный экран настроек, открываемый с Home. Художественная замена кнопок и иконок отложена; фирменные цвета Android ещё не утверждены. Зафиксировано в [ADR-0055](../DECISIONS/ADR-0055-home-settings-five-icon-navigation.md).

Сначала проверить новый маршрут и сохранность медиатеки на Huawei. Затем продолжить последовательность **обложки → полноценные страницы альбомов/исполнителей → Now Playing и постоянный мини-плеер на всех основных экранах → поиск/сортировка**. Не запускать индексирование 3590 файлов при проверке переходов.

## Порядок дальнейшей работы

1. **Довести медиатеку до удобного повседневного использования.** Постоянные обложки, мини-плеер и Now Playing уже реализованы и получили базовый Huawei smoke #301; приоритет — **поиск/сортировка**, компоновка и точечная проверка offline/автоматической загрузки обложек. Не инициировать полную индексацию повторно ради UI-проверки.
2. **Надёжность playback.** Сохранение очереди/позиции/режимов после завершения процесса, управление через Bluetooth и аудиофокус, смена соединения, фоновые ограничения Huawei.
3. **Измерения и совместимость.** Проверить сетевое чтение после seek при полностью готовом кэше; сценарии больших библиотек (10k+), производительность и доступность. Расширение форматов только когда появятся воспроизводимые тестовые файлы.
4. **Внешний вид и выпуск.** Отдельно согласовать палитру, шрифты, иконки и Бандита для Android. Оформить лицензию, release signing/distribution и итоговую документацию.
5. **После MVP.** Плейлисты, опциональный ИИ, сохранение offline и SAF/DocumentsProvider — не выдавать за существующие функции.

## Обязательные правила

- **Нет Wi-Fi-only** или ограничений по типу сети по решению владельца. Индексация запускается явно; dataSync foreground service поддерживает фон/блокировку, Room фиксирует прогресс, самопроизвольного автозапуска после reboot нет.
- **Без Google Play Services/Firebase и телеметрии**, только HTTPS и согласованные сетевые назначения. Секреты не печатать, не хранить в Room/Intent/Git или резервных копиях; постоянное хранение логина — только добровольное и защищённое Android Keystore.
- Каталог `/AllMusic` одноуровневый: `Depth: 1`, без рекурсивного обхода; группы строятся по тегам. Для имеющейся коллекции поддержаны FLAC и MP3; прочие форматы из первоначального ТЗ остаются незакрытыми.
- **Stable Preview** `app.enotone.android.preview` подписывается постоянным приватным ключом из CI secrets; установка поверх предыдущей Stable Preview сохраняет Room. Обычный debug `.preview.rN` — иной пакет. Не удалять установленную Stable Preview ради теста.
- Для новых изменений — feature-ветка, PR, проверки точного HEAD (build, unit, lint, Room и GMS), отдельный Huawei smoke при затронутой Android-функции. Перед слиянием не подменять успешный merge или сообщение «работает» доказательством непроверенных побочных сценариев.
- Android использует **стандартную Material 3 тему**. Изображения, цветовая палитра и маскот из отдельного дизайн-проекта не включаются без утверждения для Android.
