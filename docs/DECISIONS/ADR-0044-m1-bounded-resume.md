# ADR-0044 — M1: ограниченное ручное продолжение теговой индексации

Дата: 2026-11-09; статус Draft до Huawei smoke.

После принятого пилота 10/10 тегов в Stable Preview #177 и проверки вкладок Albums/Artists пользователь хочет перейти от повторяющихся маленьких проверок к постепенной индексации всего плоского /AllMusic (3590 файлов), не рискуя неконтролируемым количеством GET.

## Решение
- Новая отдельная кнопка `Продолжить индексацию (до 100 файлов)` на диагностическом экране, рядом с существующими 10/20 пилотами и кнопкой остановки. Запускается **только вручную**, при наличии email и пароля; при работающем пилоте запрещены другие запуски.
- Это не бесконечный цикл, а **не более 100 кандидатов и одновременно** прежние жёсткие квоты `MAX_BATCH_GETS = 60`, `MAX_BATCH_BYTES = 4 MiB`. Тайм-бюджет `MAX_BATCH_NANOS = 180 s` проверяется между файлами (не является жёстким deadline на сам HTTP-запрос). Один файл может потребовать до 6 малых Range GET, но общий лимит всегда доминирует. Не обязано обработать 100 файлов за нажатие; итог содержит точный счётчик.
- Реиспользование существующих `PilotBudget.select`, `PilotTagIndexer.run` и `recordFastScanIfUnchanged`: по завершении каждого файла отдельно обновляем Room. Успешно обработанные файлы не выбираются повторно; при отмене текущий незавершённый файл может повториться. После остановки/перезапуска пользователь может нажать ту же кнопку для следующего ограниченного прохода, без повторного PROPFIND и сохранения списка.
- Нет WorkManager/уведомления фоновой задачи, нет автоматического сканирования всего каталога и новых сетевых API. Вручную запускать по одной сессии и оценивать реальную стоимость по числовому отчёту, особенно на мобильном интернете. Изменений Media3, аудиокэша, Room schema, хранения учетных данных и палитры нет.

## Граница приёмки
CI exact HEAD: Android/JUnit/lint/Room/GMS + JVM 3590 synthetic files and reselect test + Python static budget contract. Для Huawei — установить подписанный stable APK поверх #177, убедиться, что прежние 10 тегов сохранены, запустить один Resume и подтвердить число HTTP запросов, байты, ошибки и stopCode, проверить остановку/продолжение. Не обещать full 3590 или 0 GET на файл.
