# ADR-0062 — единый импорт медиатеки, GENRE и политика обложек

Дата: 2026-11-10. Статус: Draft PR, требует CI exact HEAD и аппаратной проверки на Huawei. Заменяет **UX-разделение** импорта каталога и индексации из прежних M1-решений; сетевые ограничения остаются.

## Решение владельца

Пользователю не нужны отдельные обязательные действия «получить список», «прочитать теги», «индексировать теги». Нужен **единый импорт** (первоначально) / **обновление медиатеки** (позже), в котором быстрый WebDAV PROPFIND /AllMusic (Depth:1) сохраняет список в Room, а затем та же пользовательская операция самостоятельно запускает уже реализованную фоновую индексацию новых/изменённых/неоконченных MP3/FLAC. Фоновая индексация продолжает оставаться отдельной *внутренней стадией*: отсутствие чтения содержимого у PROPFIND не позволяет получить аудиотеги прямо из ответа на листинг. Обработка может продолжаться при свёрнутом приложении.

Техническая кнопка «Индексировать оставшиеся» доступна только через расширенную диагностику, а не как обычное второе действие. Кнопки паузы/остановки и числовой прогресс запущенного фонового сервиса сохраняются. Успешная повторная синхронизация не переопрашивает теги неизменённых файлов: исходные Room checkpoints по версии файла остаются валидными.

## Полный набор текущих тегов

- Прочитать **GENRE** вместе с **TITLE, ARTIST, ALBUM, ALBUM ARTIST, DATE/YEAR, TRACKNUMBER, DISCNUMBER** на уже существующем ограниченном Range-механизме без отдельных сетевых запросов для GENRE.
- Native FLAC Vorbis: поле `GENRE` (без выдумывания значения при отсутствии).
- MP3 ID3v2.3/v2.4: `TCON` — обычная строка или стандартный ID3-номер `(17)`/`17`, кодовые жанры преобразуются по общему справочнику. MP3 ID3v1: жанр из последнего байта 128-байтового блока, числовой код. Некорректные коды оставлять пустыми, текст очищать от управляющих символов и ограничивать.
- На одно чтение файла те же ранее утверждённые ограничения GET/байт/времени и skip огромных APIC/PICTURE; никакого full-file fallback. Прежний параллельный reader (4 workers) и сериализованный Room writer используются повторно.
- Room **v3 → v4** через `AutoMigration`: nullable поле `genre` без очистки 3590 ранее импортированных файлов. Основной индексатор, тестовый индексатор и одиночное ручное чтение передают genre через прежний CAS. `LibrarySnapshotPlanner` сохраняет жанр для той же версии и сбрасывает при изменении исходного файла. Повторный старый APK и downgrade схемы не поддерживаются.
- В существующем локальном поиске жанр индексируется наравне с title/artist/album; у альбома отображается жанр только при единственном непротиворечивом значении среди прочитанных треков. Будущая отдельная фильтрация по жанрам и FTS — M2.

## Как обновляем в будущем

- **Обновить медиатеку**: один PROPFIND, обнаружение новых/изменённых/пропавших, фоновые теги только тех, у кого нет успешного checkpoint или версия изменилась.
- **Переиндексировать** (в будущих контекстных меню альбомов/исполнителей, либо всю медиатеку из настроек): единый скопированный набор *стабильных ID* для одних и тех же фоновых reader и CAS. Даже если ETag/size не изменились, принудительно перечитать теги.
- Диагностическую кнопку обновления по 10 треков не развивать как пользовательский API: позже заменить «Переиндексировать альбом».
- Перезапуск устройства не должен без запроса владельца начинать массовую сеть; повторный явный импорт продолжает с checkpoint. Никакого обязательного Wi-Fi-only.

## Обложки: не забыть и не загружать все 3590

Существующая `ArtworkPreviewRepository` получает встроенную обложку **лениво** при показе видимых альбомов/альбома/активного трека, с двумя слотами и приватным WebP LRU **32 МиБ**, preview до 512 px. Подтверждено владельцем на Huawei, что обложки не тормозят воспроизведение.

Импорт текстовых тегов **не** должен скачивать изображения, тем более огромные PICTURE/APIC; парсер умеет пропускать их по смещениям. В существующем ключе кэша используются account, trackId, path, размер и ETag — смена версии при нормальных заголовках приводит к новому ключу. В будущей команде «Переиндексировать альбом/исполнителя» обязательно явно сбрасывать соответствующий artwork cache даже когда сервер ошибочно сохраняет прежний ETag/размер, а затем по запросу обновлять миниатюры; без этого ручная правка картинки может остаться незаметной.

**Ещё не завершены:** миниатюры у треков, большой 1320 px вариант и полноценный Now Playing, изображения исполнителей/источник портретов, гарантированное обновление обложки при неизменном ETag. Не выдавать наличие placeholder обложки за портрет артиста. Этап обложек остаётся следующим после завершения пользовательского импорта/синхронизации.

## Безопасность и приёмка

- GitHub exact-HEAD CI, Android Gradle/JUnit/Lint, Mock WebDAV, KSP Room v4 schema с точным снимком и сохранёнными v1/v2/v3, запрет Google Services.
- Huawei Stable Preview ставится **поверх #269**, без удаления Room, защищённых credentials, кэша и 3590 записей.
- Первоначальный/повторный импорт запускает *один* сетевой листинг и отдельный фоновой этап с уведомлением, умеет приостановиться/возобновиться; неизменённые файлы не читаются повторно.
- MP3 TCON, ID3v1 и FLAC GENRE доступны в сохранённых результатах и локальном поиске/при общей жанровой принадлежности альбома. Старые треки не получают GENRE сами собой от установки новой APK: потребуется явная переиндексация, которую реализуем отдельным действием по договорённому UI.
- Не требовать массовой повторной индексации лишь ради проверки UI, и никогда не показывать в логах/CI приватные теги, файлы/пути, ETag или пароль.
