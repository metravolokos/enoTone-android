# ADR-0081: Модульные ViewModel технических настроек

Дата: 2026-11-12. Статус: предложено в Draft PR M6-0/4b-2.

## Контекст

PR #100 (M6-0/4b-1) реализует O-09 и `AccountSettingsViewModel`. Существующий `SettingsScreen.kt` содержит крупный Compose-экран со смешанными действиями Room, WebDAV и foreground-сервисов. Целевой интерфейс Android v2 ещё не применяется (действует ADR-0073). Нужно вынести побочные эффекты из Composable, не менять внешний вид и контроль запросов.

## Варианты

1. **Один огромный `SettingsViewModel`.** Плюс: одна модель для экрана. Минусы: монолит с огромным интерфейсом, неочевидные зависимости, сложные тесты, конфликты между несколькими видами индексирования.
2. **Небольшие ViewModel на самостоятельные области (выбран).** `AccountSettingsViewModel` в 4b-1; `ArtworkSettingsViewModel`, `TechnicalProbeViewModel`, `ManagedIndexSettingsViewModel` и последующие VM для аудита тегов и импорта. Плюсы: независимое тестирование Gateway-фейками, экран-компоненты ≤300 строк, разные жизненные циклы; минус: нужно аккуратно координировать состояние busy и разрешение фоновых уведомлений.

## Решение

Только `AppContainer` / Gateway взаимодействуют с Android, Room и сетевыми клиентами. Compose читает неизменяемые `StateFlow<…UiState>` и отправляет действия. События для запуска фонового индексатора могут проходить через системный launcher разрешения POST_NOTIFICATIONS в Compose; фактический `startForegroundService` выполняет Gateway. Сохранены ограничения индексаторов и безызменённая разметка ADR-0073.

Реализованные в первом Draft-коммите разделы: управление режимом/очисткой обложек, безопасная WebDAV-диагностика, команды фонового индексатора, секция статусов с Preview. **Остаются** импорт/обновление/полная переиндексация, аудит, чтение одного трека, pilot, разбиение оставшегося Compose-файла до ≤300 строк на файл. Это не закрытый ADR до полного ревью и CI.

## Последствия и проверка

Поведенческие JVM-тесты ViewModel с Gateway-фейками, затем exact-HEAD CI + Huawei smoke. Нет миграции Room, GMS, новых ресурсов дизайна или автоматической полной переиндексации. Б-1 для #100 остаётся отдельным аппаратным сценарием, Б-2 — строго по разрешению владельца. Стек PR: базовая ветка #100 до его squash merge, затем 4b-2 нужно перенести на новый `main` без дублирования изменений.
