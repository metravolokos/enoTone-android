# ADR-0068 — спокойный, минималистичный интерфейс enoTone Android

Дата: 2026-11-11. **Статус: проектное направление предложено владельцем; первый UI-кандидат в ветке; не считать художественно утверждённым до проверки на Huawei.**

## Задача и референс

Владелец поменял приоритет: **сначала закончить оформление/дизайн, потом — глобальный поиск, сортировки и другие функции**. Референс — Apple Music по простоте использования и объёму визуального шума. **Не копировать** логотип Apple, торговые знаки, эксклюзивные ресурсы, фирменные цвета или конкретные скриншоты. Заимствовать общие закономерности: музыка/обложки на первом плане, ясная типографическая иерархия, одна главная операция, редкие функции в overflow.

Это **не замена** принятого визуального enoTone из `metravolokos/enotone-design`: [DESIGN_DECISIONS](https://github.com/metravolokos/enotone-design/blob/main/docs/DESIGN_DECISIONS.md), [UI_BASELINE_V1](https://github.com/metravolokos/enotone-design/blob/main/docs/UI_BASELINE_V1.md), [tokens/colors.json](https://github.com/metravolokos/enotone-design/blob/main/tokens/colors.json) (v1.3). Дизайн-репозиторий и Android-кандидат синхронизировать явно; не объявлять первый APK окончательным оформлением.

## Визуальные константы

- **Тёмная тема «Графит»**: фон `#1B1A19`, поверхности `#252321`/`#2F2C2A`, текст `#F4ECE4`, вторичный `#B9AEA4`, пудрово-розовый акцент `#EBAE9F`; голубой `#8FB0C2` только точечно.
- **Светлая тема «Фарфор»**: фон `#EDE9E5`, поверхность `#F8F5F1`, вторичная `#E2DCD6`, текст `#211E1C`, вторичный `#5C544E`, контрастный активный `#A24F3E`, заливка Play `#EBAE9F` с **тёмным** текстом/пиктограммой.
- **Нет** автоматического перекрашивания настоящих обложек, стеклянного размытия везде, искусственных фоновых градиентов, постоянных текстовых подсказок и карточек ради украшения. Сначала базовый аккуратный Material 3 с принятыми цветами, позже — осторожная фирменная полировка.
- **Типографика:** в дизайн-системе приняты Onest (метаданные/навигация) и Unbounded (заголовки). Нельзя незаметно подменять утверждённые мастер-файлы. Пока ресурсы не доступны в Android-репозитории, Kotlin использует платформенную типографику **как временное техническое решение**; итоговый шрифтовой экспорт — отдельное проверяемое действие.
- **Бандит и логотип:** использовать **только утверждённые оригиналы** (13 иллюстраций / PNG иконки v1.0 / mirrored wordmark). Никаких новых AI-перерисовок; пока нет в app-ресурсах, оставляем аккуратную текстовую маркировку `enoTone`, не подделываем фирменный wordmark шрифтом.

## Правила экранов

1. **Нижняя навигация:** сохраняем одобренные Home + четыре независимо отключаемые музыкальные категории. Без новых вкладок, текстовых блоков поверх списков или отдельной страницы поиска, пока не начат этап поиска. Не вводить двойную панель меню.
2. **Списки треков:** обложка 44 dp, название и одна строка исполнителя/альбома, разделитель, действие по нажатию. Реальная музыка, а не декоративные баннеры; длинные названия сокращаются, TalkBack остаётся.
3. **Альбомы:** реальная 2-колоночная/адаптивная сетка обложек; страница альбома — обложка, название, исполнитель, **одна** строка год · жанр · количество; крупная кнопка Play. Редкое обновление тегов доступно через **«⋮»**, а не постоянно отдельной большой кнопкой. Это первый переход к согласованным контекстным действиям; переиндексацию исполнителя/альбома целиком подключать только после отдельного UX-проекта.
4. **Мини-плеер:** компактная фиксированная полоса над навигацией: обложка, две строки, Pause/Play и Next. Нажатие на обложку/текст открывает Now Playing. Убираем дублирующую кнопку Expand — она повторяет действие самой полосы. Прогресс остаётся тонким.
5. **Now Playing:** полноэкранная обложка и ясная пара названия/исполнителя; seek, крупная круглая Play/Pause, предыдущий/следующий; repeat/shuffle второстепенные. Не перегружать диагностикой и техстатистикой, они остаются в Настройках.
6. **Настройки:** хорошо сгруппированные «Медиатека», «Обложки», «Воспроизведение», «Подключение»; опасные действия подтверждаемы; диагностика свернута. Не удалять работающие функции.

## Что входит в первый PR и что не входит

**Первый UI-кандидат:** точные цвета Graphite/Porcelain по системной теме, упрощение header альбома/overflow, мини-плеер с двумя транспортными кнопками, сохранение технических действий и accessibility. Это **не** завершение дизайна: ещё требуется аппаратная оценка компоновки, типографики, ассетов wordmark/Бандита, ручного выбора темы, улучшений Home/исполнителей/Настроек и ночных/светлых контрастных состояний.

**Не изменять:** Room v4, 3590 файлов, Unified Import / reindex, постоянные обложки **1200 px в filesDir**, WebDAV, Media3, очередь/настройки воспроизведения, packageId/подпись. Новые функции поиска, сортировки, плейлистов, ИИ и офлайн-музыки — **после** дизайна.

## Проверка / принятие

- Exact-HEAD CI Kotlin/JUnit/Lint/contract/MockWebDAV/Room/GMS; кодовая проверка отсутствия изменений музыкального движка.
- На Huawei только подписанная Stable Preview поверх установленной; не переиндексировать 3590 файлов, не удалять данные.
- Проверить Graphite и Porcelain, контраст текста/Play, верх экрана, узкие длинные кириллические строки, TalkBack метки, навигацию, открытие альбома, «⋮» → действие, возврат, мини-плеер с двумя кнопками и открытие Now Playing по картинке/названию.
- **Только после пользовательской проверки макета** отмечать дизайн-этап принятым; до этого PR визуальный кандидат, не финальный брендовый Android UI.
