# ADR-0025 — Подтверждение сохранённых тегов через офлайн-агрегаты Room

Дата: 2026-11-08 | Статус: Draft до CI и ручной проверки

## Контекст
На Huawei Preview #47 владелец успешно записал результат чтения **одного** файла в приватную Room: title=1, artist=0, album=0, `Сохранено в Room: 1`, 39 Range-запросов и 2 490 368 байт (2,375 МиБ). Предыдущий файл в Preview #45 дал title/artist/album=1/1/1 и 50 GET / 3,125 МиБ. Нельзя считать 39 GET против 50 ускорением: выбранные файлы могли отличаться.

Успешный SQL UPDATE не доказывает ещё сохранность после перезапуска приложения. Изолированные Preview APK разных CI runs не имеют общего каталога, поэтому проверка должна осуществляться **в пределах одной установленной Preview**.

## Решение
- Добавить отдельную кнопку **«Проверить сохранённые теги (без сети)»**, доступную с введённым e-mail, без пароля.
- Одним агрегирующим SQL SELECT только по sourceKey и `missingScans = 0` вернуть total, число треков с любым тегом и число треков с title/artist/album/albumArtist.
- Возвращать в UI **только числа**: никакого содержимого тегов, имён, путей, ETag, логов и сетевых запросов. База открывается в Dispatchers.IO и закрывается в finally.
- Никаких изменений схемы Room v1, пароля в БД, массового извлечения, скачивания файлов, фоновых задач или новых разрешений.
- `AudioTagFields.fromRaw` может заполнить title **из имени файла**, если embedded title отсутствует. Поэтому title=1 означает наличие сохранённого отображаемого названия, но **не доказывает наличие embedded ID3/Vorbis title**. Artist=0 и album=0 не доказывают неисправность: их могло не быть в конкретном файле.

## Приёмка
CI: Android/JUnit/Lint, неизменная Room v1 schema, APK GMS-free gate, подтверждение run-specific Preview ID и подписи. Далее на Huawei: установить новый Preview, импортировать список, прочитать/сохранить **один** файл, проверить счётчики Room, полностью перезапустить **то же приложение**, заново ввести только e-mail и проверить офлайн без облака. Число треков с сохранёнными тегами должно быть 1 (если это первый файл в новой базе), число с title — 1, artist/album могут быть 0.

При разработке настоящего индекса проверять и оптимизировать сетевую стоимость на нескольких разных форматах; 39 GET и 2,375 МиБ для одного трека не годятся для безусловного умножения на 3590.
