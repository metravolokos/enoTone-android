# ADR-0067 — постоянные обложки альбомов (1200 px)

Дата: 2026-11-11. Статус: реализация в PR #71, проверяется exact-HEAD CI и на Huawei.

## Последнее согласованное решение

**Размер:** сохраняем **ОДНУ** мастер-обложку с максимальной стороной **1200 px**, без увеличения маленьких исходных картинок. Из неё локально получаем любые экранные размеры. Исторический максимум 1320 px из ADR-0064 больше НЕ является действующим правилом.

**Хранение:** постоянный приватный каталог `filesDir/enotone-artwork-v2`, а не временный Android `cacheDir`. Нет совокупного LRU-ограничения 64 МиБ и автоматической очистки ради экономии места. Реальные мастера WebP адресуются SHA-256 содержимого, одинаковые пиксельно обложки не должны храниться многократно; source-version и album refs хэшированы и не раскрывают теги/пути. Ранее полученные временные файлы переносим лениво при использовании, не переопрашивая сеть только ради миграции. Сам пользователь может увидеть объём и явно очистить это хранилище в Настройках. Удаление данных приложения/деинсталляция, разумеется, удаляет и постоянные приватные обложки.

**Одна визуальная обложка для настоящего альбома** во всех представлениях: альбомная плитка/детали, строки треков, мини-плеер, Now Playing; будущий плейлист сможет ссылаться на ту же сохранённую мастер-обложку альбома. При этом источник обложки хранится отдельно от собственных тегов каждого трека. Виртуальный «Неизвестный альбом» не объединяет неродственные треки одним изображением. Редактор плейлистов в этом PR не создаётся.

**Как получаем:** выбор в Настройках:
- «Автоматически» — после импорта/обновления тегов начинает отдельный ограниченный background dataSync проход по группам сохранённой Room-медиатеки; продолжается в следующих явных сеансах при запуске приложения, только в выбранном режиме, без сетевого старта при reboot. Не конкурирует с работающей индексацией текстовых тегов. Сохраняет по одному выбранному artwork для альбома, используя другую запись только при достоверном отсутствии изображения у первого кандидата; не скачивает аудиофайлы целиком.
- «По мере обращения» — изображения получаются только когда нужны на видимых страницах/при воспроизведении. После первого успешного получения все экраны берут картинку из постоянного хранилища, без повторного WebDAV GET.

Сетевые сбои, истечение бюджета, ошибки авторизации и отсутствие достаточных данных не считаются успешной индексацией отсутствующей обложки. Достоверное отсутствие можно фиксировать negative checkpoint с возможностью переиндексации.

**Обновление:** принудительная переиндексация метаданных/обложек очищает соответствующие source refs, включая ошибочно неизменный ETag/size; album selection инвалидируется, мастер-файлы других треков не стираются. Для владельца доступны Pause/Stop, числовой прогресс, подтверждаемая очистка и размер хранилища.

## Границы и проверка

- Нет удалённого сервиса поиска изображений, внешних API и Google Services; только встроенные MP3/FLAC APIC/PICTURE.
- Нет отдельного дискового хранения 192/384/512 px. RAM ограничена, постоянные оригиналы (возможно уменьшенные до 1200) не подвержены автоматическому LRU.
- Два общих слота загрузки, ограниченные WebDAV Range и отменяемые сетевые запросы. Ошибки изображений не должны блокировать аудио.
- Room v4 не меняем; 3590 записей и существующая Stable Preview должны пережить установку APK поверх.
- Exact-HEAD CI: Kotlin/JUnit/Lint/Mock WebDAV/Python/Room/GMS. Затем на Huawei: одинаковая обложка альбома и его треков; навигация туда-обратно без повторной сети; закрыть/открыть плеер, выключить интернет, открыть сохранённый альбом; проверить «По мере обращения», не запускать массовую загрузку автоматически при проверке.
- Старую ADR-0064 считать историческим решением для временного кэша; этот ADR заменяет требования о 1320 px, cacheDir и лимите 64 МиБ.
