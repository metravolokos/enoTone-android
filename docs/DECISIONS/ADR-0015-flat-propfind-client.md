# ADR-0015: Один PROPFIND Depth:1 через Ktor CIO с ограниченным ответом

Дата: 2026-11-08 | Статус: предложено к проверке CI | Автор: ChatGPT

## Контекст
После объединения M1 первого среза (PR #2) появился безопасный разбор DAV 207 Multi-Status, но он не подключён к сети. Основная медиатека /AllMusic плоская, на реальном Huawei PROPFIND Depth:1 возвращает 207, а Depth:infinity не завершился за 15 секунд.

## Варианты
1. Получить весь ответ как String через bodyAsText — просто, но размер ответа не контролируется.
2. Прямой поток SAX из Ktor channel — меньше памяти, но требует отменяемого bridge async → blocking SAX на Android; отдельная проверка.
3. Один Ktor CIO PROPFIND + bounded read (16 MiB) и последующий SAX — выбран как безопасный первый интеграционный вертикальный срез. Временное дополнительное RAM при больших библиотеках; позже заменить на потоковую Room pipeline.

## Решение
- Один запрос только к доверенному HTTPS endpoint /AllMusic c Depth:1 и запретом redirect.
- Basic auth в памяти, без хранилища/логирования, без рекурсии.
- Требовать HTTP 207; не считать 401/302 успешными и не показывать их тела.
- Строго ограничить XML до 16 MiB до парсинга; ограничение временное и должно быть поднято в удобной диагностике при слишком большой медиатеке, а не скрыто.
- Использовать FlatWebDavListingParser из PR #2, запрещающий внешние URI и DTD.
- На следующем шаге вывести только число файлов и обезличенные статусы для проверки на Huawei, затем подключить Room батчами.

## Проверка
MockWebServer/JUnit: один PROPFIND /AllMusic Depth:1, 207/401/302, Basic auth без утечки, ни одного редиректа и без рекурсии, только localhost HTTP в тестах; полный Android CI GMS gate без исключений. Реальный Cloud.Mail.ru XML ещё не протестирован.
