# ADR-0078: Нумерация версий

Дата: 2026-11-12 | Статус: принято владельцем | Автор: Claude

## Контекст

`versionCode` уже монотонный (номер прогона CI) — от него зависит установка поверх. Но `versionName` у всех сборок с первого дня одинаковый: `0.0.1-m0` + `-preview`. Владелец не может назвать, какую сборку он проверил, а отчёты о проверках на Huawei привязываются к сборке только по времени.

## Рассмотренные варианты

1. **Оставить как есть** — ноль усилий. Минус: отчёты неоднозначны, CHANGELOG не делится по версиям, откат «к прошлой рабочей» не адресуем.
2. **Только номер сборки CI** (`preview.425`) — автоматически и однозначно. Минус: не видно, на каком этапе продукт; номер растёт и от PR-сборок, поэтому скачет.
3. **SemVer `0.<этап>.<исправление>` + номер сборки (выбрано).** Читаемо, однозначно, совместимо с привычными `alpha` / `beta`, если они понадобятся при публичном выпуске. Минус: `MINOR` и `PATCH` нужно менять вручную.
4. **Календарная версия** (`2026.11.12`) — проста, но ничего не говорит о готовности; несколько сборок в день всё равно требуют суффикса.

## Решение

- `versionName = 0.MINOR.PATCH` до первого публичного релиза `1.0.0`.
  - `MINOR` = текущий этап роадмапа (M6 → `0.6`). Повышается, когда начинается следующий этап (M7 → `0.7.0`).
  - `PATCH` повышается вручную, когда владелец **принял** результат на Huawei; в том же PR — запись в CHANGELOG под этим номером.
- Суффикс варианта сборки добавляется автоматически:
  - Stable Preview: `-preview.<номер прогона CI>`, например `0.6.0-preview.425`;
  - debug: `-preview.r<номер прогона>` (как раньше).
- Версия показывается в Настройках приложения первой строкой.
- Принятая на Huawei версия получает git-метку `v0.6.N` на точном коммите `main`, из которого собрана проверенная сборка.
- `versionCode` не меняется: номер прогона CI.

## Последствия

- Отчёт владельца: «0.6.0-preview.425: пункты 9, 12 — PASS».
- CHANGELOG: секция `Unreleased` переименовывается в номер версии при её принятии.
- Буквенные стадии (`-alpha`, `-beta`, `-rc`) — только при подготовке публичного выпуска, отдельным решением.

## Как проверить / когда пересмотреть

Настройки → «Версия 0.6.0-preview.<N>», где N совпадает с номером прогона CI артефакта. Пересмотреть перед `1.0.0`.
