# ADR-0054 — извлечение встроенных обложек по запросу, отдельно от индексатора тегов

Дата: 2026-11-10. Статус: первоначальный технический срез; аппаратная проверка и кэш изображений ещё не завершены.

## Контекст

После подтверждения работающей Stable Preview #235 пользователь запросил медиатеку с обложками, полноценными альбомами и современным мини-плеером. Текущий `FastAudioTagReader` преднамеренно пропускает большие фреймы ID3 APIC и FLAC PICTURE, чтобы индексирование 3590 файлов оставалось быстрым. Повторно выполнять полный обход /AllMusic только ради UI недопустимо.

## Решение

1. Вынести поиск изображений в отдельный чистый `EmbeddedArtworkLocator` в `:data:library`. Он вызывается **только по запросу видимого элемента или Now Playing**, никогда из массового индексатора.
2. Поддержать безопасное обнаружение ID3v2.3/v2.4 APIC и FLAC PICTURE. Предпочитать фронтальную обложку (тип 3), иначе использовать первое допустимое встроенное изображение. MIME: JPEG, PNG, WebP; неподдерживаемые/повреждённые метаданные не обходить дорогостоящим чтением всего аудиофайла.
3. Первый срез возвращает **только диапазон** изображения (смещение, длина, тип), не скачивает само изображение, не изменяет Room и не рисует bitmap. Пределы: ≤96 КиБ чтения дескрипторов, ≤12 разных 64-КиБ сетевых блоков, область заголовков ≤16 МиБ, кандидат изображения ≤8 МиБ, ≤256 MP3-фреймов / ≤128 FLAC-блоков. Каждый последующий сетевой слой обязан иметь собственный строгий бюджет, HTTPS и validate Content-Range/ETag.
4. Следующий срез: по запросу загрузить **ровно одно изображение**, проверить декодирование и геометрию, ограничить разрешение для 192/512/1320 px, положить в приватный локальный LRU. Для начального экрана без обложки — placeholder. Отдельно определить, как показывать изображения исполнителей: обложка альбома не равна портрету артиста.
5. Для плоской /AllMusic не угадывать сопоставление sidecar `cover.jpg` по подкаталогам. Не отправлять аудио и обложки третьим сторонам, не подключать GMS, не логировать имя файла/путь/ключ/ETag/картинку. Сохранить индексацию, Room, Media3 и подпись Stable Preview без изменений.

## Приёмка первого среза

- JVM-тесты: APIC v2.3/2.4, FLAC PICTURE, приоритет фронтальной картинки, смещение внутри файла, oversized/corrupt, отсутствие обложек, отказ сети и отсутствие операций для неподдерживаемых форматов.
- CI exact HEAD build/JUnit/lint/no-GMS. На устройство первый срез **не должен добавлять новые HTTP-запросы**: он пока не подключён к Compose UI.
- Кэш, запрос картинок по мере отображения и UI карточек — отдельные контролируемые PR, тестируются на Huawei без переиндексации.

## Открытые вопросы

- Сетевой лимит одного изображения и политика ограничений в списках при быстром скролле.
- Можно ли выбирать изображение по первому треку альбома, когда другие треки содержат другую обложку? Технически выбор возможен, но правила должны быть стабильными.
- Портреты артистов: placeholders до отдельного утверждения источника, без тайных внешних API.
