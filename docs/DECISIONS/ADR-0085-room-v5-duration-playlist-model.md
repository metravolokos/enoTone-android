# ADR-0085: Room v5 — длительность и модель плейлистов

Дата: 2026-11-13 | Статус: принято в задании M6-0/6; реализация в Draft PR | Основание: ADR-0074 (M6-0/6), ADR-0083 (`:data:playlist`), ADR-0080 (выход), ROADMAP (D4), `docs/AUDIT_PROTOCOL.md`.

## Контекст

Room v4 хранит версии удалённых файлов и теги, но не длительность. Индексатор уже читает ограниченные Range-блоки MP3/FLAC; запрашивать новые диапазоны только ради длительности запрещено. У владельца около 3590 записей: массовое дочитывание и автоматическая переиндексация не входят в этот шаг. Плейлистам нужны собственные строки, упорядоченные элементы, аккаунтная область и поведение при отсутствии трека и выходе. Интерфейс плейлистов и показ длительности появятся позднее.

`trackId` стабилен при смене ETag, но вычисляется из `sourceKey + encodedPath`: переименование файла создаёт новый ID. Изменение идентификатора или эвристическое сопоставление не входит в этот ADR.

## Варианты и решение

### Источник длительности

1. **Уже загруженные заголовки плюс значение плеера (выбрано).** Из FLAC читается STREAMINFO; из MP3 — Xing/Info или VBRI в первом аудиокадре, только если эти байты уже находятся в RAM-кэше Range-блоков. При воспроизведении сохраняется известный `Player.duration`, только если Room ещё содержит `null`. Плюсы: не создаёт дополнительных Range-запросов и постепенно заполняет данные при обычном прослушивании. Минусы: CBR-MP3 без Xing/VBRI и не прослушанные старые треки остаются без длительности.
2. **`MediaMetadataRetriever` для каждого файла при индексации.** Плюсы: извлекает длительность независимо от заголовка, поддерживаемого быстрым парсером. Минусы: массово открывает аудио владельца при импорте, увеличивает работу и время индексации, не подходит для WebDAV-файлов без дополнительной загрузки.
3. **Только при воспроизведении.** Плюсы: минимум кода парсера и сетевой работы. Минусы: не использует уже загруженные заголовки и медленно заполняет данные только у прослушанных файлов.

### Повторы трека в плейлисте

1. **Первичный ключ `(playlistId, trackId)` (выбрано).** Плюсы: дубль невозможен на уровне БД, повторное добавление идемпотентно. Минусы: очередь с повторным треком в одном плейлисте потребовала бы миграции схемы.
2. **Суррогатный ID элемента.** Плюсы: один трек можно вставить несколько раз в разных позициях. Минусы: дубли становятся допустимыми уже сейчас, усложняются удаление, проверка членства и перестановка; повторы отложены.

### «Избранное»

1. **Системная строка `playlists.kind = FAVORITES` (выбрано).** Плюсы: использует общую модель и те же элементы/каскады, а получение строки можно сделать атомарно в Room-транзакции. Минусы: для единственности нужна транзакция `getOrCreate`, потому что Room не выражает частичный уникальный индекс для `FAVORITES`.
2. **Булев флаг у `remote_tracks`.** Плюсы: простое чтение статуса. Минусы: связывает трек с одной системной функцией, затрудняет общую модель плейлистов и аккаунтную очистку.

### Элементы отсутствующего трека и выход из аккаунта

1. **При отсутствии оставить элемент и отдавать `present = false`; при выходе удалить плейлисты и треки в одной транзакции (выбрано).** Плюсы: временно отсутствующая запись сохраняет позицию, будущий UI может показать её приглушённой; при выходе не остаются данные аккаунта и осиротевшие элементы. Минусы: запрос элементов делает JOIN с `remote_tracks`.
2. **Удалять элемент сразу при `missingScans > 0` и сохранять плейлисты при выходе.** Плюсы: короткие списки и возможность вернуть плейлисты при повторном входе. Минусы: временное отсутствие теряет пользовательский порядок, а сохранённые имена и связи остаются после удаления учётных данных, что расходится с ADR-0080.

### Миграция

1. **Room `AutoMigration(4, 5)` (выбрано).** Добавляется nullable `durationMs` и создаются новые таблицы с внешними ключами/индексами; Room поддерживает эти изменения и экспортирует схему.
2. **Ручная `Migration`.** Даёт полный контроль SQL, но добавляет код обслуживания и не требуется при данной схеме. Перейти на неё только если проверка Room покажет, что авто-миграция не создаёт требуемые индексы или FK.

## Решение

- `remote_tracks.durationMs INTEGER NULL`; `null` значит неизвестно, `0` не используется. Неизменённая версия сохраняет длительность в планировщике полного upsert. Записи тегов не обнуляют поле; результат быстрого парсера может заполнить его только пока значение `null`.
- Быстрый парсер извлекает длительность из синтетически проверенных FLAC STREAMINFO и MP3 Xing/Info/VBRI только через `readCachedAt`, который не может открыть HTTP-соединение. CBR-MP3 без счётчика кадров остаётся с `null`. При некорректных данных исключение не выходит.
- `PlaybackSnapshot` отделяет реальную известную длительность Media3 от сохранённого значения для отображения восстановленной очереди. App-слой вызывает репозиторий один раз на пару source/track; DAO сохраняет только положительное значение в пустое поле. `:playback` не зависит от Room.
- Таблицы `playlists` и `playlist_items` находятся в одной `EnoToneDatabase`. Системный список `FAVORITES` создаётся в транзакции; одна строка на source обеспечивается атомарным `getOrCreate` на единственном process-wide экземпляре базы. Повторное добавление элемента игнорируется составным PK.
- Обычные элементы сохраняются при `missingScans > 0`, а запрос отдаёт признак `present`. Удаление плейлиста и удаление строки трека каскадно удаляют элементы. Выход удаляет плейлисты аккаунта перед его треками в транзакции `deleteAccountData`, до очистки Keystore.
- Обложка плейлиста не добавляется: по ADR-0067/AGENTS будущая ссылка будет указывать на существующую мастер-обложку альбома без копии.

## Обоснование и последствия

Решение сохраняет сетевой бюджет, направление зависимостей ADR-0083 и правило выхода ADR-0080. В базе уже находившиеся 3590 треков не дочитываются автоматически: пока длительность не заполнена через существующее чтение заголовка или воспроизведение, поле останется `null`. Вопрос о будущем заполнении этих записей вынесен владельцу в описание PR. Эвристика переименования файла остаётся известным ограничением.

`:data:playlist` теперь содержит только модель и репозиторий; UI не создаётся и не считается готовым. Новая внешняя runtime-зависимость или Gradle-модуль не добавляется.

## Проверка

- MigrationTestHelper: v4 с 120 строками и `tagScanCode` → v5; цепочка v1 → v5; значения v4 сохранены и длительность `null`.
- Поведенческие Room/Robolectric тесты: отсутствие дублей при конкурентном `favorites`, add/remove, порядок и перестановка, `present`, FK cascades, удаление аккаунта без затрагивания другого источника.
- DAO и планировщик: сохранение длительности неизменённой версии, очистка при изменённой версии, compare-and-set записи только в `null`.
- Синтетические байты: FLAC STREAMINFO, Xing, VBRI, отсутствие MP3-счётчика кадров и повреждённые данные; MockWebServer подтверждает, что поиск Xing не создаёт дополнительный Range GET.
- Huawei: владелец обновляет Stable Preview поверх текущей и проверяет миграцию без переиндексации; этот результат не подтверждается исходниками или CI.
