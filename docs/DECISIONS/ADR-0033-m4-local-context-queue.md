# ADR-0033 — M4-A: локальная контекстная очередь без новых WebDAV-опросов

Дата: 2026-11-08. Статус: Draft до CI и Huawei smoke.

## Контекст

На Huawei Preview #87 владелец подтвердил все заявленные функции фонового воспроизведения: звук при сворачивании и блокировке, управление из медиауведомления. PR #23 объединён в main после зелёного CI #87 на точном HEAD. В существующей Room уже есть 3590 имён файлов, однако проигрывался ровно один выбранный трек.

## Решение

- Очередь строится **только из текущего видимого списка** на экране «Треки» — с учётом локального поиска. Например, поиск возвращает 50 записей, значит в очередь войдут эти 50 записей в том же порядке. Без поиска — до 3590.
- На нажатие выполнить **один локальный Room запрос** для чтения идентификаторов/путей/size/ETag. Отфильтровать `missingScans>0`, неизвестный/нулевой размер, неверные URL/вложенные пути. **Никаких сетевых PROPFIND**; GET только при выборе текущего трека или переходе к следующему/предыдущему.
- Держать неизменяемый список QueueTrack + текущую позицию в памяти приватного MediaSessionService; пароли отдельно в RAM для продолжения очереди при сворачивании. Очередь не записывается в SQLite, SavedState, Intent, MediaSession extras, уведомления или публичные логи. Стандартная MediaSession показывает только данные активного трека.
- «Предыдущий», «Следующий» — явные кнопки в Compose. После штатного `STATE_ENDED` начать следующий трек автоматически. На последнем треке остановить авто-переход; никакой бесконечной рекурсии или цикла запросов.
- На ручной «Стоп» очистить очередь и ссылки на учётные данные, но оставить приложение открытым. Ошибка чтения отдельного трека не запускает лавину повторов. Ограничение не более 10 000 локальных записей в очереди; новая Preview не скачивает все файлы.
- Media3, HTTPS-only, strict Content-Range/ETag, запрет redirect, GMS-free APK gate, MediaSessionService, Room v2 сохраняются без ослабления.

## Что пока не реализовано

- Передача команд skip-next/previous через системные медиа-кнопки гарнитуры/MediaSession: Media3 ExoPlayer по-прежнему содержит один MediaItem, системная кнопка skip не обязана появиться. В M4-B нужна тестируемая реализация Controller-команд либо полноценного playlist.
- Shuffle/repeat, сохранение состояния очереди после убийства процесса, предзагрузка следующего трека, умный кэш и оптимизация seek относятся к следующим срезам. Не выдавать M4-A за полную M4.
- Фоновая служба продолжает воспроизведение после сворачивания (уже проверено в #87), но новый механизм автоперехода требует реальной проверки.

## Тесты и приёмка

- Синтетический `PlaybackQueueTest`: выбранная позиция, порядок поиска, предыдущий/следующий, границы, 3590 элементов, пустая/невалидная очередь.
- Полный Android/JUnit/lint/Room/GMS-free/signing/artifact CI на точном HEAD. Проверить, что `:playback:testDebugUnitTest` входит в workflow.
- Huawei новой Preview: разово сохранить список /AllMusic (потому что новый applicationId и отдельная Room), открыть медиатеку, найти запросом 2–3 трека, выбрать средний; проверить «Предыдущий» и «Следующий» внутри найденных результатов, остановку, а затем авто-переход в конце **короткого** трека. При сворачивании проверить продолжение музыки, не нужно читать теги всех 3590 файлов.
- Публичный GitHub получает только агрегированные числовые результаты; названия треков/пути/ETag/пароль и скриншоты с уведомлениями не публикуются.
