# ADR-0080: Постоянное хранение входа и полный сброс данных при выходе

Дата: 2026-11-12 | Статус: предложено в Draft PR M6-0/4b | Решение владельца: REQUIREMENTS O-09 (2026-11-12)

## Контекст

ADR-0043 предусматривал отдельное добровольное сохранение учётных данных. Очередь Media3 восстанавливается только при наличии зашифрованного входа. После успешного подключения владельцу не нужна отдельная кнопка сохранения: вход должен переживать перезапуск, а явное «Выйти» должно полностью удалить данные соответствующего аккаунта. Установленная Stable Preview содержит медиатеку, обложки и настройки, поэтому обновление приложения не должно уничтожать данные само по себе.

## Рассмотренные варианты

1. **Всегда сохранять вход после проверки WebDAV (выбран).** Плюсы: очередь восстанавливается после запуска без отдельного пользовательского действия; понятная пара «проверить / выйти»; устройство хранит только шифротекст AES-GCM. Минусы: хранение секрета обязательно до явного выхода, нужен строгий порядок очистки.
2. **Один раз спрашивать согласие на сохранение.** Плюсы: привычная модель для устройств совместного пользования. Минусы: создаёт неоднозначность восстановления очереди и усложняет UI; противоречит решению владельца O-09.
3. **Не хранить пароль вообще.** Плюсы: нет долговременного секрета. Минусы: при каждом запуске ручной вход, невозможна обычная процедура восстановления очереди.

## Решение

- Учётные данные записываются **только после успешного ответа WebDAV** на проверку подключения; запись — AES-256-GCM Android Keystore, приватное зашифрованное хранилище без бэкапа. Провал проверки ничего не записывает. Ранее сохранённые данные восстанавливаются без новой проверки и остаются совместимыми.
- Нет кнопок «Сохранить вход» и «Удалить сохранённый вход». Действие «Выйти» доступно только при наличии входа и предваряется подтверждением с локальным количеством треков.
- `AccountSignOut` вызывает этапы **в порядке**: (1) остановить MediaSession/очередь; (2) завершить два индексатора и дождаться их остановки; (3) удалить только строки Room текущего `sourceKey`; (4) удалить ссылки на обложки и WebP-мастера без оставшихся ссылок; (5) сбросить checkpoint; (6) **последним** удалить вход из Keystore.
- Перед удалением Room сохраняется небольшой служебный manifest с хешами ссылок на обложки: повторный выход после сбоя должен завершить очистку. Мастер WebP другого аккаунта сохраняется, если на него ещё есть ссылка.
- Ошибка этапа прерывает выход с безопасным кодом; прежде очистки данных секрет не стирается. Повторный выход должен быть безопасен. Настройки темы, страниц, режимов обложек и неидентифицирующая диагностика сохраняются.
- Схема Room остаётся **v4**; `DELETE FROM remote_tracks WHERE sourceKey = :sourceKey` не требует миграции.
- `PlayerViewModel` восстанавливает очередь с подтверждённым сохранённым входом. `NO_CREDENTIALS` — только когда после выхода входа нет; новые входы становятся сохранёнными сразу после успешной проверки.

## Последствия и границы

ADR-0080 **заменяет ADR-0043** для изменений M6-0/4b. Пока Draft PR не слит, фактическое состояние `main` определяется прежней версией кода. M6-0/4b не меняет дизайн ADR-0073, ресурсы Android v2, схему Room, WebDAV-клиенты, версию APK или правила индексации. Расширение ViewModel технических инструментов и экранов требует отдельной проверки CI и ревью, прежде чем отмечать шаг завершённым.

## Как проверить

JUnit с фейками: успешное и ошибочное подключение, восстановление, индикатор проверки; порядок выхода, отказ на удалении Room с сохранением входа и повтором, изоляция аккаунтов, сохранение общего WebP. SQL DAO требует отдельного Robolectric-теста (REQUIREMENTS R-8.5). Точный HEAD PR должен пройти Gradle/CI. На Huawei сначала только безопасный Б-1 (просмотр диалога и «Отмена»). **Разрушительный Б-2 — исключительно по отдельному решению владельца:** потребуется повторный полный импорт 3647 файлов.
