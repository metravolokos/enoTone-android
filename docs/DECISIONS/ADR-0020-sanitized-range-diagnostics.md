# ADR-0020: Обезличенная диагностика ошибки Range/MediaMetadataRetriever

Дата: 2026-11-08 | Статус: эксперимент до зелёного CI | Автор: ChatGPT

## Контекст
На Huawei в изолированном Preview #36 (PR #9) пользователь получил общее сообщение «Не удалось прочитать теги одного файла. Лимит 8 МиБ/128 запросов». Это **не** доказывает превышение лимита: прежний код подавлял любое исключение, включая сетевые ошибки, неправильные Content-Range, ETag и отказ платформенного извлекателя. Настоящая причина на устройстве **ещё неизвестна**.

## Решение
- В `WebDavRangeReader` ввести строго фиксированные enum-коды `RangeReadIssue`: `LIMIT`, `HTTP_STATUS`, `MISSING_CONTENT_RANGE`, `BAD_CONTENT_RANGE`, `BAD_ENCODING`, `CHANGED_ETAG`, `SHORT_BODY`, `OVERSIZED_BODY`, `NETWORK`.
- В `RangeReadStats` добавить только числовой HTTP-код и диагностический enum. **Не** добавлять исходные URL, имена треков, ETag, Authorization и тексты исключений.
- Перед передачей источника `MediaMetadataRetriever` прочитать **один байт** через тот же ограниченный Range-клиент. Это позволяет отделить первый HTTP/Range отказ от ошибки извлекателя; загруженный 64-КиБ блок затем используется им же, без дополнительных обязательных запросов.
- На ошибке UI отображает этап `LOCAL_DB` / `SOURCE` / `RANGE` / `EXTRACTOR`, фиксированный код, HTTP-статус и счётчики GET/байт; исходный текст исключений не выводится. Не считать код `PLATFORM_EXTRACTOR` доказательством проблемы формата, если платформа могла скрыть IOException.
- Не увеличивать лимиты (8 МиБ, 128 GET, ~40 секунд), не смягчать проверки 206/Content-Range/ETag/redirect, не переходить к массовому чтению 3590 файлов.

## Проверка
Unit tests: 200/302 → HTTP_STATUS, неверный Content-Range → BAD_CONTENT_RANGE, смена ETag → CHANGED_ETAG, достижение бюджета → LIMIT, кэш и успешные байты как прежде. CI: Android build/tests/lint, Room v1 schema, GMS dependency/APK scanner и identity/signature Preview с новым номером CI. На Huawei после зелёного CI повторить ровно один файл и передать **только обезличенные коды и счётчики**. Каждый новый Preview является отдельным приложением без доступа к локальной Room предыдущего Preview, поэтому требуется один новый импорт списка /AllMusic. Не удалять старый enoTone.
