# ADR-0074: Этап M6-0 — устранение технического долга перед новыми функциями

Дата: 2026-11-11 | Статус: принято владельцем | Автор: Claude (по результатам аудита 2026-11-11)

## Контекст

Функционально M0–M5 работают на Huawei (Stable Preview #301), но аудит выявил накопленный долг, который делает дальнейшую разработку и передачу проекта дорогой:

- архитектура из ТЗ (раздел 4) реализована только номинально: 10 из 15 модулей пустые, весь UI и сервисы в `:app`, нет ViewModel, DI и слоя репозиториев;
- `RoomDatabase` создаётся заново при каждой операции, параллельно в UI и сервисах;
- значимая часть автотестов (`tools/test_*_contract.py`) проверяет наличие строк в исходниках, а не поведение;
- документация превратилась в журналы по 30–75 КБ с противоречиями; за 10–11 ноября шесть раз менялось визуальное направление (ADR-0068…0073);
- функциональные пробелы: нет `WAKE_MODE_NETWORK`, не сохраняется очередь, нет модели плейлистов, нет FTS.

Полный перечень — `docs/KNOWN_ISSUES.md`.

## Рассмотренные варианты

1. **Продолжать функции и UI, долг устранять попутно.** Плюсы: видимый прогресс. Минусы: каждый новый экран добавляется в `MainActivity`, переписываются строковые тесты, растёт стоимость будущего рефакторинга; попутное устранение на практике не происходит.
2. **Один большой рефакторинг-PR.** Плюсы: быстро по календарю. Минусы: невозможно ревьюировать, высокий риск регрессии воспроизведения и Room на рабочем устройстве с 3590 треками.
3. **Отдельный этап M6-0 из серии небольших PR с заморозкой функций и визуала (выбрано).** Плюсы: каждый шаг проверяем CI и при необходимости Huawei, откат точечный. Минусы: несколько дней без новых видимых функций.

## Решение

Этап M6-0, порядок PR (каждый — отдельная ветка `feature/m6-0-<тема>`, зелёный exact-HEAD CI, merge только по команде владельца):

| Шаг | Содержание | Huawei-проверка |
|---|---|---|
| M6-0/1 | Документация: короткие STATUS/KNOWN_ISSUES/TESTING, архив журналов, индекс ADR со статусами, исправление AGENTS.md | нет |
| M6-0/2 | Единственный `EnoToneDatabase` на процесс; `setWakeMode(C.WAKE_MODE_NETWORK)` | да: фон с выключенным экраном |
| M6-0/3 | Сохранение и восстановление очереди, позиции, shuffle/repeat | да |
| M6-0/4 | DI (ручной `AppContainer`, см. ниже), репозитории, ViewModel + StateFlow для медиатеки, плеера, настроек | да: smoke |
| M6-0/5 | Перенос экранов в `:feature:*`, моделей в `:core:model`; удаление или наполнение пустых модулей; замена строковых тестов поведенческими (Robolectric: Room DAO, `MigrationTestHelper`, ViewModel; Compose UI-тесты ключевых экранов) | да: smoke |
| M6-0/6 | Room v5: `durationMs`, таблицы `playlists` / `playlist_items` (ссылка на `trackId`), DAO, миграция, тесты; плейлист «Избранное» как проверка модели. UI плейлистов — не в M6-0 | да: миграция поверх v4 без потери 3590 записей |
| M6-0/7 | FTS4 для поиска, `Collator` (ru), свёртка ё/е, Paging для списка треков | да |
| M6-0/8 | Gradle Wrapper, detekt + ktlint, lint всех модулей, Dependabot, `LICENSE` (лицензию выбирает владелец) | нет |

На время M6-0: **визуальное направление заморожено на ADR-0073**, новых функций нет. Исключение — исправление дефектов, найденных на Huawei.

DI: ручной `AppContainer` в `:app` (продолжение ADR-0008) вместо Hilt/Koin — без кодогенерации и новых зависимостей; при росте графа пересмотреть отдельным ADR.

## Обоснование

Порядок выбран по соотношению риск/польза: сначала дешёвые исправления с реальным эффектом для пользователя (2–3), затем каркас (4–5), после которого новые функции (плейлисты, поиск) добавляются уже в правильные модули (6–7).

## Последствия

- Строковые тесты, ссылающиеся на перенесённые файлы, будут удаляться по мере появления поведенческих замен — не переписываться.
- `MainActivity` и `OfflineLibraryScreen` будут разделены; внешне приложение не должно измениться.
- Документы: STATUS/KNOWN_ISSUES/TESTING описывают только текущее состояние; история — в `docs/archive/`.

## Как проверить / когда пересмотреть

Готовность M6-0: все шаги объединены; в `:app` остаются только навигация, тема и сборка зависимостей; ни одного `openLibraryDatabase()` вне контейнера; не осталось строковых contract-тестов на Kotlin-код; Huawei-проверки шагов 2, 3, 6 пройдены. Пересмотреть, если какой-либо шаг вызывает регрессию воспроизведения или Room на устройстве.
