# ADR-0064 — единая мастер-обложка и локальное масштабирование

Дата: 2026-11-11. Статус: Draft; аппаратная приёмка Huawei и CI exact HEAD обязательны.

## Решение владельца

Не хранить 192/512/1320 px как три самостоятельные дисковые картинки.
Для одного фактически одинакового изображения хранить **одну** сжатую
мастер-версию высокого качества (до 1320 px, без увеличения исходника).
Малые размеры декодировать локально из неё, не обращаясь повторно к WebDAV.
Обложки по-прежнему загружаются **лениво**: при появлении видимой строки,
плитки альбома или воспроизводимого трека, а не во время импорта всех 3590 файлов.

## Техническое решение

- Новая приватная папка cacheDir/enotone-artwork-v2 изолирует мастер-кэш
  от исторических 512px файлов. Старые записи Room и учётные данные не трогаем.
- SHA-256 сжатого мастер-изображения задаёт имя одного art-<hash>.webp.
  ref-<hash-of-account-and-source-version>.txt содержит только хэш
  изображения и связывает его с аудиофайлом/версией источника.
  Разные треки с реально одинаковыми картинками разделяют один
  дисковый объект; разные картинки в одном альбоме **не смешиваются**.
  Из-за отсутствия хэша картинки в WebDAV-листинге впервые запросить
  встроенную картинку у каждого нового исходного файла всё равно может
  потребоваться. Невозможно заранее гарантировать один GET для
  неизвестных одинаковых картинок.
- Дисковый LRU теперь **64 МиБ** (мастера крупнее); один
  мастер-файл — не более 4 МиБ. Ссылки на вытесненные изображения
  удаляются при следующем обращении к источнику.
- RAM LRU не более **12 МиБ** содержит декодированные экранные размеры,
  а не три сохранённых варианта. Для строки трека — 192 px, остальные
  существующие вызовы пока — 512 px. Крупный будущий Now Playing
  сможет запросить до 1320 px из того же мастера.
- Два общих слота семафора и 32 ключевых мьютекса предотвращают
  одновременное повторное чтение одного аудиоисточника при нескольких
  одновременных видимых элементах. Сохраняются ограничения HTTP Range
  (128 запросов / 8 МиБ и строгая проверка 206 / Content-Range).
- После явно подтверждённого обновления тегов выбранного альбома
  удаляются соответствующие source refs и RAM-кэш, включая основную
  картинку отображаемого альбома. Это работает при ошибочно неизменных
  ETag и размере. Общие blob-файлы не удаляются.
- refreshEpoch только перезапускает Compose-загрузчики на обновлённом
  локальном списке, но не меняет постоянный source/version key.

## Границы и последующие этапы

- Нельзя по названию альбома предполагать, что все треки имеют
  идентичную картинку; дедупликация происходит после чтения содержимого.
- Если сеть недоступна или embedded picture отсутствует, показываем
  placeholder и не блокируем воспроизведение.
- Полноценный отдельный Now Playing ещё не реализован: в этой итерации
  подготовлена инфраструктура для будущей крупной обложки.
- Будущие контекстные команды «Переиндексировать исполнителя / альбом»
  используют тот же метод invalidate(email, targets).
- Не меняем Room v4, GMS-free, Media3, очередь, WebDAV-авторизацию,
  стандартную Material 3 тему и правила установки Stable Preview.
- Исторический enotone-artwork-v1 может остаться до очистки кэша Android;
  удаление старых файлов безопасно сделать отдельной оптимизацией.
- Измерить на Huawei скорость списков, память и число повторных GET
  на реальных обложках перед окончательной приёмкой.

## Приёмка

1. Зелёный CI exact HEAD: сборка, JUnit, Lint, Python contract,
   Room schema v1–v4, отсутствие GMS.
2. Только подписанная main Stable Preview поверх установленного приложения
   без удаления: сохранить 3590 записей Room и credentials.
3. Пролистать обложки треков и альбомов, открыть альбом, запустить музыку,
   проверить мини-плеер и повторное открытие списка из дискового кэша.
4. Проверить, что индивидуальные картинки разных треков не подменяются
   альбомной обложкой по названию.
5. Ограниченную ручную переиндексацию картинки проверять только на
   доступных тестовых файлах; не переиндексировать все 3590 ради UI.
