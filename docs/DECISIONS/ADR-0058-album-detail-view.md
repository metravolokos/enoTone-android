# ADR-0058 — детальная страница альбома, без повторной индексации

Дата: 2026-11-10. Статус: Draft PR; необходимо проверить точный HEAD CI и Stable Preview на Huawei.

## Контекст

Владелец подтвердил на Huawei, что Stable Preview #253 загружает обложки альбомов по мере прокрутки и не ухудшает воспроизведение. Дизайн, иконки и нижняя навигация пока остаются без переделки. Продолжаем реализацию функциональности из исходного ТЗ.

Ранее нажатие на карточку в разделе «Альбомы» открывало только список треков. Существует локальная группировка `OfflineLibraryGrouping.albums`, а `AlbumArtworkTile` и `ArtworkPreviewRepository` уже умеют получать встроенную обложку из MP3/FLAC по HTTPS WebDAV Range и использовать частный LRU-кэш 32 МиБ.

## Принятое изменение

- После выбора альбома открыть **отдельный контекст детального просмотра внутри вкладки «Альбомы»**, сохранив прежний возврат по стрелке к сетке. Не открывать новое Activity/запускать сеть при самой навигации.
- В начале скроллируемого `LazyColumn` разместить `AlbumDetailHeader` с крупной обложкой 200dp, названием, реальным исполнителем альбома (уже известный fallback), количеством треков и кнопкой **«Воспроизвести альбом»**. За header остаётся список всех треков с прежним обработчиком нажатия.
- Обложка использует тот же `ArtworkPreviewRepository`, ограничение на количество GET, кэш и placeholder при отсутствии данных. Для виртуального «Неизвестного альбома» остаётся заглушка: нельзя присваивать ему произвольную обложку одного из несвязанных треков.
- Кнопка воспроизведения передаёт **всю группу альбома** в уже существующий `service.playQueue`, независимо от поисковой фильтрации на экране. Нажатие отдельного трека сохраняет прежний механизм очереди из видимых/отфильтрованных треков. У этих действий теперь **один** обработчик Media3.
- Не создавать дополнительных запросов Room, WebDAV/сканирования, сервисов и разрешений. Текущая работающая Preview остаётся приёмочной базой до аппаратной проверки.

## Ограничение метаданных (без ложных сведений)

Room `RemoteTrackEntity` пока хранит title, artist, album, albumArtist и технические метаданные, **но не хранит YEAR, TRACKNUMBER или DISCNUMBER**. `FastAudioTagReader` их также не сохраняет. Поэтому не показывать в деталях вымышленный год и не утверждать, что порядок композиций соответствует номерам в исходном альбоме: пока используется текущая сортировка каталога по названию.

Отдельный будущий этап: расширить быстрый парсер (ID3 TDRC/TYER/TRCK/TPOS, FLAC DATE/TRACKNUMBER/DISCNUMBER), безопасно мигрировать Room и добавить выборочную переиндексацию изменившихся/неполных записей; только после этого отображать год и сортировать по дискам/трекам.

## Проверка

1. Exact-HEAD Android Build/JUnit/Lint/no-GMS; проверки базовых UI/Room/Media3 контрактов.
2. Установить подписанную Stable Preview поверх #253, **не удаляя данные**.
3. Открыть реальный альбом с обложкой: картинка, название, исполнитель, число треков; прокрутить до треков и вернуться в сетку. Повторное открытие использует кэш.
4. Проверить «Воспроизвести альбом», Next, воспроизведение отдельного трека, поиск внутри альбома и корректную очередь при активном поиске.
5. Проверить «Неизвестный альбом», длинные заголовки, отсутствие обложек, отсутствие новой индексации 3590 файлов и сохранение фонового воспроизведения.
