# ADR-0021: Диагностика несовпадения Content-Range без потери безопасности

Дата: 2026-11-08. Статус: ожидает CI и проверки Huawei.

## Реальный результат
Huawei Preview #38: `RANGE; BAD_CONTENT_RANGE; HTTP 206; 1 GET; 0 байт`. Запрос первого блока осуществлён; проверка заголовка не пройдена **до чтения тела**. Это не доказательство достижения 8 МиБ или 128 запросов и не доказательство неподдерживаемого аудиоформата.

## Неизвестно
Существующий код требует `Content-Range: bytes start-end/total` со строгим совпадением **всех трёх чисел** с запросом и размером из WebDAV XML. Ошибка возможна при другом начале, конце, размере, синтаксисе или изменившейся версии файла. Содержимое заголовка на Huawei не известно и публично не экспортируется. Не следует ослаблять проверку наугад.

## Решение
В дополнение к прежнему `BAD_CONTENT_RANGE` фиксировать безопасную классификацию `FORMAT`, `START`, `END`, `TOTAL`, `MULTIPLE` или `INVALID_BOUNDS` и **только** ожидаемые/полученные три числа. Если заголовок не распознан — полученные значения не указывать, **не публиковать исходную строку заголовка**. Ни URL/файловых имён, ни ETag, ни пароля, ни текста исключения в отчёте. Диагностика не парсит и не скачивает тело после несовпадения.

Строгие HTTP 206, Content-Range, If-Range, no-redirect, 8 МиБ, 128 GET и 40 с **без изменений**. В том числе нет массового сканирования библиотеки, нет отключения защиты, нет загрузки аудио в постоянный кэш.

## Дальше
После зелёного CI установить новый изолированный Preview (отдельный пакет нового run), заново импортировать список /AllMusic и выполнить **одну** проверку одного файла. По обезличенному типу/числам решить, нужна ли повторная проверка размера по HEAD/PROPFIND, корректное ограничение блока, другой Range-формат или обработка изменения файла. До этого никаких угадываемых исправлений транспорта.
