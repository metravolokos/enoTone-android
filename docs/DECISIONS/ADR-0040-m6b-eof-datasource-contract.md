# ADR-0040 — M6-B: корректное чтение на границе EOF и безопасная диагностика I/O

Дата: 2026-11-09. Статус: **Принято** — CI #157 и функциональный Huawei Preview #157.

## Контекст и факты

Huawei Preview #147 после первых исправлений управления воспроизведением выдала `PlaybackException.errorCode=2000` на **03:54/03:55**, при текущем `COMPLETE` и следующем `COMPLETE` в приватном кэше. 2000 — **IO_UNSPECIFIED**, не подтверждение ошибки облака, кэша или формата файла. На скриншоте видны имена треков; в Git их не публикуем.

В `WebDavMedia3DataSource.open()` прежняя проверка `position in 0 until remoteSize` **ошибочно отклоняла `position == remoteSize`**. По документированному контракту AndroidX Media3 DataSource, такое открытие разрешено: `open()` успешно, `read()` сразу возвращает `RESULT_END_OF_INPUT`. Для позиции **больше** размера обязателен `DataSourceException(ERROR_CODE_IO_READ_POSITION_OUT_OF_RANGE)`. Непроверено, был ли именно этот дефект причиной наблюдавшейся ошибки: одних скриншотов недостаточно.

## Рассмотренные варианты

1. При 2000 автоматически скипать дальше или многократно повторять WebDAV GET. Отвергнуто: скрывает ошибки, может создать бесконечный цикл/лишний трафик, ломает явную Pause, не устраняет причину.
2. Убирать проверки Content-Range/ETag, принимать HTTP 200 или изменять сетевой стек. Отвергнуто: регресс безопасности и недостоверные данные, нет доказательств необходимости.
3. Исправить **точный контракт EOF**, сохранять строгие проверки в остальных случаях, добавить whitelist-only диагностическую классификацию I/O. Выбрано.

## Решение

- Чистая модель `PlaybackReadWindow`: `position<size` → валидный точный диапазон; `position==size` → EOF **без HTTP**, `bytesLeft=0`, стандартные события DataSource, следующий `read()` → `RESULT_END_OF_INPUT`; `position>size` → Media3 IO 2008. Не выходить за `remoteSize`; с известной запрошенной `DataSpec.length` возвращать по контракту её значение, хотя `read()` завершится при фактическом EOF.
- `WebDavMedia3DataSource` по-прежнему требует HTTPS с фиксированным origin, HTTP 206, точный Content-Range, ETag при наличии, отсутствие redirect и identity encoding. Фактический преждевременный EOF тела остаётся ошибкой.
- `PlaybackDataIssue`: только фиксированные OPEN_STATUS/OPEN_RANGE/OPEN_ENCODING/OPEN_VERSION/OPEN_LENGTH/OPEN_NETWORK/READ_NETWORK/READ_TRUNCATED/UNKNOWN. Исключения сети не протаскивают оригинальные messages и causes с потенциальными частными URL. UI показывает только безопасный код стадии при ошибке, без имён/путей/токенов.
- Не менять staged Media3, существующий temp current+next CacheWriter, лимиты кэша, кнопки Pause/Next, GMS-free и стандартную MaterialTheme.

## Проверка и последствия

- Kotlin `PlaybackReadWindowTest`: EOF равно размеру, EOF с заданной длиной, чтение до/после границы, попытки за размером, неверные значения; `PlaybackDataIssueClassifierTest`: вложенные исключения и отсутствие приватных текстов.
- Static security contract: отсутствие HTTP в ветке EOF, категоризация IO без сырых exception details, проверка вызова read.
- На точном HEAD пройти Android/Room/JUnit/lint/MockWebDAV/GMS/APK и выдать отдельную Preview. На Huawei повторить **естественное окончание**, прямой Next из Pause, seek около конца при полном кэше, repeat-one и проверить реальный звук на следующем треке. Если код 2000 сохранится — сообщить только whitelist stage и общий код ошибки; не делать выводы без новых чисел.
- Это устраняет **доказанный дефект контракта** исходника. Аппаратная причина остановки останется гипотезой до повторного Huawei smoke.

## Финальная приёмка (2026-11-09)
После исправления Media3 EOF-контракта Huawei Preview #157 прошла проверки перемотки и переходов. CI #157 success, PR #30 merged. Исправление дефекта контракта доказано тестами; что именно он был первопричиной прежнего IO 2000, однозначно не установлено.
