# ADR-0024: Аудиотеги одного файла — атомарная запись в Room v1

Дата: 2026-11-08 | Статус: реализация до CI и Huawei

## Основание
Ручной результат владельца на Huawei enoTone Preview #45: один реальный файл, title=1, artist=1, album=1, HTTP Range GET=50, загружено 3 276 800 байт (3,125 МиБ). Сетевых ошибок и ошибок извлечения не было. Реальные названия, путь, ETag и учётные данные в GitHub не переносились.

Это успешное извлечение **одного файла**, а не доказательство качества или цены обработки всей коллекции.

## Решение
- Использовать уже существующие nullable поля title/artist/album/albumArtist из Room v1 без изменения схемы.
- Только по добровольному нажатию кнопки для **одного файла** после успешной работы MediaMetadataRetriever выполнять один SQL UPDATE.
- Условие UPDATE сравнивает id, sourceKey, encodedPath, remoteEtag, remoteSize, remoteModified и требует missingScans=0. Сравнение nullable полей использует SQLite IS. Если список обновился, SQL меняет 0 строк — прежние теги не перезаписывают новую версию.
- Перед запросом проверять источник, идентификатор, плоский путь, положительный размер и отсутствие пометки о пропаже файла.
- В интерфейсе оставлены только флаги title/artist/album, число GET, байты и результат «Сохранено в Room: 0/1». Сами значения не выводятся. Пароль никогда не записывается в БД.
- Нельзя считать compare-and-set по Room подтверждением неизменности самого удалённого файла, если сервер не сообщил сильный ETag: для массовой индексации необходима отдельная проверка.

## Стоимость и ограничения
50 GET и 3,125 МиБ на одном файле могут оказаться чрезмерными при обработке 3590 треков. Пока не включать массовую загрузку и не повышать лимиты 8 МиБ / 128 GET / 40 секунд. Перед серийной индексацией измерить диапазоны и чтение нескольких форматов, разработать ограниченный план.

## Проверки
Unit tests проверяют отсутствие записи при чужом источнике, неправильном id, вложенном пути, нулевом размере и missingScans. Компиляция Room KSP проверяет SQL, существующая схема Room v1 должна остаться неизменной. Нужны зелёный CI на точном HEAD и ручной тест единственного сохранения на Huawei; инструментальный тест параллельной записи в настоящую БД пока не проведён.
