# ADR-0061 — повтор выборочных тегов после неполных/временных ошибок

Дата: 2026-11-10. Статус: Draft PR, требуется CI и проверка на Huawei.

## Подтверждённая проверка #266

Владелец прислал последовательность экранов нескольких альбомов. У «…Который возвращается» в ходе нескольких пользовательских попыток были разные результаты, включая 7 обработанных / 6 прочитанных и 2 / 2; в последнем снимке показано **9 / 9** и все девять реальных номеров композиции. Никакого подтверждённого исчезновения номеров из уже успешно прочитанных записей нет. Годы для некоторых других альбомов отображаются корректно. Ручной путь Room v3/Media3 стабилен.

## Дефект старого поведения

`PilotTagIndexer.onFileCompleted(id)` вызывался после попытки, независимо от того, записалась ли в Room успешная конечная версия тегов или случился временный сбой `RETRY_NETWORK`, `RETRY_HTTP`, `FAILED_...` либо stale CAS. `AlbumTagRefresher.checkedIds` ошибочно включал **все** попытки. Экран исключал такой ID до уничтожения Compose-состояния. Поэтому пользователь мог вынужденно выйти и снова зайти в альбом, чтобы повторить ошибочный файл. Сообщение «Проверено» не объясняло, что результат относится лишь к последнему запуску, и не отличало запросы от успешных сохранений.

## Решение

- Добавить callback `onFileOutcome(id, completed)` к прежнему `onFileCompleted`; `completed=true` только при успешной атомарной записи терминального, не `RETRY_...` и не `FAILED_...`, результата.
- Результат выборочного обновления возвращает отдельные наборы `attemptedIds` и `checkedIds` (успешно завершённые). Последние пропускаются в рамках открытой страницы, а неудачные остаются пригодны для повторного подтверждённого запуска.
- Планировщик `AlbumTagRefreshSelection.nextBatch` по-прежнему выбирает только допустимые локальные ID **одного альбома** (предел 10), но отдаёт приоритет ещё не проверенным трекам, чтобы проблемный ранний трек не блокировал оставшиеся. Уже завершённые исключаются.
- В UI разделять **«За попытку: проверено X, теги прочитаны Y»** и **«Незавершённых в порции Z»**; при сетевой паузе или бюджетном ограничении показывать нейтральную причину, без секретов/сырых URL и текстов исключений.
- Не увеличивать число попыток автоматически, каждый повтор требует отдельного нажатия/подтверждения. Не изменять лимиты GET, фоновое воспроизведение, очередь, кеш обложек, Room v3, MediaStore или запросы к глобальному индексу.

## Проверка

Synthetic 9-track album: при 7 попытках с 6 успешными второй выбор должен быть **8, 9, 7**, а не повторять успешно сохранённые 1–6 и не блокировать 8–9 неудачной попыткой 7. Synthetic 3590-track catalogue: максимум 10 ID в UI без HTTP или Room. Проверить точный HEAD CI/JUnit/Room/no-GMS и Stable Preview на Huawei поверх #266. В проблемном альбоме воспроизведение не должно прерываться, отчёт должен показывать число незавершённых файлов после каждой порции.
