# ADR-0082: Версия файла для обложек без перекачки кэша

Дата: 2026-11-13 | Статус: действует (PR этого ADR) | Источник: внешний аудит 2026-11-13, п. 5

## Контекст

Импорт считает файл изменённым, если изменились ETag, размер **или** `remoteModified` (`LibrarySnapshotPlanner.sameRemoteVersion`), и тогда перечитывает теги. Ключ ссылки на обложку (`ArtworkPreviewRepository.sourceKey`, ADR-0067) содержит ETag и размер, но не `remoteModified`. Если сервер переписал файл с прежними ETag и размером, теги обновятся, а старая обложка останется действительной и после перезапуска. Кроме того, RAM-кэш альбома возвращал картинку по ключу альбома до проверки, не изменился ли набор источников.

## Рассмотренные варианты

1. **Добавить `remoteModified` в ключ обложки.** Плюсы: версия обложки строго совпадает с версией тегов. Минусы: все сохранённые ссылки владельца (~3647 треков, сотни альбомов) станут недействительными; без отдельной миграции — массовая повторная загрузка обложек (запрещено ADR-0067: никаких массовых image GET); миграция требует знать старое mtime для каждой ссылки.
2. **Сбрасывать ссылки только у файлов, которые импорт признал изменёнными (выбран).** Плюсы: ключи и сохранённые мастера не меняются, повторно читаются только изменённые файлы и только при показе (или автообходе); одна точка — результат планировщика. Минусы: изменение, пропущенное импортом, не заметит и обложка — но тогда не обновятся и теги, то есть поведение согласовано.
3. **Ничего не менять.** Отклонено: расхождение тегов и обложки остаётся.

## Решение

- `SnapshotPlan.changedIds` — идентификаторы файлов новой версии (не новых). После сохранения списка `AndroidLibraryIndexingGateway` вызывает `artworkPreviewRepository.invalidate` для них: удаляются только ссылки этих источников и записи выбора альбомов; общие WebP-мастера остаются.
- RAM-ключ альбома включает хеш набора источников (`group.targets`, с версиями и эпохой переиндексации): после изменения состава или версий альбома старая картинка из памяти не возвращается.

## Последствия

Сохранённый кэш обложек не перекачивается. Изменённые файлы получают обложку заново при следующем показе или автообходе. Ключ ADR-0067 не меняется.

## Как проверить

JUnit `LibrarySnapshotPlannerTest`: изменение только mtime попадает в `changedIds`, неизменённые и новые — нет. На устройстве: обычное «Обновить медиатеку» без изменений в облаке не вызывает загрузки обложек.
