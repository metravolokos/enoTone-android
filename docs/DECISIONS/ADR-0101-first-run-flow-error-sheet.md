# ADR-0101 — Поток первого запуска и лист ошибки (D6)

**Дата:** 2026-11-19. **Статус:** предложен, ждёт решения владельца. **Риск:** R (вход и выход аккаунта; контракт запуска приложения). **Связано:** ADR-0080, ADR-0090, ADR-0093, DESIGN_PLAN (D6), `design/assets/ui-screens/android-v2/12_states_graphite.png` и `13_states_porcelain.png`, задачи D6-0, D6-FR, D6-FR2, D6-A, D6-B, D6-E, D6-F.

## Контекст

Макеты D6 содержат четыре экрана первого запуска: «Вход» («Привет! Я Бандит»), «Индексация» («Читаю вашу музыку…»), «Индексация на паузе» («Задремал — нет сети») и «Индексация завершена» («Всё готово!»). Сейчас отдельного стартового экрана нет: вход живёт в `AccountSettingsSection`, индексация — в «Настройках». Ошибки показываются техническим текстом с числовым кодом (`playback_error`, `account_verification_failed`).

Решения владельца 2026-11-19:
1. «Вход», «Читаю…» и «Всё готово» — полноэкранные экраны **только первого запуска**; повторять их в «Настройках» или где-либо ещё не нужно.
2. «Задремал» — вариант экрана индексации первого запуска при пропаже сети.
3. «Ничего не нашлось», «Облако не отвечает», «Где же музыка?» и «Настройки» — обычные экраны работы приложения. «Тишина» и поза `RELAXING` в экране не используются; поза остаётся в наборе и нужна листу ошибки.
4. «Слушать, пока читаю» уводит в приложение; индексация продолжается в фоне; экран «Готово» тогда не показывается.
5. Вход пока только для Облака Mail.ru. Выбор сервисов появится позже; заглушки не делаем.
6. `NetworkCallback` разрешён (`ACCESS_NETWORK_STATE` уже есть в манифесте).
7. **Лист ошибки.** Ошибка проверки входа, ошибка индексации не из-за сети (например, отозван пароль) и ошибка плеера показываются всплывающим листом по аналогии с листом действий песни: Бандит `RELAXING` («Ничего не играет»), текст «Пока ошибка {описание ошибки}, я немного отдохну», одна кнопка по ситуации; высота листа не больше ¾ высоты экрана.

Что есть в коде: `VaultCredentialsProvider` / `LocalCredentialVault.restore` (вход), `SignOutMarker` (незавершённый выход, ADR-0080), `LibraryIndexingUiState.hasLogin`, checkpoint индексации, `EnoActionSheet` (`ModalBottomSheet`, `:core:ui`).

## Варианты (поток первого запуска)

1. **Фаза вычисляется только из существующих данных, без нового флага.** Плюсы: нет нового хранимого состояния; существующие установки «пройдены» автоматически. Минусы: «Готово» нельзя показать ровно один раз и нельзя отличить «ушёл по „Слушать, пока читаю“» от «результат ещё не показан»; после закрытия на экране «Готово» оно может показаться повторно.
2. **Явный флаг `firstRunCompleted` + вычисляемые правила приоритета (выбран).** Плюсы: «Готово» ровно один раз; решение 4 выражается одной записью; миграция одной строкой. Минусы: ещё одно хранимое состояние; сброс при «Выйти» меняет путь выхода (класс R).
3. **Оставить вход в «Настройках» (статус-кво).** Отклонён владельцем: нет единого пути первого запуска.

## Варианты (показ ошибок)

1. **Полноэкранный экран ошибки.** Плюсы: максимум места. Минусы: перекрывает контекст (поля входа, плеер), нужен свой возврат и свои правила Back.
2. **Лист поверх экрана, ¾ высоты (выбран, решение владельца).** Плюсы: контекст остаётся под листом; привычное поведение (жест вниз, нажатие вне листа, Back), общий компонент с листом действий. Минусы: нужен предел высоты и прокрутка при длинном тексте или крупном шрифте.
3. **Snackbar.** Минусы: нет места для Бандита и объяснения, пропадает сам.

## Решение

### Поток первого запуска

Флаг `firstRunCompleted` — `SharedPreferences` без личных данных, исключён из backup (как `SignOutMarker`). Фаза определяется чистой функцией `FirstRunPhasePlanner` по входу, флагу, `SignOutMarker`, состоянию индексации и доступности сети:

| Условие | Фаза |
|---|---|
| `SignOutMarker.pending` | `APP` (пользователь повторяет «Выйти» в «Настройках», как в ADR-0080) |
| нет сохранённого входа | `LOGIN`; флаг записывается `false` |
| вход есть, ключа флага нет в хранилище (установка до ADR) | флаг записывается `true`, `APP` |
| вход есть, флаг `false`, индексация идёт или возобновляется, сеть есть | `INDEXING` |
| то же, сети нет | `INDEXING_OFFLINE` («Задремал») |
| вход есть, флаг `false`, индексация завершена, песни есть | `DONE` |
| то же, песен нет | флаг `true`, `APP` (покажет «Где же музыка?») |
| вход есть, флаг `true` | `APP` |

Переходы:
- `LOGIN` → успешная проверка WebDAV (вход сохраняется по ADR-0080, флаг `false` записывается явно) → индексация стартует сама → `INDEXING`.
- `INDEXING` → «Слушать, пока читаю» → флаг `true` → `APP`; служба индексации продолжается, «Готово» не показывается.
- `INDEXING` → завершена → `DONE` → «К музыке» → флаг `true` → `APP`.
- `INDEXING_OFFLINE` ↔ `INDEXING` автоматически по сигналу сети; «Повторить сейчас» — немедленная повторная попытка.
- Перезапуск при флаге `false`: возврат на `INDEXING` (индексация возобновляется по checkpoint) или `DONE`, если она успела завершиться.
- «Выйти» (ADR-0080): флаг записывается `false` после удаления данных и до очистки Keystore, который остаётся **последним**. Если процесс убит между шагами, правило «нет входа → `LOGIN`» сбрасывает флаг.
- Back на `LOGIN`, `INDEXING`, `DONE` закрывает приложение (индексация в службе продолжается); вкладок и «Настроек» в первом запуске нет.

### Лист ошибки (`EnoErrorSheet`, `:core:ui`)

- Построен как `EnoActionSheet` (`ModalBottomSheet`, скругление `EnoRadii.xl`, ручка, фон `surfaceContainerHigh`, системные панели как в листе действий).
- Содержимое по центру: Бандит `RELAXING` (декоративный), текст «Пока ошибка {описание ошибки}, я немного отдохну», одна кнопка (акцент). Описание — короткая фраза голосом приложения, **без числовых кодов и путей**; коды остаются в «Диагностике».
- Высота не больше 75 % высоты экрана; при длинном тексте или крупном шрифте содержимое листа прокручивается, кнопка остаётся видимой.
- Закрывается жестом вниз, нажатием вне листа и Back; закрытие оставляет экран под листом в прежнем состоянии. Одновременно показывается один лист.
- Применения: ошибка проверки входа и ошибка индексации не из-за сети (D6-FR), ошибка плеера (D6-F, заменяет строку с кодом в мини-плеере и «Сейчас играет»; код остаётся в «Диагностике», Play-обход по ADR-0093 сохраняется).
- Кнопка по ситуации (предложение, уточняется в PR): неверные данные входа — «Ввести заново»; сервер не ответил — «Повторить»; вход больше не подходит при индексации — «Войти заново» (открывает «Вход» с почтой, **не удаляя** медиатеку); прочая ошибка индексации и ошибка плеера — «Повторить».

Тексты и позы Бандита остальных экранов — по макету; ошибки — без технических кодов (голос приложения, решение 2026-11-12).

## Что не входит
- Выбор сервисов подключения; вторая точка входа в «Настройках» для тех же экранов; повтор «Читаю…» и «Готово» в других местах.
- Экран «Тишина».
- Экран «О приложении» (в коде его нет; до решения владельца не создаётся).

## Последствия
- Класс R для D6-FR: два независимых ревью; сценарии — вход, выход, перезапуск посреди индексации, потеря сети, миграция, ошибка пароля.
- Открытый вопрос для исполнителя D6-FR: запрос `POST_NOTIFICATIONS` перед стартом управляемой индексации — при отказе поток не должен застревать на «Индексации»; вариант предлагает исполнитель в PR, решает владелец.
- Новые строки ресурсов с префиксами `first_run_*`, `state_*`, `error_sheet_*`; общие компоненты — `EnoStateView`, `EnoErrorSheet` (D6-0).

## Как проверить
- Юнит-тесты `FirstRunPhasePlanner` на все строки таблицы.
- Robolectric: миграция (вход есть, ключа флага нет → `APP`), сброс флага при «Выйти», возобновление после перезапуска.
- Roborazzi: экраны первого запуска и `EnoErrorSheet` × две темы, в том числе крупный шрифт; высота листа ≤ 75 % экрана.
- Huawei: поток нельзя пройти без «Выйти» и полного импорта 3590 файлов — только по отдельной команде владельца (AGENTS §3); до тех пор PASS по этим сценариям не выставляется. Лист ошибки плеера и индексации проверяется через тестовые сценарии/ADB-харнесс.
