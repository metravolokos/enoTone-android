# ADR-0018: WebDAV Range MediaDataSource — пробное чтение тегов одного файла

Дата: 2026-11-08 | Статус: эксперимент, до зелёного CI и ручного теста на Huawei

## Контекст
В приватной Room на Huawei подтверждены 3590 аудиофайлов в плоской /AllMusic. PR #7 добавил системный MediaMetadataRetriever из абстрактного MediaDataSource. Реальный WebDAV ранее ответил HTTP 206 на один Range-запрос; получить теги без полного скачивания пока не проверено.

## Решение
- `WebDavRangeReader` на системном `HttpURLConnection`, отдельная обёртка `WebDavRangeMediaDataSource` для Android. Транспорт PROPFIND остаётся Ktor CIO; Range сейчас только для пробной диагностики, **не** плеер.
- Разрешён только фиксированный HTTPS-хост `webdav.cloud.mail.ru`, плоский путь файла из приватной Room; произвольный URL из пользовательского поля не принимается. Тестовый HTTP разрешён только на loopback для MockWebServer.
- Каждый GET обязан вернуть **HTTP 206**, точный `Content-Range` и `Content-Encoding: identity` (или без заголовка). **Redirect запрещён**. При сильном ETag отправляется `If-Range`, несовпадающий ETag в ответе отклоняется; на слабом ETag условие не применяется.
- Блок 64 КиБ, RAM-кэш только последнего блока. На один опыт бюджет **8 МиБ**, **128 запросов**, **40 секунд** общего активного времени плюс тайм-ауты отдельных соединений; нет дискового аудиокэша и фонового продолжения.
- Диагностическая кнопка выбирает **один** файл из локальной базы (с приоритетом MP3) или конкретный файл по указанному пользователем пути. Отчёт показывает только наличие title/artist/album (0/1) и численные показатели запросов/трафика. Сами названия, пути, ETag и пароль не выводятся и не сохраняются в отчёте.
- Значения тегов на этом этапе **не записываются** в Room; автосканирование всех 3590 файлов запрещено до подтверждения бюджета и форматов.

## Альтернативы
1. `MediaMetadataRetriever.setDataSource(url, headers)` — сложно ограничить общий сетевой бюджет и redirect; отклонено.
2. Скачивание всего файла — ненужный трафик; отклонено.
3. Собственный ID3/FLAC парсер — значительно увеличивает объём работ, отложено.
4. Дополнительный HTTP клиент для метаданных — пока не нужен; системного достаточно для разового диагностического опыта.

## Проверка и открытые риски
MockWebServer/JUnit: кэш и диапазоны, корректный EOF, отказ на 200/302/ошибочном Content-Range/ETag, блокировка путей вне папки, ограничения 128/8 МиБ. CI: Android, JUnit, lint, GMS-free APK, Room schema v1. Реальное чтение через MediaMetadataRetriever на Huawei и форматы MP3/FLAC/OGG ещё **не подтверждены**. Нет гарантий прерывания нативного декодера сразу при отмене; отдельные GET ограничены connect/read timeouts.
