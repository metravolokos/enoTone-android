# ADR-0084 — дизайн-система Android v2 в коде (D2)

**Дата:** 2026-11-13. **Статус:** принято владельцем 2026-11-13; реализация D2a/D2b в отдельных PR. **Заменяет:** ADR-0073 как визуальное руководство.

## Контекст
D1 (ADR-0079) ввёл ресурсы, не меняя интерфейс. После #119 (ADR-0083) Home и Now Playing живут в `:feature:library` и `:feature:player`, но drawable и тема ещё в `:app`. Feature не вправе ссылаться на `app.R`: уже потребовался `NowPlayingIds` с 28 ID. Android v2 принят владельцем целиком, включая тени, полупрозрачную полосу с размытием и индикатор воспроизведения. D2 готовит дизайн-систему, не переписывая экраны (D3–D6).

## Варианты размещения
1. **Общий `:core:ui`** с Android-ресурсами, темой и stateless-компонентами. Плюсы: независимый от `:app` ресурсный API для обеих feature; единые токены и проверяемые компоненты. Минусы: один дополнительный Gradle-модуль, сборка и API требуют сопровождения.
2. **Оставить тему и ресурсы в `:app`**, прокидывать drawable ID и цвета через параметры, а тему — через `MaterialTheme`. Плюсы: меньше модулей сейчас. Минусы: повторение контрактов ресурсов для Home/Now Playing и последующих D3–D6, дополнительное связывание слоёв.
**Решение:** вариант 1 — одобрено владельцем 2026-11-13, 21:13 МСК («Я согласен на оба»). Зависимости `:app → :feature:* → :core:ui`; `:core:ui` не зависит от других проектных модулей. Существующие строки, приложение, `AppContainer`, launcher остаются в `:app`.

## Варианты визуальных тестов
1. **Roborazzi + существующий Robolectric**, `testImplementation` в `:core:ui`, эталоны обеих тем в Git, CI сравнивает снимки и выгружает diff. Плюсы: ловит смены цветов, типографики, геометрии. Минусы: чувствителен к среде рендера; эталоны записывать в том же CI-окружении.
2. **Только семантические Compose-тесты** и ручная проверка Huawei. Плюсы: меньше инфраструктуры. Минусы: визуальная регрессия остаётся до smoke.
**Решение:** вариант 1 — одобрено владельцем 2026-11-13, 21:13 МСК. Roborazzi только для тестов, не в APK. Никаких строковых тестов исходников.

## Метрика модулей «в обе стороны»
Проверено `git log -- settings.gradle.kts` на базе `89545ea`: начальное создание репозитория `2cda186` создало 15 Gradle-модулей (не PR); **PR #119** (`9a841ac`) удалил 5 пустых модулей (15 → 10). Следовательно, среди PR до D2: **добавивших модули — 0, удаливших — 1 (#119)**; D2a предлагает добавить один `:core:ui` (10 → 11). Это оправдано: #119 и переносы Home/Now Playing, а ранее #98 (D1 ресурсы в app) уже выявили необходимость независимого ресурсного слоя. Обязательное сокращение после D6: удалить неиспользуемые компоненты и старые `ic_action_*`/`ic_nav_*`/`ic_music_*` после миграции экранов.

Собственные заливки Android v2 явно используют `EnoColors.accentFill`; `EnoColors` содержит line, onAccent, shadow, coverOutline, playingOverlay/bar и 6 пар цветов аватаров.

## Типографика и геометрия
Onest variable с `FontVariation.weight` 400/500/600 для обычного текста, Unbounded variable 600 **только** `headlineLarge` 30sp, `headlineSmall` 24sp и буква аватара (в D2b). Wordmark остаётся drawable. Размеры: `titleLarge` 23, `titleMedium` 18, `titleSmall` 17, `bodyLarge` 16, `bodyMedium` 15, `bodySmall` 13.5, `labelLarge` 15.5, `labelSmall` 11.5 sp. Радиусы `EnoRadii`: 10, 16, 22, 24, 28, sheet 48 dp и full 50 %; **56 dp — внешний радиус устройства, не токен**. Тени `EnoElevation`: Now Playing Y22/blur44, альбом Y18/blur40, мини-плеер и навигация Y8/blur24, sheet Y−10/blur40 dp; покров обложки outline 1 dp. Реализацию сверять по снимкам; выбор модификатора и близость к макетам документировать в D2b.

## Границы и последствия
D2a заменяет палитру/шрифты всего приложения, но не меняет навигацию, вёрстку, строки, функциональное поведение, Room, очередь, учётные данные, `UiAppearance` (ключ `enotone_ui_appearance_v1` и SYSTEM/DARK/LIGHT), ID и подпись Stable Preview. M3-элементы `Slider`, `NavigationBar` и др. остаются до замены экрана в D3–D6. ADR-0073 перестаёт задавать визуал, однако запрет кнопок-заглушек, сохранность пользовательских данных и отсутствие выбираемого акцента остаются. D2b вводит компоненты с Preview/скриншотами, **не** подключая к экранам.

**D3:** полупрозрачная полоса 84% background, линия 70% line, размытие подлежащего слоя 18dp. `Modifier.blur` размывает сам компонент, не содержимое позади: нужен новый ADR для библиотеки вроде Haze либо запасной вариант ~94% непрозрачности только для API <31. Дополнительные runtime-зависимости без решения владельца запрещены.
