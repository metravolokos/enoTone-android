# ADR-0059 — год выпуска, номер трека и номер диска MP3/FLAC

Дата: 2026-11-10. Статус: Draft PR #62, требует CI и проверки миграции на Huawei.

## Контекст

Stable Preview #256 пользователь проверил на Huawei: детальная страница альбома, обложка и кнопка «Воспроизвести альбом» работают. Оставляем дизайн Material без изменений. Ранее база Room v2 содержала title/artist/album/albumArtist, но не хранила год/порядок. Порядок был по алфавиту. Библиотека плоская: **3590 файлов** в `/AllMusic` (главным образом FLAC и немного MP3).

## Изменение

- `AudioTagFields` содержит три новых **nullable Int**: `year`, `trackNumber`, `discNumber`. Принимать YYYY, YYYY-MM или YYYY-MM-DD и положительные номера с необязательным суффиксом `/total` в ограниченных пределах (год 1000–2999; номер трека 1–999, номер диска 1–99). Неизвестное/некорректное оставлять `null`.
- `FastAudioTagReader` читает MP3 ID3v2.3/v2.4 поля `TDRC` / `TYER`, `TRCK`, `TPOS`, FLAC Vorbis `DATE` / `YEAR`, `TRACKNUMBER`, `DISCNUMBER`. Сохраняет прежний лимит 6 диапазонов по 64 КиБ, максимум 96 КиБ прочитанных тегов, не загружает APIC/PICTURE.
- Room `EnoToneDatabase` меняется с v2 на **v3**, `AutoMigration(from=2,to=3)` добавляет три необязательные колонки. Миграция не удаляет строки, индекс, аккаунты, статус сканирования, старые теги, настройки или очередь. Схема v1 и v2 остаётся в репозитории. Включить экспорт точной v3 schema, не угадывать identity hash.
- `LibraryTagStore` и `ParallelTagIndexer` передают числовые теги в атомарные DAO update, с теми же проверками ETag, размера, изменённого времени, ID аккаунта и отсутствия пропусков. Обычная ошибка повторного чтения не очищает подтверждённую старую запись. `LibrarySnapshotPlanner` сохраняет новые поля при неизменной версии и сбрасывает только при смене версии.
- `OfflineTrackCatalog` проецирует новые поля, сортирует композиции на экране и в очереди альбома по диску, затем номеру трека; отсутствующие номера — по названию. Трек с номером показывает его, без номера — нет. В заголовке альбома год появляется, если у известной части треков год один и тот же; при конфликте нескольких годов не показывать ничего.

## Политика запросов и старой медиатеки

**Никакой автоматической повторной индексации всех 3590 файлов после обновления APK.** У уже проиндексированных записей три новые колонки остаются NULL. Извлечь значения можно с помощью прежнего явного механизма очереди обновления тегов (выбор отдельных записей через аудит, или явная повторная индексация в настройках); чтение использует ограниченный WebDAV Range. Отдельной доработкой можно дать пользователю удобное массовое обновление тегов ровно **выбранного альбома**, а не всей библиотеки.

## Не изменяем

UI-темы, Mascot/иконки, пятипозиционную навигацию, структуру музыкальной библиотеки, ключи локального шифрования учётных данных, Media3, кэш аудио, кэш обложек/лимиты GET, Stable Preview signing.

## Проверка

CI exact HEAD: Kotlin/JUnit, синтетические ID3v2.3/v2.4 и FLAC с большой обложкой, валидация числовых полей и различных дат, Room KSP auto-migration, исходные схемы v1/v2 и точный экспорт v3, Lint, no-GMS, компиляция Stable Preview. Установить подписанный APK **поверх #256** на Huawei с сохранением 3590 локальных записей, проверить отсутствие полной пересканировки и доступность всех альбомов. Затем выборочно обновить теги нескольких MP3/FLAC и проверить сортировку по диску/номеру, год, очередь «Воспроизвести альбом», предыдущие обложки и фоновую музыку.
