# ADR-0098 — Версия компилятора в CI-зеркале берётся из каталога версий, а не задаётся литералом

**Дата:** 2026-11-17. **Статус:** реализовано в ветке `ci/f-03-compiler-mirror-version`, ожидает приёмки владельцем. **Связано:** ADR-0076 (quality tooling, собственный шаг установки Gradle с проверкой SHA-256 и запасными зеркалами), ADR-0074 (корневые задачи по всем модулям), находка F-03 [аудита 2026-11-17](../audit/AUDIT_2026-11-17_local-state.md), Issue #195.

## Контекст

CI содержит шаг предзагрузки компилятора Kotlin: он скачивает `kotlin-compiler-embeddable`, проверяет SHA-256 и кладёт артефакт в локальный Maven-каталог, путь к которому экспортируется как `ENOTONE_CI_COMPILER_MIRROR`. [`settings.gradle.kts`](../../settings.gradle.kts#L12) регистрирует этот каталог первым репозиторием с фильтром `content { includeModule("org.jetbrains.kotlin", "kotlin-compiler-embeddable") }`.

Назначение шага — подстраховка от сбоев Maven Central CDN (504), как и у шага установки Gradle (ADR-0076). Фильтр по модулю задан **без версии**, поэтому зеркало участвует в разрешении любой запрошенной версии компилятора.

Проблема, зафиксированная как F-03: шаг предзагружал `2.3.10`, а проект собирается Kotlin 2.4.21 ([`gradle/libs.versions.toml`](../../gradle/libs.versions.toml#L3)). Проверено локально:

```text
gradlew :core:model:dependencies --configuration kotlinCompilerClasspath
-> org.jetbrains.kotlin:kotlin-compiler-embeddable:2.4.21
   org.jetbrains.kotlin:kotlin-build-tools-cri-impl:2.4.21
   org.jetbrains.kotlin:kotlin-compiler-runner:2.4.21
   org.jetbrains.kotlin:kotlin-daemon-embeddable:2.4.21
```

В `debugRuntimeClasspath` `kotlin-compiler-embeddable` не встречается вовсе — шаг влияет только на разрешение компилятора.

**Следствие.** Зеркало консультируется, но всегда промахивается: в нём лежит версия, которую сборка не запрашивает. Шаг при этом не падает — он проверяет лишь наличие и хеш скачанного файла, — поэтому дефект был молчаливым: цена шага (обращения к трём зеркалам с таймаутами, 40 строк YAML) платилась, а защита не работала.

**Корневая причина** — не «устаревшая константа», а дублирование версии. Одна и та же версия задавалась в двух независимых местах (`libs.versions.toml` и `ci.yml`) и уже разошлась. Правка литерала на 2.4.21 устранила бы симптом и оставила механизм расхождения: следующее обновление Kotlin повторило бы F-03.

## Решение — варианты

1. **Версия читается из каталога версий, хеш — из таблицы пинов в шаге (выбрано).** Шаг извлекает `kotlin` из `gradle/libs.versions.toml`, затем берёт SHA-256 из `case`-блока «версия → хеш». Если пина для версии нет — шаг падает с `::error::` **до** скачивания. Плюсы: дрейф версии становится невозможным по построению, а не по дисциплине; смысл подстраховки от CDN 504 сохраняется; обновление Kotlin превращается в две строки в одном коммите (версия в каталоге + пин), причём забытый пин обнаруживается сразу и громко. Минусы: хеш остаётся ручным — Maven Central не публикует `.jar.sha256` для этого артефакта (проверено: HTTP 404), автоматически его взять неоткуда.
2. **Обновить литерал 2.3.10 → 2.4.21 и хеш, ничего не меняя в способе получения версии.** Плюс: минимальный diff. Минус: оставляет дублирование версии — механизм, породивший F-03. Отклонено: устраняет симптом, а не причину.
3. **Удалить шаг и блок `ENOTONE_CI_COMPILER_MIRROR` из `settings.gradle.kts` как мёртвую конфигурацию.** Плюс: минус 40 строк YAML и блок настроек, ноль ручных пинов. Минус: теряется подстраховка от 504 — та самая, ради которой шаг появился; при сбое CDN резолв компилятора падает вместо переключения на зеркало. Отклонено владельцем: риск сбоя CI дороже стоимости поддержки пина.
4. **Оставить как есть, записав дефект в `docs/KNOWN_ISSUES.md`.** Плюс: ноль изменений. Минус: сохраняет шаг, который не выполняет свою функцию, но выглядит работающим — то есть маскирует отсутствие защиты. Отклонено.

## Границы решения

- Версия Kotlin в проекте не меняется — правится только способ её получения внутри шага CI. `gradle/libs.versions.toml` читается, но не изменяется.
- Продукционный код, зависимости, схемы Room и миграции не затрагиваются.
- Список зеркал (`huaweicloud`, `talend`, `repo.maven.apache.org`) и порядок их перебора не меняются.
- `ENOTONE_CI_COMPILER_MIRROR` и фильтр `includeModule` в `settings.gradle.kts` остаются без изменений: меняется только то, какой артефакт туда попадает.

## Последствия

- Зеркало впервые начинает обслуживать тот компилятор, который запрашивает сборка: версия совпадает с каталогом по построению.
- Забытый пин при обновлении Kotlin — это красный CI с внятным сообщением `No SHA-256 pin for kotlin-compiler-embeddable <версия> (ADR-0098)`, а не молчаливая подмена артефакта.
- Неверный хеш по-прежнему обнаруживается самим шагом через `sha256sum --check --status`; перебор зеркал при несовпадении продолжается, как и раньше.
- Контракт закреплён тестом `tools/test_ci_compiler_mirror_contract.py`: отсутствие литерала версии, наличие пина для текущей версии из каталога, формат хешей, обязательный отказ для неизвестной версии, совпадение пина с хешем локального артефакта (когда он есть в кэше Gradle).
- Когда появится способ получать хеш из источника (публикация `.sha256` или `verification-metadata.xml` в зависимостях), таблицу пинов можно заменить автоматическим получением — это отдельное решение, не требующее пересмотра границ.

## Проверка

- Пин для 2.4.21 вычислен двумя независимыми путями: из кэша Gradle и из свежей загрузки с Maven Central — `ef19419c765e7ac8404465fa026ca8fc4dbb8a822de0fc79aa53c8dce29f1d02`, значения совпали.
- Методика подтверждена обратным тестом: тот же способ для 2.3.10 даёт ровно `ac6a182785345380b5db5085dbeea3f5f0e925e2e100e54ab059b5787d4f6e40` — значение, уже зафиксированное в `ci.yml` из `verification-metadata.xml` JetBrains.
- Разбор версии из каталога проверен в bash: `awk -F'"' '/^kotlin[[:space:]]*=/ { print $2; exit }'` → `2.4.21`.
- Мутационная проверка контракта: те же инварианты, применённые к исходному `ci.yml` из `main` `c930c94e`, падают по всем трём пунктам (нет чтения каталога, есть литерал `2.3.10`, для текущей версии нет пина). То есть тест ловит именно F-03, а не описывает новое состояние.
- Доступность артефакта 2.4.21 в зеркалах: Maven Central и talend отдают POM (HTTP 200), `mirrors.huaweicloud.com` с машины разработки недоступен (код 000) — работоспособность этого зеркала проверяется только на раннере GitHub и остаётся риском доступности, но не логики шага.
