# ADR-0045 — Album Artist первичен для альбомов и вкладки «Исполнители»
Дата: 2026-11-09. Статус Draft до exact-HEAD CI и Huawei smoke.

## Контекст
В пользовательской плоской медиатеке /AllMusic основная принадлежность альбома определяется тегом **Исполнитель альбома** (*Album Artist*) и отличается от персоны, исполняющей конкретную композицию (*Artist*). Треки сборников и дуэтов могут иметь разных Artist при одном Album Artist.

## Решение
1. Не терять исходные теги: `artist` и `albumArtist` — независимые поля в `AudioTagFields`, `RemoteTrackEntity`, `OfflineTrackRow`. Существующий Room schema не менять.
2. MP3 ID3v2.3/v2.4: `TPE2` → albumArtist, `TPE1` → artist (уже реализовано). ID3v1 не имеет TPE2: albumArtist остаётся пустым, без выдуманного значения.
3. FLAC Vorbis: `ALBUMARTIST` → albumArtist (уже реализовано). Поддержать распространённые ключи `ALBUM ARTIST` и `ALBUM_ARTIST`, нормализовать только имя поля; содержание значения не терять. `ARTIST` остаётся независимым.
4. Вкладка альбомов уже группирует по паре (album, albumArtist ?: artist). Вкладка исполнителей должна использовать `albumArtist ?: artist`, в первую очередь общий артист альбома. Для треков без albumArtist действуют прежние Artist-группы. Поле обычного artist сохраняется для трека и локального поиска, даже если в Artist-навигации первичен albumArtist.
5. Ранее проиндексированные значения сохраняются; изменение логики группировки вступает в силу при повторном открытии медиатеки из Room без GET. Новые алиасы FLAC применятся к будущим сканам; автоматически переиндексировать сохранённые записи нельзя.

Никаких изменений веб-протокола, Media3, Keystore, сетевых квот, схемы Room и палитры. Утверждение о широком покрытии требует отдельного теста по реальным файлам, особенно если файлы используют другие стандарты/ID3v1.
