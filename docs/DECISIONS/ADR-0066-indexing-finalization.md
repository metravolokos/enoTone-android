# ADR-0066 — завершение тегов, инкрементальной индексации и переиндексации

Дата: 2026-11-11. Статус: implementation PR — ожидает exact-HEAD CI и Huawei smoke.

## Согласованная функциональная модель

**Импортировать / обновить медиатеку** — одна основная команда в Настройках:
PROPFIND Depth:1 каталога /AllMusic → атомарный Room snapshot →
автоматический запуск существующего фонового индексатора только для
новых, изменённых, ранее не прочитанных и retryable MP3/FLAC.
Не добавляем отдельной обязательной «индексации тегов». Метаданные
получаются из аудиофайла, поэтому технически после листинга есть
внутренний ограниченный сетевой этап. Уже проиндексированные
неизменённые файлы не загружаются повторно.

**Принудительная переиндексация** — отдельная редкая операция,
доступная в Настройках только с подтверждением. Она ставит в
существующую Room-очередь все доступные MP3/FLAC текущего аккаунта,
не удаляя старые теги, сбрасывает их ссылки в ленивом artwork-кэше
и запускает тот же foreground-indexer. Новые/изменённые файлы
обрабатываются обычным обновлением: для них эта команда не нужна.

**Переиндексация альбома или исполнителя** — общая внутренняя
LibraryReindexCoordinator готовит очередь по *стабильным ID* из
сохранённой локальной библиотеки:
- Album: полная групповая идентичность по ALBUM и Album Artist
  (с fallback на ARTIST только для группирования альбомов), включая
  виртуальный «Неизвестный альбом».
- Artist: только поле ARTIST, не ALBUM ARTIST.
- Album Artist: только ALBUM ARTIST, не ARTIST.

Сейчас **контекстные меню не добавляем**. Их расположение
(три точки или долгое нажатие) будет утверждено при завершении
интерфейса вместе с управлением альбомами и исполнителями.
Ранее добавленная ручная диагностика альбома по 10 файлов остаётся
временным тестовым механизмом, не объявляется финальным UX.
Backend позволяет потом подключить кнопки без нового парсера/Room-схемы.
Группы подготавливают очередь локально, не стартуют WebDAV сами;
интеграция меню позже должна вызвать artwork invalidation для
возвращённых sources и существующий background indexer.

## Теги

Один bounded MP3 ID3v2.3/2.4, ID3v1 или FLAC Vorbis проход читает
TITLE, ARTIST, ALBUM, ALBUM ARTIST, DATE/YEAR, TRACKNUMBER,
DISCNUMBER и GENRE. Не добавляем отдельный HTTP-проход для жанра,
года или обложек; embedded APIC/PICTURE остаются отложенными.
Неизвестные поля остаются пустыми: никаких выдуманных альбомов/
исполнителей в базе. Пользовательский «Неизвестный альбом» —
виртуальное представление реальных неполных тегов.

Постоянная схема — Room v4, миграции 1→2→3→4 сохраняются;
парсер обновляет поля только при успешном результате и корректном
CAS на текущую версию файла. Ошибки/отмена/повторное чтение не
стирают ранее известные теги.

## Дополнительный исправленный случай инкрементального импорта

Некоторые WebDAV-серверы могут ошибочно возвращать тот же ETag
после изменения размера или времени модификации файла.
Раньше равенство ETag автоматически означало «не изменён».
Теперь изменение любого *сопоставимого* size/mtime принудительно
переоткрывает metadata checkpoint. Если ETag отсутствует,
для идентичности по-прежнему требуются и одинаковый size, и mtime.
Контент с теми же ETag/size/mtime автоматически распознать как
изменённый невозможно: для этого остаётся **ручная переиндексация**.

## Безопасность и лимиты

- /AllMusic плоский; PROPFIND Depth:1, без вложенных папок.
- Групповая переиндексация выбирает только присутствующие MP3/FLAC
  нужного sourceKey, без файлов другого аккаунта. SQLite update
  разбит на партии по **400 ID** под лимит bind-параметров.
  Для всей библиотеки — один SQL UPDATE в транзакции.
- Старая музыка и теги остаются в Room при остановке, сетевых
  сбоях и обновлении приложения. Сохранённый прогресс используется
  при следующем явно запущенном сеансе.
- Foreground dataSync поддерживает Pause/Stop, 4 readers,
  фиксированные сетевые бюджеты, тайм-аут и работу по мобильной сети;
  нет Wi-Fi-only, автозапуска после reboot и фоновых скрытых проверок.
- Секреты остаются только в оперативной памяти/Keystore по
  явному согласию; не передаются в Intent или логи.
- Artwork-кэш v2 сохраняет одну мастер-картинку до 1320 px и
  лениво получает её при показе. Не сканировать все 3590 обложек
  во время импорта или переиндексации тегов.

## Что не заявляется завершённым

- Пользовательские контекстные меню альбомов/исполнителей,
  фильтры жанров, FTS и художественный дизайн — другие этапы.
- Непроверенные форматы (например, OGG/Opus) не добавляем без
  тестовой медиатеки; MP3/FLAC уже проверены на Huawei.
- Нельзя гарантировать автоматическое обнаружение правки тегов
  при полностью неизменных серверных ETag, size и mtime.
- Принудительную полную переиндексацию **не запускать ради
  простой проверки интерфейса**: это потенциально тысячи GET.

## Приёмка

1. Exact-HEAD GitHub CI: Android, JUnit, Lint, Python, Mock WebDAV,
   Room v1–v4, без GMS. Проверить unit-тесты для неверного ETag,
   групповых областей и 3590 ID.
2. После merge только постоянная подписанная Stable Preview из
   main, install-over-install без удаления приложения.
3. На Huawei проверить простой **обычный** импорт/обновление без
   новой массовой переиндексации: неизменённые 3590 записи
   сохраняются, сохраняются настройки/пароль, музыка играет.
4. Ручную полную переиндексацию не запускать автоматически и не
   запускать для smoke по умолчанию. При отдельном желании владельца
   после подтверждения: пауза/продолжение/остановка, корректный
   числовой прогресс и сохранность старых тегов при прерывании.
5. UI-проверка групповых контекстных меню отложена до их создания.
