# ADR-0028 — Ограниченный пилотный индексатор с Room checkpoint

Дата: 2026-11-08 | Статус: Draft, до CI и испытаний на Huawei

## Основание
Реальный Huawei Preview #54 подтвердил быстрый разбор двух отдельных файлов:
- MP3 ID3v2.4: title/artist/album=1/1/1, **3 GET**, **196 608 байт**, запись Room=1;
- FLAC Vorbis: title/artist/album=1/1/1, **1 GET**, **65 536 байт**, запись Room=1.

Это не статистически представительная проверка 3590 файлов. Массовые 3590 вызовов пока запрещены.

## Границы пилота
- Только ручные кнопки **10 или 20 файлов**, последовательная обработка; без фонового воркера и без хранения пароля.
- **За один запуск максимум 60 GET и 4 МиБ**, причём для 10 файлов ещё строже: до 30 GET и 2,5 МиБ. Операция не начинает следующий файл после превышения 180 секунд общего времени; каждый WebDAV Reader дополнительно ограничен прежними 40 с, 6 GET, 384 КиБ, а быстрый парсер — шестью блоками/96 КиБ запрошенных метаданных.
- Каждому Reader выдаётся только **остаток** общего бюджета, поэтому отдельный файл не может вывести весь пилот за ограничения. HTTP 206, Content-Range, ETag, запрет redirect, проверка длины тела и host guards не ослаблены.
- Перед началом выбираются до 10/20 записей MP3 и FLAC из текущего sourceKey. Порядок детерминирован, ранее завершённые или уже имеющие теги записи исключаются; ожидающие retry идут после новых.
- После каждого файла результат записывается одним атомарным SQL UPDATE вместе с nullable тегами и кодом результата; при несовпадении id/source/path/ETag/size/modified/отсутствии файла запись не меняется.
- `NO_EMBEDDED_TAGS`, `UNSUPPORTED_LAYOUT`, `INVALID_METADATA`, `FAST_BUDGET_EXCEEDED` фиксируются как завершённые диагностические исходы; при изменении версии удалённого файла checkpoint сбрасывается. Временные сетевые сбои `RETRY_NETWORK` можно повторить следующим запуском (после новых файлов). При HTTP 401/403 весь пилот прекращается без повторных попыток.
- Остановка пользователя реализована отменой coroutine, результат каждого уже завершённого файла остаётся в Room. Текущий блокирующий GET может закончиться только после установленного тайм-аута.
- Новый Room v2 добавляет **только nullable tagScanCode**, безопасная AutoMigration v1→v2; нет destructive migration/DELETE. Все предыдущие теги сохраняются. Надо проверить реальное открытие БД; инструментального теста миграции пока нет.
- В UI только безличные счётчики: обработано/с тегами/без тегов/ошибки/устаревшие/GET/байты/ожидают и код остановки; никаких имён, тегов, ETag или пароля.

## Приёмка и условия перехода
1. CI на точном HEAD: Android build, JUnit, lint, Room v1 неизменна, Room v2 экспортирован/проверен, GMS gate, APK signing/Preview ID.
2. Huawei: новый Preview (отдельная Room), импорт /AllMusic только как список; запустить **10 файлов**, затем повторить. Число завершённых должно накапливаться, повторно обработанные — 0; возможны retries в конце. Прервать пилот, перезапустить ту же Preview и проверить продолжение.
3. Не включать 20 и тем более весь каталог, пока не оценены 10 файлов по запросам, трафику и охвату MP3/FLAC. Нет утверждения о пропорциональной скорости для коллекции.
4. Перед релизом — instrumentation-тест миграции и конкурентных updates, постоянный закрытый signing key в GitHub Secrets. Репозиторий публичный, ключ не коммитить.

## Известные ограничения
- Unsupported layouts/codecs сейчас диагностируются, но не декодируются. Нельзя выдавать такие файлы за заполненные тегами.
- При network retry checkpoint `RETRY_NETWORK` хранится локально и не имеет автоматического backoff; в ограниченном ручном пилоте новые файлы получают приоритет.
- Версия удалённого файла защищена доступными ETag/size/modified, но без сильного ETag глобальная неизменность удалённого контента не доказана.
