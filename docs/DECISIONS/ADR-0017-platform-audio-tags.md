# ADR-0017: Извлечение аудиотегов через системный MediaMetadataRetriever

Дата: 2026-11-08 | Статус: первый срез, до проверки реального аудиофайла | Автор: ChatGPT

## Контекст
Владелец подтвердил на Huawei наличие 3590 аудиофайлов в плоской /AllMusic и чтение 3590 сохранённых записей из приватной Room без нового WebDAV-запроса. Теперь необходимо получить title, artist, album и albumArtist из содержимого аудиофайлов, а не из несуществующих каталогов.

## Выбор
- Для первого среза используем **системный Android MediaMetadataRetriever** с `setDataSource(MediaDataSource)` (API 23+, minSdk 26). Это не требует Google Play Services и позволяет отделить извлечение тегов от будущего сетевого источника. Документация: https://developer.android.com/reference/android/media/MediaMetadataRetriever
- Альтернатива: сторонняя библиотека тегов с поддержкой FLAC/ID3/Vorbis/MP4. Это увеличит зависимости и потребует отдельной проверки качества/лицензий; пока не выбрана.
- Альтернатива: `MediaMetadataRetriever.setDataSource(url, headers)` с Basic Authorization — отвергнута для первого среза: непрозрачное число сетевых запросов и ограничений трафика, риск нежелательного полного чтения.

## Границы первой реализации
- `AudioTagFields` очищает управляющие символы, нормализует NFC, ограничивает размер одного текстового поля и берёт **только title** из имени файла при отсутствии embedded title.
- Никаких выдуманных artist/album из пути или имени файла.
- `AndroidAudioTagReader` принимает абстрактный `MediaDataSource` и извлекает четыре поля через системную платформу. Не сохраняет и не выводит личные значения, не выполняет сетевых запросов самостоятельно.
- Массовую обработку 3590 треков **не запускать** до реализации и проверки WebDAV range backed `MediaDataSource`, лимитов суммарных байтов/запросов, тайм-аутов, отмены, поддержки форматов и ошибок.
- Отдельный PR должен безопасно реализовать random-access Range с проверкой HTTP 206, `Content-Range`, без redirect/пересылки авторизации на другой хост, с временным RAM-кэшем, без постоянного аудиофайла.
- Ещё одним отдельным шагом тестировать один файл на Huawei и лишь затем добавить запись тегов в Room с проверкой версии удалённого файла.
- Поддержка MP3/FLAC/OGG/OPUS/M4A/AAC/WAV **не доказана** до испытаний конкретных файлов на устройстве.

## Тестирование
JVM unit tests нормализации Unicode, отсутствующих тегов, fallback названия, ограничений текста. Android MediaMetadataRetriever не эмулируется JVM-тестами: нужен отдельный реальный тест. Полный CI: Android сборка, JUnit, lint, строгий GMS-free APK scan, проверка Room schema v1.

Состояние: только примитивы извлечения и unit tests; пока нет WebDAV random access, массовой обработки, обновления Room или UI просмотра медиатеки.
