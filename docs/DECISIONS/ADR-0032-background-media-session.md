# ADR-0032 — MediaSessionService вместо привязки ExoPlayer к экрану

Дата: 2026-11-08. Статус: Draft, до Android CI и Huawei smoke.

## Основание

Владелец подтвердил «Работает» на Huawei Preview #82: первый выбранный трек успешно звучит через защищённый Media3 DataSource без GMS. PR #22 объединён после точной проверки CI #82. Плеер #82 уничтожался при закрытии Compose-экрана, а при сворачивании ставил паузу. Для мобильного enoTone это только проба транспорта, не нормальное воспроизведение музыки.

## Решение

- Перенести ExoPlayer в нативный `MediaSessionService` (Media3) с `MediaSession`, `foregroundServiceType="mediaPlayback"` и штатными разрешениями `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_MEDIA_PLAYBACK`. Media3 автоматически управляет foreground-уведомлением, аудиофокусом и стандартными транспортными командами.
- `android:exported="false"` — не предоставлять сторонним приложениям общий binder к приватному плееру. Для UI использовать bind по явно заданному имени службы и приватному `ACTION_LOCAL_BIND`; все остальные bind-запросы передавать `super.onBind()` для Media3.
- Передавать e-mail, пароль приложения, путь/size/ETag **через вызов локального binder в RAM**, не помещать их в URI, Intent extras, PendingIntent, MediaSession extras, SQLite, логи или публичные отчёты. Воспроизводимый URL остаётся единственно разрешённым `https://webdav.cloud.mail.ru/AllMusic/...`, с отключёнными redirect и строгим `206 / Content-Range` из ADR-0031.
- Открытие экрана только привязывает UI к уже существующей службе. При закрытии экрана UI делает `unbindService`, **не** закрывает ExoPlayer и **не** ставит паузу: Android продолжает воспроизведение, пока играет трек. Media3 контролирует длительность жизни службы/уведомления.
- Текущее MVP всё ещё воспроизводит только один выбранный трек: до M4 очередь/skip/shuffle и до M5 временный кэш не реализованы. Не скрывать это ограничение.

## Контракты и проверка

- Python static contract проверяет manifest, private service, отсутствие секретов в Intent, разъединение UI без автоматического stop/release; CI выполняет Android/Kotlin/JUnit/lint, схемы Room, строгий GMS-free байтовый APK gate, пакет/подпись.
- Huawei следующей отдельной Preview: ввести e-mail и пароль; один раз сохранить список в новой Room; открыть медиатеку, нажать один MP3. После появления звука **свернуть приложение**, проверить непрерывное воспроизведение и управление в системной панели; заблокировать экран и проверить медиа-кнопку паузы/продолжения; вернуться в приложение, нажать «Стоп». Затем возможно один FLAC.
- Только успешный CI на точном HEAD и проверка Huawei дают право объединять PR. Стабильный signing key ещё отсутствует, каждая Preview имеет отдельные ID/Room. Не заливать названия треков, теги и скриншоты с личными уведомлениями в публичный GitHub.

## Отложено

- Background recovery после убийства процесса и сохранение пароля через Android Keystore.
- Умное управление очередью, следующий трек, shuffle/repeat, preload и локальный seek.
- Внешние MediaBrowser-клиенты и Android Auto; сервис закрыт извне намеренно.
