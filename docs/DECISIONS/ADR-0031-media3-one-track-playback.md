# ADR-0031 — первый вертикальный срез Media3 через Cloud.Mail.ru WebDAV

Дата: 2026-11-08. Статус: Draft, ожидает Android CI и ручной проверки Huawei.

## Контекст

Preview #70 показывает 3590 из 3590 треков без сетевого чтения аудио; локальный поиск возвращает ожидаемые результаты. В приложении пока нет воспроизведения, а цель продукта — мобильный плеер. Не нужно заставлять владельца ещё 3560 раз проверять теги для первого звука.

## Решение

- На нажатие одной строки трека получить её `encodedPath` из Room по стабильному id и хешу аккаунта, `missingScans=0`, известный ненулевой `remoteSize`.
- Использовать `androidx.media3:media3-exoplayer` 1.11.1 и официальный `media3-datasource-okhttp`. Media3 создаётся только при реальном нажатии, никакого фонового сканирования.
- Сетевые запросы только к `https://webdav.cloud.mail.ru/AllMusic/<один файл>`. Валидатор проверяет исходный каталог, плоскую структуру, процентное кодирование, отсутствие query/fragment, запрет encoded slash/backslash, совпадение домена и HTTPS. OkHttp отключает **все** redirect (не только межпротокольные).
- HTTP Basic Authorization передаётся через заголовок в DataSource, **не** в URI. Учётные данные уже вводятся владельцем на диагностическом экране и остаются только в RAM. Пароль не попадает в Room, публичные логи/скриншоты/ошибки и GitHub.
- Проигрывание одного трека из списка с кнопками пауза/продолжить/стоп и безопасным числовым кодом Media3-ошибки. AudioAttributes = media/music, audio focus и noisy-audio handling Media3.
- Это **foreground-only** вертикальный срез: при уходе приложения в фон ставить паузу; закрытие экрана освобождает ExoPlayer и соединения. MediaSessionService/уведомление/фоновое воспроизведение и очередь — следующий этап M3/M4. Не выдавать их за реализованные.
- Существующие механизмы PROPFIND/Room/tag-пилота, схемы v1/v2, сетевые бюджеты пилота остаются неизменными; скачивание полного трека и prefetch следующего пока не добавляются.

## Альтернативы

1. Повторно использовать 64-КиБ диагностический `WebDavRangeReader` — не подходит для потокового воспроизведения целого файла: его жёсткие 8 МиБ/128 GET являются защитой метаданных.
2. Android `MediaPlayer` без Media3 — простая проба, но расходится с принятым стеком M3 и будущей MediaSession.
3. `DefaultHttpDataSource` с перенаправлениями — не подходит для приватных заголовков WebDAV; используем OkHttp с `followRedirects(false)`, `followSslRedirects(false)`.
4. Сразу запускать foreground playback service, кэш двух треков, очередь — увеличивает область первой отладки без подтверждения, что Cloud.Mail.ru совместим с Media3 Range.

## Проверка

- JUnit для валидатора origin/path/encoded traversal/query/fragment.
- CI: `:playback:testDebugUnitTest`, Android/JUnit/lint, Room schema, GMS-free dependencies/APK, отдельный Preview APK и проверка подписи на точном HEAD.
- Huawei: новая Preview отдельно от #70, ввести e-mail и пароль приложения, **один раз сохранить список 3590 файлов**, открыть медиатеку, нажать **один известный MP3**, проверить статус/звук, паузу/продолжить/стоп; при ошибке сообщить только номер Media3-кода. Следом можно отдельный FLAC. Не публиковать названия треков или пароль.

## Риски

У Cloud.Mail.ru подтверждён нестандартный формат `Content-Range: bytes=...`; совместимость именно **Media3 playback DataSource** с таким ответом до теста неизвестна. Media3 может не распознать длину при seek, хотя инициальный поток пойдёт. Любой обнаруженный сбой исправлять тестируемым адаптером, не отключать проверку origin/redirect и не запускать массовую загрузку.
