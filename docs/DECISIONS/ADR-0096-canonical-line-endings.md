# ADR-0096 — Канонические окончания строк в репозитории (`.gitattributes`)

**Дата:** 2026-11-17. **Статус:** реализовано в ветке `chore/f02-eol-attributes`, ожидает приёмки владельцем. **Связано:** ADR-0090 (побайтная проверка дизайн-ресурсов), ADR-0076 (Gradle Wrapper и проверки в CI), находка F-02 [аудита 2026-11-17](../audit/AUDIT_2026-11-17_local-state.md).

## Контекст

`design/tools/sync_android.py --check` (ADR-0090, решение 2) сравнивает дизайн-ресурсы **побайтно**: `dst.read_bytes() != src.read_bytes()` плюс сверка SHA-256 с `design/android-resources.sha256`. В репозитории не было `.gitattributes`, а Git for Windows по умолчанию ставит `core.autocrlf=true` — файлы выгружаются в рабочую копию с CRLF, хотя в индексе лежит LF.

Следствие, зафиксированное аудитом 2026-11-17 (`F-02`): на Windows `--check` сообщал о расхождении **32 файлов**, содержимое которых не менялось, — только окончания строк рабочей копии. То есть локальная проверка контракта ADR-0090 на Windows была нерабочей: красный результат на неизменённом коде, при зелёном CI на Linux (там `core.autocrlf` обычно `false`).

Факты, собранные до решения (ветка `chore/f02-eol-attributes`, `main` = `9a0a4b52`):

- 828 отслеживаемых файлов; в индексе LF у **827** (`i/lf`), CRLF — только у `gradlew.bat` (`i/crlf w/crlf`);
- `w/crlf` в рабочей копии — у 661 файла (все текстовые, включая побайтно сверяемые ресурсы дизайна);
- 149 бинарных файлов уже хранятся как `i/-text w/-text`, то есть Git их и так не трогает;
- `design/android-resources.sha256` — 59 записей, столько же пар «источник → приложение» проверяет `--check`.

## Решение — чем убрать расхождение

1. **`.gitattributes` с `* text=auto eol=lf` (выбрано).** Каноническое содержимое в Git — LF, рабочая копия на любой ОС — тоже LF; исключения объявлены явно: `*.bat`/`*.cmd`/`*.ps1` → `eol=crlf`, бинарные форматы → макрос `binary` (`-diff -merge -text`). Плюсы: результат проверки перестаёт зависеть от локальных настроек Git; побайтный контракт ADR-0090 остаётся **строгим и неизменным**; правило версионируется вместе с кодом и одинаково действует у всех агентов и в CI. Минусы: одноразовая перенормировка индекса там, где он расходился с политикой (в нашем случае — единственный файл `gradlew.bat`).
2. **Нормализовать окончания строк внутри `sync_android.py` перед сравнением.** Плюс: не нужно трогать Git-настройки. Минус: это **ослабление** контракта — проверка перестаёт ловить реальные байтовые правки в XML-ресурсах, ради которых она и вводилась; причина расхождения (настройки Git) не устранена, а замаскирована. Отклонено.
3. **Проверять дизайн-ресурсы только в Linux CI, локальные расхождения объявить ожидаемыми.** Плюс: ноль изменений в репозитории. Минус: на Windows нельзя локально проверить ни один PR, затрагивающий дизайн; ошибка обнаруживается только после пуша. Отклонено.

## Решение — где именно проходит граница политики

- Текст по умолчанию — LF (в Git и в рабочей копии). Это относится и к ресурсам дизайна, и к `core/ui/src/main/res`, и к документации.
- `gradlew`, `*.sh` — `text eol=lf` явно, чтобы запуск на Linux/macOS не зависел от `text=auto`.
- `*.bat`, `*.cmd`, `*.ps1` — `text eol=crlf`: это файлы Windows-команд, cmd.exe ожидает CRLF в рабочей копии.
- Бинарные форматы (`*.png`, `*.webp`, `*.ttf`, `*.mp3`, `*.jar`, хранилища ключей и т. д.) — `binary`. Явный список, а не только автоопределение: `text=auto` угадывает тип по содержимому, и файл без байта `0` может быть ошибочно принят за текст.
- `*.sha256` и `SHA256SUMS` — `text eol=lf`: содержимое сверяется как текст (нужны `diff` и `blame`), но байты должны быть стабильны.

## Последствия

- Индекс **не переписывается**: все 828 файлов уже хранились с LF, кроме `gradlew.bat`; `git add --renormalize .` в этой ветке изменил ровно один файл (`gradlew.bat`, CRLF → LF в индексе). Истории не переписываем, сторонние клоны не ломаются.
- После принудительного re-checkout (`git rm -r --cached . && git reset --hard HEAD`) в рабочей копии остаётся единственный CRLF-файл — `gradlew.bat`, и это ожидаемо (`attr/text eol=crlf`).
- `git ls-files --eol` становится полезной проверкой: любое отклонение от политики видно одной командой.
- Разработчикам не нужно менять `core.autocrlf`: политика в репозитории имеет приоритет над локальной настройкой.

## Проверка

- До исправления: `python design/tools/sync_android.py --check` на Windows → ошибка на 32 неизменённых файлах (находка F-02).
- После исправления и re-checkout: `python design/tools/sync_android.py --check` → «дизайн-ресурсы совпадают с design/: 59 файлов», код возврата 0; `python -m unittest discover -s tools -p "test_*.py"` → 78 тестов OK; `gradlew.bat -q --version` → Gradle 8.13 на JVM 17 (обёртка не сломана перенормировкой).
- `git ls-files --eol` → `w/crlf` только у `gradlew.bat`.
- Отрицательная проверка сохраняется: изменение байта в `ic_eno_play.xml` или добавление `ic_eno_test.xml` по-прежнему валят `--check` (проверка не ослаблена — см. отклонённое решение 2).
