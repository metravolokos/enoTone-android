# ADR-0038 — M6-A: измерение переходов и упрощение интерфейса

Дата: 2026-11-09. Статус: Draft, ожидает exact-HEAD CI и Huawei smoke.

## Предыстория

M5-B Preview #127 прошла проверку владельцем («Работает»). PR #28 объединён с зелёным CI #127. Подтверждено: файл, который воспроизводится, продолжает загружаться даже при Pause; после его 100% один следующий предварительно скачивается. Быстрый staged Media3 старт из M5-A остаётся критичным. Никакого доказательства gapless-перехода между аудиосэмплами пока нет.

В прототипе в основном списке медиа появилось много технических строк: синхронная инициализация Media3, Room, READY и количество подготовленных MediaSources. Они помогли устранить 3,3-секундную задержку, но не должны захламлять основной интерфейс.

## Решение

1. **Анонимная метрика перехода на уровне Media3**, в private `PreviewAudioPlayback` внутри `MediaSessionService`:
   - Начало таймера: нажатие «Следующий/Предыдущий» либо событие перехода Media3 (для авто/управления из уведомления и гарнитуры). Это НЕ момент окончания предыдущего PCM сэмпла.
   - Окончание: `Player.STATE_READY` и, отдельно, callback `onIsPlayingChanged(true)`. Время измеряется монотонным `SystemClock.elapsedRealtime()` на главном потоке.
   - Если новый media item уже в READY, считываем состояние непосредственно на `onMediaItemTransition`, потому что следующий READY event может не возникнуть.
   - При начале handoff записываем признак, что именно следующий предварительно загруженный файл был `CachePhase.COMPLETE` **до** сброса предыдущей cache-работы; listener метрики регистрируется перед listener кэша.
   - `PlaybackHandoffTracker` содержит только enum происхождения, фазу и длительности (без media ID, названий, путей, URL, HTTP-заголовков, паролей, журналов или телеметрии). Первая загрузка новой очереди исключается из метрики перехода. При Stop/новой очереди метрика сбрасывается.
   - Измерения показывают время до состояния Media3 READY/isPlaying, но **не** гарантируют отсутствие акустической тишины, настоящий gapless или какую-либо задержку Bluetooth-кодека. Акустическая приёмка — отдельный реальный тест на Huawei.

2. **UI — первая безопасная косметическая итерация без изменения WebDAV/Room/плейлиста**:
   - Штатный режим — **с временным кэшем**, как принято в M5; отключение кэша остаётся только в раскрываемой «Диагностике».
   - Числовые трассы Room/Media3 и прогресс постановки 3590 MediaSources скрыты по умолчанию за `Показать диагностику`; никаких функциональных тестовых запросов на экран не добавлено.
   - Компактно показаны последний handoff с числовыми метриками и флагом предзагрузки, плюс два индикатора current/next cache. Текущий список/поиск/кнопки MediaSession сохранены.
   - Введены темы `Porcelain`/«Фарфор» и `Graphite`/«Графит» из принятого `metravolokos/enotone-design/tokens/colors.json` v1.3. На розовом акценте тёмный текст; используем системную light/dark настройку, без dynamic colors и GMS.
   - **Не** подставляем неутверждённую картинку Бандита и не имитируем Wordmark: актуальные бинарные оригиналы пока не опубликованы в дизайн-репозитории. Шрифты Onest/Unbounded не заменяются случайными файлами/гарнитурами; перенос — отдельный шаг при наличии утверждённых ресурсов.

## Проверки

- JVM `PlaybackHandoffTrackerTest`: первый выбранный файл исключён, кнопка Next, авто, внешний MediaSession, cached флаг, READY/isPlaying, исключения, reset.
- Python contract `test_media_session_contract.py`: порядок listeners, no credentials/track IDs in tracker, скрытые debug controls, M5 cache ON по умолчанию и private service. `test_m6_theme_contract.py`: соответствие токенов дизайн-репозитория, onPrimary темный, отсутствие динамической палитры.
- Exact-HEAD Android/JUnit/lint, Room v1/v2, strict GMS-free dependency+APK, Preview signing/identity, APK artifact+GitHub direct URL.
- Huawei Preview с новым applicationId/Room: разово импортировать **только список** /AllMusic. В светлой/тёмной теме проверить читаемость кнопок и текста; выбрать трек при cache-on, дождаться current+next COMPLETE, нажать Next, прочитать `READY`/`Media3 PLAYING` и флаг «заранее в кэше: да». Проверить автовоспроизведение следующего на коротком треке, затем внешнюю кнопку из собственного уведомления (в Huawei отдельная системная панель сторонние плееры не поддерживает). Не считать физическое gapless доказанным только по метрике.
- Любые имена треков, пути, ETag, личные уведомления и пароль в публичный GitHub не помещать.

## Не затронуто

HTTP Range 206/Content-Range/no redirect/ETag, GMS-free, ограниченный cacheDir, current then one next, 256/512 МиБ лимиты, стадийное восстановление списка из 3590, shuffle/repeat, foreground service, Music semantics. Нет массового GET и повторного PROPFIND из-за UI.
