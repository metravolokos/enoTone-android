Это доказательства реализации для независимого ревью, не заключение ревьюера.
База: `d4b88ebe4a4dd2c095787c6879345077501c7c39`. HEAD и полный вывод
`python3 tools/review_helper.py triggers <BASE> <HEAD>` приводятся в описании Draft PR.
Класс R: изменяется контракт общего состояния навигации; независимые ревью — по WORKFLOW §6,
назначает владелец. Никаких аппаратных PASS этим документом не добавляется.

## T-VM — экран, источник и переключение

| Экран | Источник | Момент переключения |
|---|---|---|
| Активный альбом | LibraryViewModel.state / AppLibraryRouteSnapshots.stateFor | При совпадении derivedRoute используется liveState; при смене маршрута — снимок до готовности |
| Уходящая деталь | Immutable snapshot маршрута | Фиксируется SideEffect только совпадающего маршрута |
| Плеер | PlayerViewModel.state + индекс LibraryViewModel | Теги и назначения — из общего индекса; до готовности запрос назначения ждёт loading=false |
| Home с деталью | Та же LibraryViewModel, без нового экземпляра и вкладки | libraryTarget определяется деталью; нижняя вкладка остаётся Home |
| Диагностика | Разовое чтение Room активного аккаунта + числовой LibraryAlbumAudit | Только по нажатию; числа последнего альбома публикуются после композиции; выход очищает |

## T-CONC — событие и незавершённое действие

| Событие | Незавершённое действие | Результат / проверка |
|---|---|---|
| Запрос назначения на холодном старте | Первое чтение каталога | playerDetail ждёт StateFlow.first; LibraryViewModelTest |
| Повторный тап | Первый запрос назначения | openingDetail разрешает только один запрос; лист закрывает действие один раз |
| Изменение песни или сворачивание плеера | Загрузка каталога | PlayerDetailOpener сверяет текущий ID и открытость перед навигацией; PlayerDetailOpenerTest |
| Выход аккаунта | Ожидание каталога/диагностика | forgetAccount выставляет loading=false; unavailable запрещает переход; job диагностики отменяется |
| Отказ назначения или навигации | Полный плеер открыт | close не вызывается, короткий Toast; unit + настоящий Compose-лист |
| Альбомная очередь одновременно с полной | CAS tag writer | Только UPDATE существующих строк; LibraryReindexAuditTest проверяет размер после каждой записи; это аудит, не доказанное исправление A |
| Смена маршрута при переиндексации | Общее чтение каталога | Существующие filterVersion/cancel и immutable snapshots не менялись; повторяющиеся файлы из наблюдения владельца подтверждены в облачном `/AllMusic`, ошибка гонки приложением не установлена |

## T-PERSIST — окна обрыва

Формат `tab|overlay|scroll|details` не меняется, полей не добавлено. Новое допустимое
состояние — details поверх HOME — теперь читается restore, а не отбрасывается.
До сохранения Compose восстановит прежнюю целую строку, после — новую целую строку;
некорректные detail-элементы по-прежнему отбрасываются. Проверка round-trip и Back —
AppNavigatorTest. Записей Room/файлов музыки/очереди, миграций и очистки данных в PR нет.
Самоисцеление A пока не реализовано и не может быть заявлено как PASS.
