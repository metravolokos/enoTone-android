# Спецификация продукта enoTone Android — перенесённые требования

Основа: приложенное владельцем ТЗ «PROMPT_AllMusic_Player.md» от 2026-11-08. Название приложения и новый репозиторий переопределяют историческое «AllMusic»: **enoTone** в `metravolokos/enoTone-android`; `/AllMusic` остаётся удалённой папкой.

## Обязательные ограничения
1. Полная автономность от GMS/Play Services/Firebase; Gradle dependency и APK scan.
2. Только HTTPS; нулевая телеметрия; сеть только к WebDAV и по явному согласию — к ИИ.
3. Пароль приложения и ключи: Android Keystore AES-GCM, никаких логов/бэкапов. M0 — без постоянного хранения.
4. Минимум Android 26; targetSdk современный, с подтверждением по официальной документации.
5. Русская/английская локализация; интерфейс для портретного экрана 1320×2856, адаптивность позже.
6. Сначала тесты и работающие вертикальные срезы; не имитировать готовые возможности.

## Подтверждённая структура библиотеки владельца (2026-11-08)

Удалённая папка `/AllMusic` **плоская**: музыкальные файлы находятся непосредственно в ней; **вложенных папок нет**. Для основной библиотеки enoTone M1 выполнить **один** `PROPFIND /AllMusic` с `Depth: 1`, разобрать список файлов и завершить перечисление: **не выполнять рекурсию и не запрашивать `Depth: infinity`**. На неожиданные подпапки реагировать диагностическим сообщением и пропускать их, не переходя внутрь, пока владелец не изменит требование.

Альбомы/артисты/диски — **виртуальная группировка по аудиотегам**, не по каталогам. При отсутствии тегов title брать из имени файла; artist/album не выводить из несуществующих частей пути (допустимо «Неизвестный исполнитель/альбом»). Обложки — прежде всего встроенные в теги; файловые sidecar-обложки возможны только при явном безопасном правиле сопоставления, потому что отдельных папок альбомов нет.

Это ограничение для текущего источника `/AllMusic`, а не запрет абстракции `MusicSource` поддерживать другие структуры в будущем.

## Функциональные требования по этапам
M0: ввод учётных данных только в RAM, PROPFIND root и /AllMusic, статус, проверка Range/ETag/Depth, экспорт без секретов, mock WebDAV, CI APK.
M1: индексировать mp3/flac/ogg/opus/m4a/aac/wav, теги, альбомы, Unicode NFC, Room FTS, incremental scan, progress, WorkManager.
M2: Треки/Альбомы/Артисты, поиск, обложки 192/512/1320, LRU.
M3: Media3 ExoPlayer, WebDAV Range, MediaSession, foreground service, Bluetooth и гарнитуры, seek, отсутствие задержек при тёплом кэше.
M4: контекстная очередь, shuffle Fisher–Yates, repeat off/all/one, порядок, восстановление и ручные изменения.
M5: полностью скачать текущий трек в temp cache даже при pause, потом следующий, seek локально, preload, Wi-Fi policy, LRU.
M6: 10k+ треков, 60 fps, доступность, локализация, релизные APK.

## Будущее
Плейлисты с безопасными устойчивыми ID, UI позже. AI только opt-in и только метаданные с подтверждениями действий. Offline и DocumentsProvider — после MVP.

## Статусы и доказательства
Нет основания утверждать, что Cloud.Mail.ru поддерживает Range/ETag/Depth; все непроверенные свойства сервера помечать «ГИПОТЕЗА — проверить на устройстве». После M0 **ждать подтверждения владельца**, M1 не начинать.

## Уточнение владельца 2026-11-09 — приоритет над перенесённым ТЗ
- В процессе индексации или воспроизведения не нужна привязка к Wi-Fi: никакого Wi-Fi-only ограничения, чекбокса разрешения мобильной сети или блокировки иных подключений. Предыдущие упоминания Wi-Fi policy в разделах M5 являются историческими и переопределены этим решением.
- Индексация должна **продолжаться при свёрнутом приложении и заблокированном экране**; работа только внутри Activity неприемлема.
- M1 использует явно запущенный foreground service типа dataSync с уведомлением вместо WorkManager для первой ограниченной ручной сессии (ADR-0047). Это выбранная архитектурная альтернатива исходному предложению WorkManager с учётом JobScheduler-квот Android 16; не использовать Play Services. Фоновый автозапуск при загрузке телефона не требуется и не включён.
- Сохранность Room и существующего списка обязательна; нельзя заново опрашивать /AllMusic только из-за нового APK.
