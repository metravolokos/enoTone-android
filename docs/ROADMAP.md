## Очередь воспроизведения

Q1 (#192) завершена в PR #199, слита 2026-11-18; предел активной очереди — 100 песен, просмотр и переход по playback-order реализованы по [ADR-0099](DECISIONS/ADR-0099-queue-limit-100.md). Issue #192 закрыта владельцем после общего принятия сборки 1038; это не поимённый Huawei PASS. Q2 (#193) отменена владельцем 2026-11-18: удаление и перестановка песен в очереди не планируются. Скользящая очередь для повышения предела также не планируется. Возвращаться к этим функциям можно только по инициативе владельца и с отдельным дизайном.

## Будущие функции и зависимости

- ~~**TAG-EDIT (#200)**~~ — **отменено владельцем 2026-11-21.** Редактирование
  тегов с записью в облако признано избыточно сложным для плеера и выпадающим из
  концепции простого плеера: запись требует скачивания файла целиком (частичная
  запись в WebDAV нестандартна), временного файла с `MOVE` по `If-Match`,
  библиотеки записи тегов с риском для единственной копии музыки и нового экрана
  редактора. Чтение тегов, индексация и группировка по тегам не затрагиваются;
  WebDAV остаётся только на чтение. Возврат — только по инициативе владельца,
  с отдельной Issue, ADR и дизайном. [Issue #200](https://github.com/metravolokos/enoTone-android/issues/200)
  закрыта как `not planned`.
- **DEPS-01 (#203)** — после завершения #201 и #179 (код #179 слит в #204, Issue ждёт device-test; #202 закрыта после PR #206), тремя отдельными PR: (1) Roborazzi и OkHttp/MockWebServer; (2) Compose BOM; (3) Gradle 9 вместе с AGP 9 и отдельным ADR. Версии брать актуальные на момент каждого шага. Подробности — [Issue #203](https://github.com/metravolokos/enoTone-android/issues/203).

**После M6-0:** единый сетевой слой с абстракцией `MusicSource` (R-4.2, критерий — единая обработка ошибок) и экспериментом gzip/даты коллекции для списка; UI плейлистов и экспорт диагностики; затем ИИ (M8) и офлайн/DocumentsProvider (M9).

История визуальных итераций ADR-0068…0072 и ADR-0073 — заменены актуальным ADR-0084, см. [индекс ADR](DECISIONS/README.md).
