# ROADMAP — enoTone Android

Актуализация: **2026-11-09**. Основной репозиторий — `metravolokos/enoTone-android`, нативный Kotlin/Compose, **не** прежний Flutter PoC.

Источники требований: [первоначальное задание](ORIGINAL_PROMPT_AllMusic_Player.md), [перенесённая спецификация](USER_SPEC_RU.md), [фактические проверки](STATUS.md), [тестирование](TESTING.md). При расхождении между планом и реализацией готовность подтверждают **точный HEAD, зелёный CI и Huawei smoke**, а не слово «готово» в названии этапа.

## Ближайшая последовательность

1. **M6-B принято:** Huawei Preview #157 подтвердил seek, последовательный и shuffle автопереходы, Next после Pause и repeat-one; CI #157 зелёный, [PR #30](https://github.com/metravolokos/enoTone-android/pull/30) объединён. Следующие приоритеты — незавершённые M1/M2/M3/M4/M5.
2. **Вернуться к незавершённым базовым требованиям M1/M2:** поэтапное расширение индексации с бюджетом трафика, форматами и checkpoint, затем виртуальные альбомы/артисты и FTS, потом обложки. Любое увеличение охвата — отдельное измеримое решение; никаких 3590 запросов без контроля.
3. **Закрыть жизненный цикл плеера M3/M4:** сохранение и восстановление очереди/позиции/режимов без хранения credentials в открытом виде, проверка фонового управления и аудиофокуса.
4. **Закрыть M5/M6 до релиза:** Wi-Fi-only/metered и сетевые переключения, поведение seek в полном кэше, accessibility/10k+ тесты, постоянная безопасная подпись из GitHub Secrets, release APK.
5. Только после MVP возвращаться к UI плейлистов, opt-in ИИ и offline/SAF — эти идеи не должны блокировать работающий Android-плеер.

## Постоянные ограничения

- Только HTTPS/WebDAV пользователя, без GMS/Firebase/телеметрии; секреты не попадут в Git, Intent, логи, резервную копию или APK.
- `/AllMusic` **одноуровневая**: один `PROPFIND Depth: 1`, без рекурсивного обхода; альбомы и артисты формируются из тегов.
- Не импортировать тему, палитру или графику из прежних проектов без отдельного согласования; пока **стандартные цвета Material Design**.
- Для каждого изменения: отдельная `feature/` ветка, небольшой PR, тесты и ADR для архитектурных решений, полный CI **точного HEAD** (build/JUnit/lint/Room/GMS/APK), инструкции Huawei. Объединять только безопасные проверенные PR.
- Preview пакеты из разных CI не заменяют прежнее приложение и не разделяют приватную Room. Нельзя удалять старую установку ради обновления; постоянную подпись нужно решить отдельно.

## История ограничений M1

MediaMetadataRetriever на Huawei читал один файл ценой 39–50 GET, поэтому введён быстрый MP3/FLAC metadata-first парсер (ADR-0027) и ручные пилоты 10/20 (ADR-0028). Проверка двух файлов не считалась разрешением обработать 3590: последующие 10+20 checkpoint подтвердили ограниченное продолжение, но не полную совместимость коллекции. Все исторические результаты и открытые проблемы — в [STATUS](STATUS.md), [TESTING](TESTING.md) и [KNOWN_ISSUES](KNOWN_ISSUES.md).

## Приоритет 2026-11-09 — сохранение данных при обновлении Preview
Владелец подтвердил: исторический список 3590 и пилот 30 тегов находились в **других изолированных Preview**; при каждом новом run создаётся отдельный package ID `.preview.rN`, поэтому новая Room пуста. Чтобы больше не повторять импорт, сначала включить отдельный `app.enotone.android.preview` канал, подписанный одним приватным сертификатом через GitHub Secrets (ADR-0042). Он НЕ переносит данные ранее созданных `.preview.rN` и не решает повторный ввод пароля: для этого нужен отдельный Android Keystore этап. После первой установки стабильной Preview список надо импортировать **один раз**, дальнейшие обновления той же подписью сохранят Room; не удалять приложение. PR #33 с альбомами/исполнителями остаётся Draft до завершения этого этапа.

## Сохранение состояния: аппаратная приёмка 2026-11-09
Подписанная Stable Preview #169 успешно установлена поверх #167 на Huawei; база с импортированным списком `/AllMusic` сохранилась без повторного PROPFIND. Функциональность update-in-place подтверждена. Следующий отдельный Draft — добровольное шифрование email/app-password Android Keystore, без нового импорта или изменения плеера. Индексация и FTS ожидают приёмки этого шага.

## Новая аппаратная приёмка и следующий M1 (2026-11-09)
В Stable Preview #177 пользователь подтвердил 10/10 тегов (12 GET, 786432 байта) и работу альбомов, исполнителей и запуска музыки из новых вкладок. M2-A с частичным покрытием принят. Следующий Draft: **только явное**, ограниченное по сети продолжение индексации до 100 кандидатов за одну сессию, не более 60 GET/4 МиБ и около 3 минут; успешные checkpoint переживают стоп/перезапуск. Массивные автоматические запросы по всем 3590 файлам остаются запрещены до отдельной приёмки/планирования.

## Issue #40 — безопасная управляемая индексация
Проектирование началось после успешных #179 (52/52 + 10 раньше, 62/3590) и #181 (Album Artist принят). Первый Draft реализует **до 4** ручных ограниченных 60 GET/4 МиБ порций за одну foreground-сессию (общий потолок 240 GET/16 МиБ), выбор только ранее не завершённых записей, Wi-Fi-only по умолчанию, остановку при уходе Android в фон, кнопки Пауза/Продолжить/Стоп. Результат каждого файла в Room. Это **не** неограниченная или фоновая индексация; расширение лимитов/foreground service требуют отдельной приёмки.

## Изменение требований 2026-11-09: M1 Background (Draft PR)
Владелец уточнил: **не использовать Wi-Fi-only или выбор типа сети**, **индексация при свёрнутом приложении и заблокированном экране обязательна**. Прежний пункт Issue #40 выше — исторический, а не действующая политика. ADR-0047 вводит инициируемый пользователем `dataSync` foreground service с уведомлением и паузой/остановкой, независимый от Activity. Лимиты 4 × (60 GET / 4 МиБ / ~180 с), checkpoint Room после каждого файла, отмена на ошибках и запрет скрытого неограниченного обхода сохранены. Никакого повторного импорта 3590 записей. Статус до зелёного exact-HEAD CI и Huawei smoke — **не принят**. После проверки — планировать следующий этап, расширение до полного индекса и больше форматов.

## M1 — ограниченный параллелизм (ADR-0048, Draft)
После аппаратного теста Stable Preview #194 (23 попытки, 22 успешных, 26 GET, один временный сбой RETRY_BACKOFF) владелец потребовал ускорить чтение ~3506 оставшихся файлов и повторять временно неудавшийся запрос. Новый Draft переключает **только управляемую службу** на четыре параллельных файла со строгим общим атомарным бюджетом 60 GET/4 МиБ на порцию и двумя ограниченными повторами с backoff. Результаты каждого файла сохраняются в существующую Room; Wi-Fi не учитывается, работа в фоне сохраняется. Старые пилотные кнопки остаются последовательными. Общее число порций в сессии ещё 4; автоматическая непрерывная обработка всей медиатеки — последующий аппаратно проверяемый этап. Не считать скорость/реальную устойчивость подтверждённой до Huawei smoke.

## Huawei #205 принят; M1 continuous — следующий Draft (ADR-0049, 2026-11-09)
Подтверждена Stable Preview #205 с serial Room collector + четырьмя concurrent Range readers: **4 порции, 207/207 тегов, 0 ошибок, 240 GET, 15 МиБ, осталось 3274, SESSION_LIMIT**. Ошибка `INDEX_BATCH/STATE` в этой ограниченной сессии не воспроизвелась. Следующий Draft добавляет второй, явно запускаемый пользователем режим **«Индексировать все оставшиеся MP3/FLAC»**, который автоматически продолжает порции без повторных нажатий: до 80 × (60 GET/4 МиБ), общий лимит 4800 GET/320 МиБ/4 ч, умеренная задержка между порциями и ограниченные cooldown при массовых временных сетевых ошибках. Сохраняются 4 HTTP worker и один Room collector; автоматического запуска после перезагрузки нет; тип сети не проверяется. Результат нужно подтвердить точным CI и Huawei smoke. OGG/Opus/M4A/AAC/WAV остаются отдельной задачей расширения парсера.

## Huawei #211: M1 MP3/FLAC покрытие закончено; контроль пропусков и обновления (ADR-0050, Draft)
Проверено владельцем на Huawei после непрерывной фоновой индексации: 42 порции, 2144 попытки, 2143 успеха, 1 временная сетевая ошибка, 2490 GET, осталось 0, `NO_ELIGIBLE_FILES`. Затем офлайн Room: **3590/3590 имеют сохранённые теги**, названия 3590, исполнитель 3590, альбом 3589, Album Artist 3447. Владелец уточнил: в реальной медиатеке только FLAC и несколько MP3, поэтому дополнительные форматы отложить до появления тестовых файлов. Новый приоритет: локально показать единственный файл без альбома, дать выборочную/повторную массовую индексацию и безопасное добавление новых файлов в уже сохранённый список. Draft ADR-0050: запрос первого уровня `/AllMusic` по кнопке, сохранение неизменённых тегов, новые/изменённые файлы индексируются существующей службой; пометка одного/всех на повторное чтение без предварительного удаления тегов. До CI и Huawei smoke не принято.
