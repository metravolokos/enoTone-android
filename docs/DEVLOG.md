## Зачем этот файл

Сессии работы над проектом идут с перерывами. Без журнала каждая новая сессия начинается с восстановления контекста: «почему сделали так», «что уже пробовали», «на чём остановились». Журнал это убирает.

**Правило:** одна запись на значимый эпизод. Числа, ID и ссылки. Без пересказа кода.

### Кодовый аудит (внешний, Kimi k3.1 pro)

Три дефекта высокой серьёзности:

1. **Выход не гарантирует удаление аудиоданных до Keystore** — `stopPlayback()` только ставит очистку в IO-очередь, подавляет ошибки, `SimpleCache` не закрывает.
2. **Первый запуск показывает «Всё готово»** при исчерпании лимита сессии индексации.
3. **Scoped sign-out оставляет legacy-обложки** — `removeAccount()` не трогает `cacheDir/enotone-artwork-v2`.

Плюс: бюджет восстановления очереди из моего PR #253 не работал, а тест давал ложный PASS из-за равенства снимков `StateFlow`.

### Урок из #270/#271

В #270 я заменил Toast на параметр-колбэк со значением по умолчанию `{}`. Продакшн-хост колбэк не передал — пользователь не видел ничего, а R8 вырезал строку из APK.

Тест этого не поймал: harness передавал колбэк руками, то есть проверял контракт, которого в проде не было.

**Исправление на двух уровнях:** колбэк подключён + **убрано значение по умолчанию**. Теперь компилятор требует его от каждого вызова — регрессия стала бы ошибкой сборки.

## 2026-11-23 — диагностика на устройстве

Прогон на Huawei KLE-LX9 (Android 12), сборка `0.6.2-preview.1206` = `a2acdfcd`. Read-only, без root, `run-as` недоступен.

**Привязка к коммиту доказана трижды:** ревизия из `META-INF/version-control-info.textproto` установленного APK, сертификат по pinned SHA-256, номер CI на том же SHA. Метод стоит зафиксировать в `TESTING.md`.

**Подтверждено:**
- REST-05 `force-stop`: отставание позиции 1,8 с (норма ≤ 12), очередь 100, сама не заиграла
- REST-07 перезагрузка: 50,9 → 50,4 с, процесс отсутствовал
- NAV-14 `am kill` в глубине 2+: стек восстановлен
- SRCH-02 счётчик «Найдено 15 песен» работает, хотя автотестом не покрыт

**Найдено:** регрессия #270 (см. выше).

**Вопросы, требующие решения** (заведены как #273, #274):
- служба не отпускает соединение в фоне → состояния из #258 и #268 почти недостижимы
- `OPEN_NOW_PLAYING` без `NEW_TASK` не открывает экран

**Методические ограничения:** `uiautomator dump` ≈2,4 с — короткие состояния не ловятся; `input text` не вводит кириллицу; медиа-кнопки через ADB уходят в чужую сессию.
