## Ошибка обновления APK (Huawei, 2026-11-08)
Владелец сообщил, что APK CI #33 нельзя установить поверх старого: **сертификаты подписей не совпадают**. Корень причины: автоматически генерируемый `~/.android/debug.keystore` на каждом временном CI runner. Старая Room с 3590 файлами **должна быть сохранена**.
Новый Draft PR создаёт отдельное debug-приложение `app.enotone.android.preview.r<run_number>` («enoTone Preview #<run_number>»), сохраняет прежний пакет и изменяет имя артефакта. **До зелёного CI и ручного теста установка Preview не подтверждена.**
Стабильного закрытого ключа подписи пока нет; он потребуется через GitHub Secrets до распространения повторных обновлений Preview. См. ADR-0019. Не предлагать удалять старую версию.

## Тест Huawei Preview #36: теги одного файла (2026-11-08)
Пользователь предоставил обезличенный скриншот с результатом **«Не удалось прочитать теги одного файла. Лимит 8 МиБ/128 запросов»**. Конкретный этап не установлен: старый интерфейс скрывал все исключения, это **не подтверждение** достижения лимитов. PR по ADR-0020 добавляет этап ошибки и безопасные HTTP-коды/числа GET/байт, не увеличивает лимиты. Никаких реальных путей/имён/ETag/паролей в Git нет. До зелёного CI и повторного теста на одном файле диагноз неизвестен.

## Huawei Preview #38: точная ошибка Range (2026-11-08)
Владелец сообщил `RANGE / BAD_CONTENT_RANGE / HTTP 206 / 1 GET / 0 байт`. Ошибка до чтения тела, **не** предел 8 МиБ и **не** установленная ошибка формата аудио. В PR ADR-0021 добавлены безопасные тип и числовые границы несовпадения Content-Range; без вывода сырого HTTP-заголовка и без смягчения проверок. Требуются зелёный CI нового HEAD и повторный тест одного файла в изолированном Preview.

## Huawei Preview #40: Content-Range FORMAT (2026-11-08)
Пользователь сообщил `HTTP 206 / BAD_CONTENT_RANGE / FORMAT / 1 GET / 0 байт`, ожидалось `0-65535/10944026`. Это **не** доказательство ошибки аудиодекодера. Фактическая строка Content-Range не известна.
Новый PR ADR-0022 поддерживает RFC-совместимое `bytes x-y/*`, ранее ошибочно отвергавшееся парсером. Проверка точного диапазона, байтов и лимитов остаётся обязательной. Это проверяемая гипотеза, а не утверждение о поведении Cloud.Mail.ru.

## Huawei Preview #42 — причина синтаксической ошибки Range
Получен обезличенный отчёт `BAD_CONTENT_RANGE/FORMAT_EQUALS_SEPARATOR`, HTTP 206, один запрос, ноль байт. Классификатор подтвердил префикс `bytes=` у заголовка `Content-Range`, но не остальную строку. Создан PR совместимости (ADR-0023), принимающий ровно формы `bytes start-end/total` и `bytes=start-end/total` с прежней проверкой границ, тела и лимитов. До CI и Huawei **не считать поддержку подтверждённой**.

## Huawei Preview #45 — подтверждено успешное чтение тегов (2026-11-08)
Ручная проверка: **один** файл, title=1, artist=1, album=1; HTTP Range GET=50, скачано **3 276 800 байт (3,125 МиБ)**. Ошибок Range/MediaMetadataRetriever нет. Это подтверждает совместимость веб-диапазонов Cloud.Mail.ru и системного извлечения тегов для одного тестового файла.

## Huawei Preview #47 — запись тегов подтверждена на устройстве
Владелец получил: title=1, artist=0, album=0, `Сохранено в Room: 1`, **39 HTTP Range GET / 2 490 368 байт (2,375 МиБ)**. Это подтверждает успешный SQL UPDATE одной записи. Извлечение title могло использовать fallback из имени файла; отсутствие artist/album в другом тестовом треке не доказывает ошибку декодера. ## Новый Draft: ограниченный LRU Range (ADR-0026)
Заменён одно-блочный RAM кэш 64 КиБ на 4 блока максимум 256 КиБ, только для чтения одного файла; сохранены прежние лимиты, заголовки, бюджет и запрет массового обхода. Добавлены счётчики возвратов в RAM и вытеснений. **Уменьшение GET на Huawei не проверено**: при чисто последовательном чтении выигрыша может не быть. Требуется зелёный CI и осторожный однофайловый тест.
