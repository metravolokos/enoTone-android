# Playback queue — текущий контракт и незакрытые требования

Актуально на 2026-11-09; основа — исходное ТЗ, M4-A/B/C и M5-A/B из [STATUS](STATUS.md).

## Принято на Huawei
- Media3 ExoPlayer хранит контекстную очередь выбранного списка/результатов локального поиска (в тестовой библиотеке до 3590 позиций).
- Штатные Previous/Next, автопереход, shuffle и repeat off/all/one проверены пользователем. Очередь добавляется в Media3 поэтапно (staged), чтобы не блокировать первый звук формированием тысяч MediaSources.
- Докачка current продолжается на Pause; после COMPLETE начинается предзагрузка **ровно одного фактического следующего** элемента с учётом текущих shuffle/repeat. Это временный, а не постоянный offline-кэш.
- На Huawei работает собственное уведомление enoTone; отдельная медиа-панель этой версии Huawei для сторонних плееров не работает по сообщению владельца.

## Не утверждать готовность
- Shuffle сейчас реализован штатными средствами Media3, а не отдельным сохранённым порядком Fisher–Yates из первоначального ТЗ. Проверка и сохранение конкретной перестановки между запусками ещё открыты.
- Очередь, позиция, repeat/shuffle после уничтожения процесса не восстанавливаются. Ручное изменение порядка очереди и контексты альбома/артиста также не закрыты.
- Seek внутри трека принят в main (PR #30, Huawei #157, зелёный CI #157). Подтверждены автоматические переходы по очереди и shuffle, ручной Next после Pause, repeat-one. Zero-GET/gapless отдельно не доказаны.
- Отсутствие сетевого запроса при seek в 100% кэше и бесшовность смены треков на PCM уровне не доказаны замерами.

Дальнейшая реализация — отдельные небольшие PR с exact-HEAD CI и Huawei smoke; см. [ROADMAP](ROADMAP.md).
