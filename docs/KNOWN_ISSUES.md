# Известные ограничения M1

- В приватной Room подтверждены 3590 аудиофайлов. Их теги пока не импортированы.
- Новый Range-клиент — **только для одного диагностического файла**, с лимитами 8 МиБ/128 запросов; поддержка конкретных форматов системой пока не проверена.
- На случай смены файла во время чтения используется If-Range с сильным ETag; при слабом ETag или его отсутствии эта гарантия ограничена.
- Временный лимит XML WebDAV 16 МиБ остаётся. Нет массового чтения тегов, FTS, UI альбомов/артистов и playback.
- Нельзя публиковать реальные значения тегов, пути, ETag, email и пароль. Android backup отключён.
- Лицензия исходников и Gradle Wrapper открыты.

- Debug APK из независимых GitHub Actions runs имеют **разные сертификаты**: установка поверх `app.enotone.android` может завершиться ошибкой подписи. Старая Room должна сохраняться; новый отдельный `.preview.r<номер CI>` пакет не содержит старую базу.
- Каждая новая CI Preview до настройки signing key имеет собственный applicationId, поэтому не обновляет предыдущий Preview и начинает с пустой Room. Для стабильных обновлений требуется защищённый ключ в GitHub Secrets; открытый debug.keystore запрещён.

- Huawei Preview #36 не прочитал теги одного файла; общая ошибка не раскрывает причину. Добавляется безопасная диагностика Range/экстрактора (ADR-0020). Массовое извлечение заблокировано до теста одного файла.

- На Huawei Preview #38 первый Range-запрос получил HTTP 206, но проверка Content-Range не прошла (0 прочитанных байт). Причина отличия границ пока неизвестна; ADR-0021 добавляет безопасную числовую диагностику. Не ослаблять Content-Range до выяснения отличий.

- Huawei Preview #40: Cloud.Mail.ru вернул HTTP 206, но заголовок не совпал с узкой числовой грамматикой `Content-Range` (`FORMAT`). Поддержка RFC 9110 неизвестного размера `/*` добавлена как гипотеза; реальная форма заголовка неизвестна. Без подтверждения на устройстве массовую загрузку не начинать.

- Huawei Preview #42 диагностировал `FORMAT_EQUALS_SEPARATOR` у `Content-Range` (HTTP 206, 0 байт). Поддержка точной формы с `bytes=` добавлена в PR (ADR-0023) с неизменными числовыми/байтовыми проверками, но реальный успешный тест на Huawei ещё не пройден.

- На Huawei Preview #45 успешно прочитаны теги одного файла, но цена составила 50 GET / 3,125 МиБ. Массовое чтение требует оптимизации и тестов на нескольких форматах.
- Новый one-track SQL UPDATE в Room защищён версией записи, но ещё не проверен инструментальными тестами на устройстве. Если у сервера нет сильного ETag, полная неизменность файла во время чтения не доказана.

- Huawei Preview #47 подтвердил `Сохранено в Room: 1`, но отдельное чтение тегов после перезапуска ещё не проверялось. Новый Draft по ADR-0025 добавляет офлайн-агрегаты.
- title=1 может означать запасное название из имени файла, а не обязательно реальный встроенный title; отсутствие artist/album у выбранного трека не является доказанной неисправностью.
- Временные Preview разных CI runs имеют разные applicationId и базы: нельзя проверить сохранность между разными Preview, нужно использовать одну установку.

- LRU до 256 КиБ может уменьшить повторные GET при скачках MediaMetadataRetriever назад, но не ускоряет чисто последовательный доступ; доказательства улучшения именно на Huawei пока нет.
- Постоянный signing key всё ещё отсутствует: каждый Preview run имеет собственный applicationId и отдельную Room. Это важно для сопоставимых тестов.

- Быстрый парсер первого среза поддерживает только частые разметки ID3v2.3/v2.4/ID3v1 и native FLAC Vorbis Comments. Несовместимые ID3 unsync/extended/compressed, OGG/Opus/M4A, а также большие комментарии возвращают `UNSUPPORTED_*` или `FAST_BUDGET_EXCEEDED`; **без** автоматического дорогостоящего fallback. Не считать название из имени файла встроенным тегом.
- Экономия HTTP на реальной медиатеке пока не измерена; целевые 1–3 GET — гипотеза для типичных файлов, не гарантия. Не запускать массовый обход до измерений.
