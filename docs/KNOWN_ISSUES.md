## Воспроизведение

| Проблема | Последствие | План |
|---|---|---|
| Первая очередь после запуска службы может играть без временного кэша: он готовится в фоне и подхватывается для следующей очереди (ADR-0094) | Первый трек после перезапуска службы загружается по сети, предзагрузка следующего начинается со второй очереди | Пересмотреть после замера, если станет заметно: греть кэш при входе в приложение, не в `playQueue` |
| Размер и ETag фиксируются при создании очереди, ответ 416 не обрабатывается | Изменённый на сервере файл не играет до пересоздания очереди | Требует ADR сетевого слоя |
| У песен первого импорта нет `firstSeenEpochMs` | Они не попадают в «Недавно добавленные»; заполнение по `remoteModified` не принято владельцем | Решение по ретро-заполнению — [Issue #201](https://github.com/metravolokos/enoTone-android/issues/201) |
| Смена Wi-Fi↔LTE во время трека даёт ошибку; системный сигнал сети есть (ADR-0102), но плеер его не использует | Ручной повтор после переключения сети | Отдельная задача |
| Временный аудиокэш удаляется при старте службы; нет закрепления current/next, только LRU 512 МиБ | Повторный трафик после перезапуска | Позже, отдельный ADR |
| `EnoTonePlaybackService` `exported="false"`, нет `MediaLibraryService` | Внешние MediaController / Android Auto могут не подключиться (не проверено) | Позже |
| Bluetooth MediaSession после смерти процесса не умеет onPlaybackResumption | Автоматическое возобновление гарнитурой без открытия приложения недоступно | Отдельный PR |

| Гонка отмены prefetch в `TransientMediaCache.prefetchNext` | Загрузка стартует после смены трека или Stop | [#255](https://github.com/metravolokos/enoTone-android/issues/255) |

## Данные и приватность

| Проблема | Последствие | План |
|---|---|---|
| При удалении мастеров обложек нечитаемый `ref-*.txt` молча считается отсутствующим | Мастер, на который ссылается другой аккаунт, может быть удалён как «сирота» — тихая потеря данных при нескольких аккаунтах | Отдельный PR; при одиночном аккаунте не проявляется ([AccountArtworkFileCleanup.kt:27-43](app/src/main/java/app/enotone/android/AccountArtworkFileCleanup.kt#L27-L43)) |

| Выход не гарантирует удаление аудиоданных до очистки Keystore: `stopPlayback()` только ставит очистку в IO-очередь, ошибки подавляются, открытый `SimpleCache` не закрывается | Keystore удаляется, пока файлы могут лежать на диске — нарушен fail-closed порядок ADR-0080 | [#256](https://github.com/metravolokos/enoTone-android/issues/256), класс R |
| Scoped sign-out при наличии другого аккаунта чистит только постоянное хранилище обложек; legacy `cacheDir/enotone-artwork-v2` остаётся и восстанавливается после повторного входа | Старая обложка возвращается после «Выйти» → «Войти» | [#256](https://github.com/metravolokos/enoTone-android/issues/256), класс R |
| `QueueStateFileStore.clear()` игнорирует результат каждого `delete()` | Тихий сбой удаления не останавливает выход | [#256](https://github.com/metravolokos/enoTone-android/issues/256) |
## Данные и сеть

| Проблема | Последствие | План |
|---|---|---|
| ID трека = SHA-256(source + encodedPath) без канонизации кодирования; переименование = новый трек | Смена имени не переносит элемент плейлиста на новый ID | Ограничение ADR-0085 |
| Отказ от FTS4 (#143, ADR-0091): индекс удалён, Room v7, поиск по готовым ключам | Нет отдельного замера задержки поиска ≤20 мс | По [ADR-0104](DECISIONS/ADR-0104-auto-acceptance.md) приёмка не требует замера; при появлении жалобы — отдельная Issue |
| Три HTTP-стека (Ktor CIO, HttpURLConnection, HttpsURLConnection), нет общего backoff с джиттером | Дублирование логики; системный прокси/VPN для Ktor CIO не проверен | Отдельный ADR о едином HTTP-стеке |
| Теги только MP3/FLAC; ID3v2.3 tag-level unsync осознанно отвергается, MPEG-2/2.5 и гибридный unsync не имеют отдельных фикстур (#182) | Другие форматы и редкие MP3/ID3-кейсы поддерживаются не полностью | Отдельное решение и тесты по [#182](https://github.com/metravolokos/enoTone-android/issues/182) |

## Не реализовано из ТЗ (не дефекты, а объём)

Экспорт диагностического отчёта и кольцевой буфер логов; `ACTION_VIEW/SEND`; SAF-источник; настройки и интерфейсы ИИ; UI плейлистов; ландшафт/планшеты (ориентация зафиксирована portrait).

Удаление и перестановка очереди по Q2 (#193) отменены владельцем; возвращение возможно только по его инициативе и с дизайном. Редактирование тегов с записью в облако (TAG-EDIT, #200) **отменено владельцем 2026-11-21** — не отложено: функционал избыточно сложен для плеера. Чтение тегов, индексация и группировка по тегам действуют.

## Ограничения, принятые владельцем

Плоская `/AllMusic` без рекурсии; нет Wi-Fi-only; обложки — постоянное хранилище без автоматической очистки. D3.4 / R-3 и R-5 заменены решением D3.5 (#168, ADR-0095): predictive-подложка и перелёт shared-обложки не требуются. Не являются дефектами.
