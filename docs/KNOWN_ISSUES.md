## Закрытая запись #188 — переход из восстановленного плеера

A: владелец проверил облачную папку `/AllMusic` и подтвердил, что повторные файлы есть в
источнике. Для этих треков повторы не считаются дефектом каталога приложения; автоматическое
объединение по тегам не выполняется. Запрошенная диагностика только считает URL-алиасы по
стабильному ключу и не удаляет данные.

B: переход из восстановленного плеера исправлен и слит в PR #189 (`1349657`). Владелец
закрыл #188 2026-11-17 после общего принятия сборки 1019; это не поимённый PASS отдельного
сценария. Повторяющиеся файлы подтверждены владельцем в источнике `/AllMusic` и не являются
дефектом каталога приложения. Наблюдение о следующем prefetch осталось отдельно;
playback/cache не менялись. См. [аудит](tasks/188-audit.md).

## Данные и сеть

| Проблема | Последствие | План |
|---|---|---|
| ID трека = SHA-256(source + encodedPath) без канонизации кодирования; переименование = новый трек | Смена имени не переносит элемент плейлиста на новый ID | Ограничение ADR-0085 |
| Отказ от FTS4 (#143, ADR-0091): индекс удалён, Room v7, поиск по готовым ключам | Общее принятие владельцем 2026-11-17 есть, но нет отдельного отчёта о миграции v6→v7 поверх 677 и замера ≤20 мс | Не отмечать SRCH-05/07 как поимённый PASS без нового отчёта |
| Три HTTP-стека (Ktor CIO, HttpURLConnection, HttpsURLConnection), нет общего backoff с джиттером | Дублирование логики; системный прокси/VPN для Ktor CIO не проверен | Отдельный ADR о едином HTTP-стеке после M6-0 |
| Корневой путь жёстко `/AllMusic` | Нельзя выбрать другую папку | Позже |
| Теги только MP3/FLAC; ID3v2.3 tag-level unsync осознанно отвергается, MPEG-2/2.5 и гибридный unsync не имеют отдельных фикстур (#182) | Другие форматы и редкие MP3/ID3-кейсы поддерживаются не полностью | Отдельное решение и тесты по [#182](https://github.com/metravolokos/enoTone-android/issues/182), без изменения текущего сетевого бюджета |
