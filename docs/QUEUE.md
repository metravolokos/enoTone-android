## Как читать

Очередь идёт **волнами**. Внутри волны задачи независимы по файлам и могут выполняться параллельно; между волнами — строгий порядок.

| Метка | Значение |
|---|---|
| **P0** | Блокирует пользователя: видимый дефект, невозможность работать |
| **P1** | Требует решения до следующего этапа |
| **P2** | Важно, но не блокирует |
| **P3** | Можно отложить без последствий для продукта |
| **device** | Найдено диагностикой на устройстве, требует решения владельца |
| **R** | Класс риска R: два независимых ревью, fault-injection тесты |

## Правила порядка

1. **Волна не начинается, пока не закрыта предыдущая** — кроме задач, ждущих решения владельца: они не блокируют.
2. **Внутри волны** приоритет по метке `P`, затем по номеру Issue (старые первыми).
3. **Класс R** (метка на Issue) требует двух независимых ревью и тестов с эмуляцией падения процесса.
4. **Задача без метки приоритета** считается `P3` до первого разбора.
5. **Новая находка** получает номер волны по природе: видимое на устройстве → 1, UX-дефект → 2, технический → 3. Если не вписывается — вопрос владельцу, а не догадка.

## Что считается закрытым

Задача закрыта, когда (по [ADR-0104](DECISIONS/ADR-0104-auto-acceptance.md)):
- PR слит в `main`;
- CI на точном HEAD после merge зелёный;
- независимое ревью пройдено;
- Issue закрыт со ссылкой на PR и прогон CI.
