# AGENTS — правила работы над enoTone

Этот файл — первое, что читает любой агент или человек перед изменением репозитория.

## 1. Быстрый вход для любого агента

1. **AGENTS.md** — глобальные ограничения (этот файл).
2. **docs/WORKFLOW.md** — роли, статусы, очередность, право на изменение и слияние.
3. **GitHub Issue** — конкретное задание с целью, зависимостями, контекстом, критериями и границами.
4. **docs/CURRENT_DECISIONS.md** — только относящиеся к задаче действующие решения; при необходимости соответствующий ADR.
5. **docs/MODULE_MAP.md** — навигация к подсистеме; открыть нужные классы и разделы docs/SCENARIOS.md.
6. **docs/AUDIT_PROTOCOL.md** и **docs/TESTING.md** — для ревью, проверок и CI.

Диспетчер читает WORKFLOW + ROADMAP/DESIGN_PLAN + открытые Issues/PR; **не обязан сканировать исходники**. Исполнитель изучает связанный контекст, не всю историю. Для аудита этапа нужен более широкий контекст согласно AUDIT_PROTOCOL. Исторические журналы — в docs/archive; исходное ТЗ уступает более поздним решениям владельца.

## 2. Текущий этап и визуальные решения

**Не фиксировать в AGENTS.md название текущего этапа.** Актуальную последовательность утверждённых этапов определяют docs/ROADMAP.md и docs/DESIGN_PLAN.md; готовность конкретной работы — метки и карточка GitHub Issue (WORKFLOW). После merge нельзя оставлять прежний этап в обязательных инструкциях.

Целевой дизайн — Android v2 (ADR-0084, ADR-0086, ADR-0088): Graphite/Porcelain, Onest/Unbounded, свои компоненты и утверждённые ресурсы из metravolokos/enotone-design. ADR-0073 заменён как визуальное руководство. Ресурсы дизайна не перерисовывать/перегенерировать в app; изменения внешнего вида — по утверждённой Issue и макетам. Не добавлять заглушки, выдающие себя за готовые функции.

## 3. Жёсткие ограничения (нарушать нельзя)

- Без GMS / Play Services / Firebase, без телеметрии, без сетевых вызовов кроме WebDAV пользователя и явно включённого ИИ-API. Только HTTPS. GMS-gate в CI не ослаблять и не «белить» маркеры.
- Учётные данные и пути к личной музыке — никогда в Git, логи, backup, crash, Room, Intent. После успешной WebDAV-проверки вход **всегда** сохраняется в Android Keystore AES-GCM ([ADR-0080](docs/DECISIONS/ADR-0080-permanent-login-sign-out.md), O-09), `security-crypto` запрещён. «Выйти» сначала останавливает воспроизведение и индексаторы, удаляет данные и обложки аккаунта; Keystore очищается **последним**.
- **Обложки:** мастер до 1200 px в постоянном `filesDir/enotone-artwork-v2`, без автоматического LRU и удаления; режимы `ON_DEMAND` / `AUTO_AFTER_IMPORT`; одна выбранная обложка реального альбома на всех экранах; «Неизвестный альбом» не смешивать; никаких массовых image GET во время PROPFIND/индексации тегов ([ADR-0067](docs/DECISIONS/ADR-0067-permanent-album-artwork.md)).
- **Импорт/обновление — одно действие**, инкрементальное. Полную переиндексацию 3590 файлов запускать **только после отдельного подтверждения владельца**, никогда ради UI-проверки.
- Room: только миграции без потери данных, схемы экспортируются и коммитятся. Существующую базу на устройстве владельца не удалять.
- Ручные проверки — на подписанной Stable Preview `app.enotone.android.preview`, установленной поверх предыдущей. Не `.preview.rN`, без удаления приложения и данных.
- Плейлисты: будущая обложка плейлиста — ссылка на существующий мастер альбома, без копирования. **Не писать «плейлисты реализованы»**, пока нет UI.

## 4. Процесс

- Ветка `feature/<этап>-<тема>`, Conventional Commits, небольшие PR. `main` не менять напрямую.
- Merge — только при зелёном CI **точного HEAD** PR (сборка, JUnit, lint, Room schema, GMS scan, APK) и по команде владельца.
- Каждое архитектурное решение — ADR по шаблону: контекст; **минимум два варианта** с плюсами/минусами; решение; обоснование; последствия; как проверить. Заменять принятый ADR только новым ADR и **обновлять индекс `docs/DECISIONS/README.md`** (статус старого и нового).
- Не отмечать проверку на устройстве как пройденную без отдельного сообщения владельца с указанием, что именно проверено. Общий ответ «Работает» не равен PASS для отдельных сценариев.
- Не добавлять новые тесты, проверяющие наличие строк в исходниках (`tools/test_*_contract.py`). Тестировать поведение: JUnit / Robolectric / Compose UI.
- **Пороги сложности** ([AUDIT_PROTOCOL §4](docs/AUDIT_PROTOCOL.md#4-механизм-сокращения)): новый модуль, внешняя runtime-зависимость или пользовательская настройка — только через ADR с решением владельца; базовая линия detekt не растёт; изменение проверки в существующем тесте внутри PR-исправления — только с обоснованием в описании PR.
- Каждый PR перечисляет ID затронутых сценариев из [SCENARIOS](docs/SCENARIOS.md) и обновляет их «Последний результат» только по сообщению владельца.
- Не добавлять заглушки, выдающие себя за готовые функции.
- **Дизайн и этапы:** при завершении работы проверять зависимости в ROADMAP/DESIGN_PLAN и связанной Issue; не начинать следующий этап без разрешения владельца. Архитектор может предложить порядок, но не меняет утверждённую владельцем дорожную карту. Не смешивать несвязанные изменения дизайна, очереди и сетевого слоя в одном PR.
- **Каждый PR обновляет строки [REQUIREMENTS](docs/REQUIREMENTS.md)**, которые он затрагивает: статус и доказательство. Требование нельзя молча пропустить, удалить или считать выполненным без доказательства. Отмена или изменение требования — только решением владельца (ADR или дата сообщения), строка переводится в ⛔.

## 5. Документация — дисциплина

- docs/STATUS.md, docs/KNOWN_ISSUES.md и docs/TESTING.md описывают только текущие подтверждённые факты и инструкции проверки, не вторую очередь задач. STATUS — не длиннее двух страниц.
- Хронология — в `CHANGELOG.md` (одна запись на PR); подробные журналы при необходимости — в `docs/archive/`.
- В конце PR обновить только реально затронутые REQUIREMENTS, SCENARIOS, STATUS, CHANGELOG, KNOWN_ISSUES и ADR-индекс. **Не дублировать в STATUS/ROADMAP оперативный статус всех Issues.** Источник статуса каждой задачи — GitHub Issue.
- Язык документов, отчётов и коммитов — русский; идентификаторы в коде — английские. Комментарии объясняют «почему».
- В Git — только обезличенные числа и коды ошибок, без скриншотов с именами треков.

## 6. Сборка

`./gradlew :app:assembleDebug testDebugUnitTest lintDebug detekt` — подробности в [docs/TESTING.md](docs/TESTING.md). Новый код не должен добавлять замечаний detekt ([ADR-0076](docs/DECISIONS/ADR-0076-quality-tooling.md)), даже пока detekt не блокирует CI.
