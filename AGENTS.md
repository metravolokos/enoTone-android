# AGENTS — правила работы над enoTone

Этот файл — первое, что читает любой агент или человек перед изменением репозитория.

## 1. Что читать перед работой (в этом порядке)

1. [docs/CURRENT_DECISIONS.md](docs/CURRENT_DECISIONS.md) — действующие решения.
2. [docs/STATUS.md](docs/STATUS.md) — текущее состояние и следующий шаг.
3. [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) — **матрица требований** ТЗ и решений владельца со статусами и доказательствами.
4. [docs/DECISIONS/README.md](docs/DECISIONS/README.md) — индекс ADR с **фактическими** статусами.
5. [docs/DESIGN_PLAN.md](docs/DESIGN_PLAN.md) — **перед любой работой с внешним видом**: целевой дизайн Android v2, шаги D1–D6, источники ресурсов.
6. [docs/ROADMAP.md](docs/ROADMAP.md), [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md), [docs/OPEN_QUESTIONS.md](docs/OPEN_QUESTIONS.md), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Исторические журналы лежат в `docs/archive/` и **не** описывают текущее состояние. Исходное ТЗ (`docs/ORIGINAL_PROMPT_AllMusic_Player.md`) уступает более поздним решениям владельца.

## 2. Текущий этап: M6-0 — технический долг

[ADR-0074](docs/DECISIONS/ADR-0074-m6-0-tech-debt-plan.md). Пока этап не завершён:

- **визуальное направление заморожено на [ADR-0073](docs/DECISIONS/ADR-0073-graphite-material3.md)** (Graphite Material 3, без цветных акцентов и кнопок-заглушек). ADR-0068…0072 заменены;
- новых пользовательских функций не добавлять; исключение — дефекты, найденные на Huawei;
- шаги выполнять по порядку из ADR-0074, один шаг — один PR;
- **целевой дизайн — Android v2** ([DESIGN_PLAN](docs/DESIGN_PLAN.md)); экраны переводятся на него шагами D2–D6 после M6-0/5. Ресурсы дизайна (иконка, значки, логотип, Бандит, цвета) — **только копией из `enotone-design/main`**, не перерисовывать и не перегенерировать в этом репозитории.

## 3. Жёсткие ограничения (нарушать нельзя)

- Без GMS / Play Services / Firebase, без телеметрии, без сетевых вызовов кроме WebDAV пользователя и явно включённого ИИ-API. Только HTTPS. GMS-gate в CI не ослаблять и не «белить» маркеры.
- Учётные данные и пути к личной музыке — никогда в Git, логи, backup, crash, Room, Intent. После успешной WebDAV-проверки вход **всегда** сохраняется в Android Keystore AES-GCM ([ADR-0080](docs/DECISIONS/ADR-0080-permanent-login-sign-out.md), O-09), `security-crypto` запрещён. «Выйти» сначала останавливает воспроизведение и индексаторы, удаляет данные и обложки аккаунта; Keystore очищается **последним**. До слияния M6-0/4b в `main` ещё действует исторический ADR-0043.
- **Обложки:** мастер до 1200 px в постоянном `filesDir/enotone-artwork-v2`, без автоматического LRU и удаления; режимы `ON_DEMAND` / `AUTO_AFTER_IMPORT`; одна выбранная обложка реального альбома на всех экранах; «Неизвестный альбом» не смешивать; никаких массовых image GET во время PROPFIND/индексации тегов ([ADR-0067](docs/DECISIONS/ADR-0067-permanent-album-artwork.md)).
- **Импорт/обновление — одно действие**, инкрементальное. Полную переиндексацию 3590 файлов запускать **только после отдельного подтверждения владельца**, никогда ради UI-проверки.
- Room: только миграции без потери данных, схемы экспортируются и коммитятся. Существующую базу на устройстве владельца не удалять.
- Ручные проверки — на подписанной Stable Preview `app.enotone.android.preview`, установленной поверх предыдущей. Не `.preview.rN`, без удаления приложения и данных.
- Плейлисты: будущая обложка плейлиста — ссылка на существующий мастер альбома, без копирования. **Не писать «плейлисты реализованы»**, пока нет UI.

## 4. Процесс

- Ветка `feature/<этап>-<тема>`, Conventional Commits, небольшие PR. `main` не менять напрямую.
- Merge — только при зелёном CI **точного HEAD** PR (сборка, JUnit, lint, Room schema, GMS scan, APK) и по команде владельца.
- Каждое архитектурное решение — ADR по шаблону: контекст; **минимум два варианта** с плюсами/минусами; решение; обоснование; последствия; как проверить. Заменять принятый ADR только новым ADR и **обновлять индекс `docs/DECISIONS/README.md`** (статус старого и нового).
- Не отмечать проверку на устройстве как пройденную без отдельного сообщения владельца с указанием, что именно проверено. Общий ответ «Работает» не равен PASS для отдельных сценариев.
- Не добавлять новые тесты, проверяющие наличие строк в исходниках (`tools/test_*_contract.py`). Тестировать поведение: JUnit / Robolectric / Compose UI.
- Не добавлять заглушки, выдающие себя за готовые функции.
- **Дизайн и этапы M6-0:** при завершении шага M6-0 проверь в [DESIGN_PLAN](docs/DESIGN_PLAN.md), не открылся ли шаг D; если открылся — отметь в STATUS и ROADMAP и сообщи владельцу в отчёте. Начинать шаг D — только по заданию владельца или архитектора. В PR M6-0/4b…7 не трогать ресурсы `ic_eno_*`, `bandit_*`, `enotone_wordmark`, `eno_*`, `font/*`, иконку приложения и `raw/keep_design_v2.xml`, вёрстку не менять: ADR-0073 действует до D2. Если для шага понадобилось что-то из дизайна раньше — спросить, а не делать.
- **Каждый PR обновляет строки [REQUIREMENTS](docs/REQUIREMENTS.md)**, которые он затрагивает: статус и доказательство. Требование нельзя молча пропустить, удалить или считать выполненным без доказательства. Отмена или изменение требования — только решением владельца (ADR или дата сообщения), строка переводится в ⛔.

## 5. Документация — дисциплина

- `docs/STATUS.md`, `docs/KNOWN_ISSUES.md`, `docs/TESTING.md` описывают **только текущее** состояние: устаревшее заменять, а не дописывать вниз. STATUS — не длиннее двух страниц.
- Хронология — в `CHANGELOG.md` (одна запись на PR); подробные журналы при необходимости — в `docs/archive/`.
- В конце работы над PR обновить: STATUS, CHANGELOG, KNOWN_ISSUES (убрать исправленное), индекс ADR, при необходимости CURRENT_DECISIONS, ROADMAP, OPEN_QUESTIONS.
- Язык документов, отчётов и коммитов — русский; идентификаторы в коде — английские. Комментарии объясняют «почему».
- В Git — только обезличенные числа и коды ошибок, без скриншотов с именами треков.

## 6. Сборка

`./gradlew :app:assembleDebug testDebugUnitTest lintDebug detekt` — подробности в [docs/TESTING.md](docs/TESTING.md). Новый код не должен добавлять замечаний detekt ([ADR-0076](docs/DECISIONS/ADR-0076-quality-tooling.md)), даже пока detekt не блокирует CI.
