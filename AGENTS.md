# AGENTS — правила работы над enoTone

Перед началом: прочитать `docs/STATUS.md`, `docs/ROADMAP.md`, `docs/OPEN_QUESTIONS.md`, `docs/ARCHITECTURE.md` и последние ADR. Истина о готовности — STATUS и зелёный CI, а не текст PR.

- Разработка через `feature/<milestone>-<topic>`, Conventional Commits, небольшие PR; `main` не менять без review.
- Каждый архитектурный выбор: ADR с альтернативами, причинами, последствиями и способом проверки. Замена ранее принятого ADR только новым ADR.
- В конце сессии обновлять STATUS, CHANGELOG, KNOWN_ISSUES и, при необходимости, ADR/OPEN_QUESTIONS. Не добавлять невыполнимые заглушки.
- Документы, отчёты, архитектурные пояснения — по-русски; кодовые идентификаторы — по-английски. Комментарии объясняют причины.
- Ни GMS/Play Services/Firebase, ни телеметрии, ни сетевых вызовов вне WebDAV пользователя и явно включённого ИИ API. Только HTTPS.
- Никогда не писать credentials/путь к личной музыке в Git, логи, backup или crash. Android Keystore AES-GCM для будущего хранения, deprecated security-crypto запрещён. M0 использует только оперативную память.
- Исторический стоп-гейт M1 уже выполнен: M0 подтверждён на Huawei, M1 разрешён и реализован только ограниченными пилотами. **Нельзя автоматически запускать индексацию всех 3590 файлов**; каждый следующий охват — отдельный проверяемый этап по ROADMAP.
- Перед merge проверить точный HEAD PR и все обязательные CI, включая GMS scan и APK. Нет успеха проверки — нет merge.

Ручная проверка определяется **текущим PR**, а не старым M0-сценарием.
